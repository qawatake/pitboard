# 報告の書き方

部品は名前で呼び、属性は名前つきで渡し、知らないものは `check` がエラーにする。

## 形

行頭が `<大文字で始まる名前` の行が部品の開始、`</名前>` が終わり。それ以外の行は文 (インラインの Markdown: `code`、**強調**、[題](url))。
部品名の大文字小文字違い (`<item` `</section>` など) は `check` のエラー (部品として読みはする)。属性の書き損じ (`lang=diff` など) もエラー。
タグは必ず行頭 (字下げは可) に置く。文の途中の `<` は部品ではない。

    <Notice id="restart" at="2026-11-23 21:46">pitboard を開き直してください
      新しい版を入れました。q で閉じて、もう一度 pitboard を動かします。
    </Notice>

    <Title>pitboard を作る</Title>

    inbox を広げた pitboard を作る。いまは報告の書き方を決めている。

    <Section title="あなたへ">
      <Ask id="unit">ページの単位
        <Option key="a">セッションごと</Option>
        <Option key="b">プロジェクトごと</Option>
      </Ask>
      <Item id="hook">hook を入れるか決める
        入れると、書いたことが AI の作業中にも届く。`~/.claude/settings.json` を触る。
      </Item>
    </Section>

    <Section title="進行中">
      <Item id="impl" state="doing">最小版を実装する</Item>
      <Item id="parts" status="あなた待ち" wait="you" note="上の問いの答え">部品の一覧を決める</Item>
    </Section>

    <Section title="見せたいもの">
      <Link id="spec" path="docs/spec/SPEC.md">最小版の仕様</Link>
      <Link id="pr" url="https://example.com/pull/1">プルリクエスト</Link>
      <Code lang="diff">
      -old
      +new
      </Code>
    </Section>

    <Fold title="済んだこと (2)">
      <Item id="tui" state="done">viewer を 1 列にする</Item>
      - id の要らない、ただの行
    </Fold>

## 部品 (これ以外は `check` がエラーにする)

| 部品 | 属性 | 中身 | 人ができる反応 |
|---|---|---|---|
| `Notice` | `id` (必須)、`at` (任意。付けた時刻、端末のローカル時刻で `YYYY-MM-DD HH:MM`。書式が違えばエラー。`-h` の作法では必ず付ける) | `Item` と同じ形: 1 行目が題、2 行目以降が中身 (文と `Code`、任意)。最上位にだけ置ける。3 つまで | `y` / `n` / コメント / `x` |
| `Title` | - | 題 (1 行) | - |
| `Section` | `title` (必須) | 部品と文 | - |
| `Item` | `id` (必須)、`state` = `todo` (既定) / `doing` / `done`、`status` (右端に出す短い語)、`note` (status の理由。開いたとき見せる)、`ask` (値は `y` だけ。よし / だめ を聞いている。`state="done"` には付けられない)、`wait` (値は `you` だけ。人が何かしないと進まない印。`status` が黄になる。`state="done"` には付けられない)、`look` (値は `y` だけ。人に読んでほしい行。緑の `●`)、`re` (人のコメントの番号。`changes` が `thought N` と出す N。数字だけ。その `Item` がそのコメントへの返事であることを示し、題の上にコメントを引用して出す) | 1 行目が題、2 行目以降が開いたときの中身 (文と `Code`) | `y` / `n` / コメント |
| `Ask` | `id` (必須)、`look` (付けてよいが意味は無い。反応待ちの黄が出る) | 1 行目が問い、続けて `Option` を 2 つ以上 | 選択肢のキー / コメント |
| `Option` | `key` (必須。英小文字 1 字、`Ask` の中で一意。viewer のキー `c` `g` `j` `k` `m` `n` `q` `r` `s` `u` `x` `y` は不可。一覧の正はコードの `viewerKeys`。`e` は使ってよい) | 選択肢の文 (1 行) | - |
| `Link` | `id` (必須)、`path` か `url` のどちらか 1 つ (両方・どちらも無しはエラー。`url` は `http://` `https://` のみ)、`ask` `look` (`Item` と同じ) | 題 (1 行) | `y` / `n` / コメント (開かない。enter は何もしない) |
| `Fold` | `title` (必須)、`id` (任意。開閉とカーソルを id で追う。無ければページ内で何番目の Fold かで追い、題の変化では閉じない)、`look` (`Item` と同じ。中身すべてで読んだかを見る) | 部品と文。閉じた状態で始まる | enter で開閉 / コメント / `x` |
| `Code` | `lang` (任意。`diff` なら色を付ける) | 終わりのタグまで生のまま。字下げは開始タグの位置を基準に取り除く | - |
| (文) | - | 段落と `- ` の箇条書き | `- ` の行は `x` で隠せる |

- 属性は `名前="値"`。値の中の `"` は `&quot;`。知らない属性はエラー
- `id` は `[a-z0-9-]{1,16}`、ページ内で一意
- 入れ子: `Section` と `Fold` は `Item` `Ask` `Link` `Code` `Fold` と文を持てる。`Section` の中に `Section` は不可。`Item` と `Notice` の中は文と `Code` だけ
- `Link` は viewer の中でも外のアプリでも開かない。`→ 題` の下に、字下げしてパスか URL を薄く出す (常に見せ、折り返して `…` で切らない)。`path` は書かれたとおり、`url` は下線つきの OSC 8 ハイパーリンク

## 描き方

行頭の印、右端の状態、余白、罫線なし、選択行は `>` だけ。
`Item` の行頭は「その行で何ができるか」だけを示す: 中身か `note` があって開ける行は `▸` / `▾`、開けない行は `·` (薄く)、`state="done"` は `✓` で薄く (開けるときも `✓` のまま)。
進み具合は右端の語で示す: `state="doing"` で `status` が無ければ、道具が `作業中` (緑) と出す。`status` があればそれを出す (doing なら緑)。`todo` と `done` は `status` があれば出し、無ければ何も出さない。
`re="N"` のある `Item` は、題の行の**上**に、そのコメントの文を引用として出す: 題の 1 文字目の列に薄い `>`、続けて文も薄く (改行は空白にまとめる)。長ければ折り返し、3 行を超えたら 3 行目を `…` で終える。画像の印 (`[Image #1]`) はそのまま文として出す。引用の行は `Item` の一部で、カーソルは止まらない (カーソルの `>` は左端の列なので見分けがつく)。カーソルの行を画面に入れるときは、その引用も入れる。その番号のコメントが無い (取り消された、番号違い) ときは何も出さない。`re` の違いは隠す鍵と未読の判定に入る (別の質問への返事は別の行。`re` の無い行の鍵は変わらない)。コメントの側 (欄・一覧・行の下のコメント) は変えない。
`Ask` は `?`。閉じた状態で始まり、閉じている間は問いの 1 行だけ (答えてあれば右端に選んだキーと選択肢の文の頭を薄く。入らなければキーだけ)。
`enter` で開くと、選択肢が字下げして並び、選ばれたものに印が付く。選択肢のキーは開いているときだけ効き、閉じているときに押すと開くだけ。
答えたあとも開いたまま。開閉は id で覚え、再読み込みでも保つ。`Link` は `→`。`Fold` は `▸`/`▾`。
最上位の `Fold` (`Section` や `Fold` の中にないもの) の題と行頭の `▸` / `▾` は、`Section` の見出しと同じ太字の青 (節と同じ格の区切りなので)。`Section` や `Fold` の中の `Fold` は地の色。隠した行として `H` で出すときは薄く。
開いている `Item` `Ask` `Fold` の題は太字 (閉じているときはふつう)。開いた `Fold` の中の物 (`Item` `Ask` `Link` `Fold`、文、箇条) は、`Fold` の題の 1 文字目からさらに 2 桁字下げする (中の行の印が、題の 1 文字目より 2 桁右。中の文は中の `Item` の題と同じ列)。`Fold` の中の `Fold` はさらに同じだけ。カーソルの `>` と `●` の列は左端のまま。`Fold` に付いたコメントは、中の行の印の列に `✎`。開いた `Item` の中身はふつうの色・ふつうの太さで、題の文より 2 桁 (印より 4 桁) 深く字下げし、中身の最後のあとに 1 行空ける。
開いた `Ask` も選択肢の最後のあとに 1 行空ける。閉じている項目の間は空けない。

カーソルが止まるのは `Item` `Ask` `Link` `Fold` と、`Section` `Fold` と最上位にある `- ` のただの行 (`Item` の中身の行には止まらない)。
`Item` `Ask` `Link` `Fold` と箇条の行の題は切らない。入りきらなければ折り返し、2 行目以降は題の 1 文字目の位置に揃える (記号の下には書かない)。
右端の語 (`status`、入力の状態) は 1 行目の右端に常に全部出す。題は「右端の語の幅 + 2 桁」を除いた幅で折り返す (2 行目以降も同じ幅。右の語が縦に 1 本の列として読めるように)。
右端の語が幅の半分を超える (か、題の幅が 8 桁を切る) ときだけ、右端の語を題の下の行に右寄せで出す (それでも入らなければ折り返す)。
カーソルの `>` と `●` は 1 行目だけ。済んだ行 (薄い) も同じ。開けるのは中身か `note` がある行だけ (`Ask` は選択肢を開く。題が長いだけでは開けない)。

`Notice` は画面のいちばん上 (題の行より上) に固定して出す。スクロールしても動かない。題は黄。題は切らない (全部折り返す)。行頭の印は、中身があって (コメントが付いていても) 開けるなら黄の `▸` (開いていれば `▾`)、開けなければ黄の `!`。印は `Item` の印と同じ列。題の後ろには何も付けない。`enter` で開閉する。`at` があれば題の行の右端に薄く出す (今日なら `21:46`、今日でなければ `11/23 21:46`)。題はその幅を空けて折り返す (右端の語と同じ扱い)。人の入力の状態 (`未送信` など) は時刻の左に並べる。`at` は隠す鍵にも印の判定にも入れない (`at` だけ変わっても、隠したお知らせはまた出ない)。中身は閉じた状態で始まり、開くと題の下に `Item` の中身と同じ形で出す。
固定の `Notice` が使えるのは画面の高さの 1/3 まで (最低 1 行)。入りきらなければ、入る分を順に出し、最後の行を `ほか N 件のお知らせ` にまとめる。カーソルのある `Notice` (書いている対象の `Notice`) は必ず出す側に入れる。この上限は題 (と、収まるときの開いた中身) の話で、開いた中身まで入れると上限を超える `Notice` は固定をやめ、報告の先頭の行としてスクロールする側に出す (読めることを優先)。
作法 (`-h`): 題は 1 文で、人がすることを言う。手順やコマンドは中身に書く。
`tab` の一覧と `?` の一覧では出さない。

## 文の書き方

部品は増やさず、文 (段落・`Item` の中身・`Section` や `Fold` の中の文) の書き方を次の範囲まで広げる。

| 書き方 | 見せ方 |
|---|---|
| 空行で区切った行のまとまり | 段落。続く行は 1 段落にまとめる。段落の間 (書いた空行) は 1 行空ける |
| `- 文` | 箇条書き。印は `·` (薄く)。折り返しは文の位置に揃える |
| 字下げした `- 文` (2 つの空白で 1 段) | 入れ子の箇条書き。3 段まで。段ごとに 2 桁字下げ。印は 1 段目 `·`、2 段目 `-`、3 段目 `·` |
| `1. 文` | 番号つき。番号はそのまま出す (印の欄より広ければ、文と折り返しをその分右へ)。入れ子も可。番号の下の入れ子は、2 桁ずつのほか、文の位置に揃えた字下げ (番号の幅 + 1。`1. ` なら 3) でもよい |
| 箇条書きの下の、字下げした続きの行 | その箇条の続き (同じ箇条の文にまとめる)。箇条の印より深く字下げした、`- ` でも番号でもない行。箇条が `**…**` だけ (後ろに `:` や文が無い) なら、続きは改行して次の行に描く |
| `**語**: 文` で始まる段落・箇条 | `語` を太字に (`:` は残す)。段落では、この行から新しい段落にする |
| 行全体が `**…**` だけの行 | 小見出し。太字 + 節の見出しと同じ色。上に 1 行空ける (中身の先頭なら空けない) |
| 行末の空白 2 つ、または行末の `\` | そこで改行する (段落・箇条にまとめない。`\` は出さない) |
| `**強調**`、`` `code` ``、`[題](url)` | 今までどおり |

- 字下げの基準: `Item` の中身では中身の最初の行。`Section` / `Fold` (と最上位) の直下の文では、その中の最初の文の行。基準より浅い行は基準と同じに扱う
- `- ` のただの行 (節の直下の 1 段目) は、今までどおりカーソルが止まり `x` で隠せる。**入れ子の箇条 (2 段目以降)・番号つきの行・`Item` の中身の中の箇条は止まらない** (読むだけ)
- 節の直下の箇条に入れ子があるとき、隠す単位は 1 段目の箇条とその入れ子ぜんぶ。鍵は `-|` + その箇条の文 + 入れ子の文 (改行と段の字下げでつなぐ)。入れ子の無い箇条の鍵は今までと同じ
- 段を飛ばした字下げ (1 段目の次にいきなり 3 段目) は、1 段深いだけとして扱う
- 空行は、続いていた段落と箇条を終える
- `Code` の中は今までどおり生のまま

## 解析が壊れないこと

解析はどんな入力でも panic しない。万一 viewer の再読み込みや描画で失敗しても落ちず、「報告を読めませんでした」と前の画面を残す。

## check が見ること

知らない部品・属性、必須の属性の欠け、`id` の重複と書式、閉じていない部品、入れ子の違反、`Notice` が 4 つ以上、`Option` が 2 つ未満、`state` の値、`ask` の値 (`y` だけ) と `done` への `ask`、`wait` の値 (`you` だけ) と `done` への `wait`、`look` の値 (`y` だけ)、`re` の値 (数字だけ)、箇条の字下げが 2 の倍数でない (番号の下の、文の位置に揃えた字下げは除く)、4 段以上の入れ子。
行番号つきで出し、終了コード 1。viewer は、エラーのある報告でも落ちずに、読めた所までと、エラーの行を画面の上に出す。見出しは「報告に書き方の誤りがあります」。行や部品が描けずに抜けたとき (閉じていない部品、壊れたタグ、知らない部品など) だけ「(読めた所までを出しています)」を足す。

## 置き場所

pitboard の置き場は **セッションごと**。`.pitboard/<session>/report.md` と `.pitboard/<session>/events.jsonl`。

- 置き場はカレントディレクトリから親へさかのぼって探す (`.pitboard/<session>/` が最初に見つかった所)。`changes` `settle` `check` `path` `view` と hook (`cwd` から) で同じ。ホームディレクトリより上へはさかのぼらない
- `path` で新しく作るときは、さかのぼって `.pitboard/` があればそこに、無ければカレントディレクトリに作る

- セッションは `pitboard -s SESSION <command>` か `$PITBOARD_SESSION`。`[A-Za-z0-9_-]+`。既存のセッションは一意な先頭数文字でよい
- viewer は `-s` を省くと、さかのぼっていちばん近い `.pitboard/` の中で、いちばん最近更新されたセッションを開く
- `pitboard path` が、そのセッションの report.md のパスを出す (AI がそこを編集する)
- `-s` はコマンドの直前か直後に書く (`pitboard -s abc path` / `pitboard path -s abc`)。それより後ろ (settle の TEXT など) の `-s` は文として残る
- viewer に存在しないセッションを渡すと「セッション abx の報告はまだありません」と出す。viewer はセッションのディレクトリを作らない (作るのは `pitboard path`)
