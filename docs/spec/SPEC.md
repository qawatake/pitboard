# pitboard 仕様

AI のセッションの横のペインに置く報告の画面。

名前の見立て: レース中のドライバーには話しかけられないので、周回ごとにボードの前を通るときに読ませる。
人が書いたことは、人が送ったときに AI に届く。

## 考え方

書き手を分ける。同じファイルを人と AI の両方が書き換えることはしない。

| | 書く人 | 置き場所 | 形式 |
|---|---|---|---|
| 報告 | AI だけ | `.pitboard/<session>/report.md` | [SPEC-format.md](SPEC-format.md)。AI は普通のファイル編集 (Edit/Write) で書く |
| 人の操作 | 人だけ (viewer 経由) | `.pitboard/<session>/events.jsonl` | 追記だけの記録 |

- 置き場所の探し方とセッションの選び方は SPEC-format.md の「置き場所」
- 構成 (どんな節を作り、何を並べるか) は AI が自由に決める。部品の種類と描き方は道具が固定する
- ただし出発点として、勧める構成を `-h` の "A layout to start from" に書く (押しつけではない): 題だけ (このボードが何についてか。めったに変わらない。下に要約の段落は置かない: あなたへ・進行中と重なり、古くなる。そちらは作業が通るので新しいまま。題の下の段落は書式としてはこれまでどおり書ける) → お知らせ (あるときだけ) → あなたへ (上に人が答える・動くもの (`Ask` / `wait="you"`)、下に人の質問への返事 (`look="y"`。題は `> ` + 人の質問 (長ければ文の途中で止めずに縮めるか要約)、中身の 1 行目に結論を 1 文、そのあとに詳しい答え。1 つで複数のコメントに答えてよい)) → 進行中 (いま動いているものと次) → 決まったこと (`Fold`。1 行に 1 つ: 理由つきの決めごとと、人の働き方の決まり (書き方・先に聞くこと・してはいけないこと)。人のためだけでなく AI の記憶でもある: 長い作業では AI の文脈が要約され、セッションが再開されることもあり、チャットだけにあるものは薄れるが報告は残り、人が見て直せる。再開や要約のあとは、動く前にここを読む。節の名前は自由で、こういう場所があることが大事)。上に行くほど人の手が要るものを置き、空の節は書かない。済んだ行は進行中から消す (履歴は git にある)。リンクは要る行の中身か、その行のすぐ下の `Link` に置き、リンクだけの節は作らない。問いに答えが来たら問いを消し、決まった内容を決まったことに 1 行で残す
- 人の操作は報告を書き換えない。「id への操作」として記録し、AI がそれを読んで報告を書き換える

## 報告の画面のカーソル

報告の書き方 (部品・属性・文) は [SPEC-format.md](SPEC-format.md)。ここには、カーソルと操作の決まりを書く。

- カーソルは画面に見えている行のすべてに止まる (SPEC-format.md の「描き方」)。部品の行 (`Item` `Ask` `Link` `Notice` `Fold` と最上位の `- ` のただの行) ではそれぞれのキーが効く。文の行 (題・見出し・段落・コード・番号つきや入れ子の箇条・開いた `Item` の中身の行) で効くのは `c` だけ。`x` は「この行は隠せません (c でコメントは書けます)」と断る (`page.MsgNoHide`)。`- ` のただの行で効くのは `x` と `c`
- 起動直後 (と、止まる行が無い状態から止まる行が現れたとき) のカーソルは最初の部品の行に置く (部品の行が無ければ最初の文の行)。`g` の字で節へ飛ぶときも、その節の最初の部品の行へ
- 再読み込みのあと、カーソルは id で追う。id が消えたら近くの止まる行に移り、下の行に「報告が書き換わりました」と出す
- id が同じでも、カーソルの行の題か部品の種類が変わったら同じく「報告が書き換わりました」を出し、j/k まで操作を受け付けない (`status` `note` `state` だけの変化では出さない。`Fold` の題の変化でも出さない)
- 人が一度も動かしていないカーソル (起動直後と、止まる行が無い状態から止まる行が現れたとき) では選択肢のキーが効かない (AI への答えなので)。`x` `r` `c` `m` `enter` は効く (画面ですぐ結果が見え、`s` まで送られず、`u` で戻せる)。このとき `Ask` を開いていれば下の行に `j k 動かすと答えられる` と出し、選択肢のキーを押したら「j k で動かすと答えられます」と知らせる。この案内は、ほかのキーをすべて落としてもまだ入らない幅になるまで縮めない (縮めると `j k 動かす`、それも入らなければ移動のキー `j k` だけ。40 列では `j k 動かす` が残る)。この間、`x 隠す` は `g` `space` `enter` より後まで残す
- 画面より高い行を `j` `k` が読み進める (カーソルは動かない) とき、それは人が動かしたとみなす (一度も動かしていないカーソルの扱いは消える)
- viewer がカーソルを動かしたとき (`x` で隠したあと、`H` の切り替えで行が消えたあと、節ごと消えたあと、`g` `space` で飛んだあと) は、その行にカーソルが乗った画面を描いてから 0.4 秒たつまで、`x`・選択肢のキーを受け付けない (捨てる。ためておいて後で効かせない)。捨てたときは「いま移った行です。もう一度押すと付きます」(`x` では「…もう一度押すと隠れます」/「…表示に戻ります」) と知らせ、同じ行で同じキーをもう一度押せば 0.4 秒の間でも効く (2 度押しは守り、3 度目は知らせを見たうえでの操作とみなす)。0.4 秒たてば j/k を押さなくても効く (続けて隠せるように)。この間の案内には `x`・選択肢を出さない。`r` はこの間も効く (行は消えず `u` で戻せる。どの行を読んだことにしたかを知らせる)
- 隠した行を出していないときに、もう隠れた行へ遅れて届いた `x` は、何も記録せず「この行はもう隠れています」と断る (端末・web とも。`page.ErrAlreadyHidden`)
- 案内に出したキー (と行に効くキー `x r c`・選択肢) が効かないときは、黙って捨てず、なぜかを下の行に出す: 「報告が書き換わりました」の間はその知らせ (どのキーでも)、カーソルの行が画面の外なら「カーソルの行に戻りました」。案内の行には、いま押して効かないキーを出さない
- 選択肢のキー・`x` は、押した時点の報告を読み直し、画面に出している内容と同じときだけ記録する。違えば「報告が書き換わりました。もう一度押してください」
- 再読み込みでカーソルの行が画面の外へ出たら (AI が上に行を足したなど)、画面のほうがカーソルの行についていく。端末の大きさが変わったとき、コメントの画面から戻ったときも同じ (カーソルの行が見えていた場合)

## 人の操作 (events.jsonl に 1 行ずつ)

    {"n":1,"t":"...","op":"react","id":"unit","value":"a","option":"セッションごと"}   問いへの答え (選択肢の文字と文)
    {"n":2,"t":"...","op":"thought","id":"hook","text":"..."}     コメント。id はカーソルが止まる行の上で書いたときだけ付く
    {"n":3,"t":"...","op":"settle","thought":2,"text":"todo にした","by":"ai"}   AI が書く、コメントへの対応
    {"n":4,"t":"...","op":"hide","key":"...","title":"画面に出ていた文"}       人が行を隠す (unhide で戻す。同じ key)
    {"n":5,"t":"...","op":"retract","thought":2}                    人がコメントを取り消す
    {"n":6,"t":"...","op":"undo","undo":5}                          人が u で記録 5 を取り消す (対象は下の「u で取り消す」)

`n` は通し番号。追記は flock の下で行う。

### 答え

- 人が AI に答える道は 1 つ: 問い (`Ask`) の上で選択肢の文字。項目・リンク・お知らせ・`Fold` には答えない (コメント・隠す・読んだはできる)。はい / いいえ が欲しいときも、AI は選択肢それぞれの意味を書いた `Ask` にする
- 押した答えは、その行の右端に `a` として出す。**報告は書き換えない**
- 答えとコメントの記録には、押した (書き始めた) 時点の行の題を `title` として入れる。答えには選択肢の文を `option` に必ず入れる
- 同じ問いに押し直したら、新しいほうが有効 (記録は両方残す)
- AI が報告のその行を書き換えたら (行の文面か状態が変わったら)、答えの表示は消す
- 前の版の記録: 項目・リンク・お知らせ・`Fold` への `y` / `n` (`op` が `react` で値が `y` か `n`、`option` が無いもの) は `events.jsonl` に残ったままにし、書き換えない (移し替えはしない)。表示・数・`changes` からは読み飛ばす (その取り消しも)。もう届けたものは届いたまま

### コメント

- `m` でエディタが出る (置き場所は下の「エディタの置き場所」)。どこにカーソルがあっても効く。
  enter 置く (pitboard に置く。s で送るまで AI には届かない)、shift+enter 改行 (ctrl+j / alt+enter も)、ctrl+g で `$VISUAL` / `$EDITOR` / `vim`、esc やめる。送るのは書き終えてから `s` (エディタの中の `ctrl+s` は何もしない)。
  案内は 1 行 (`enter 置く  esc やめる  shift+enter 改行  ctrl+g エディタ`)。狭いときは後ろから落とす: `ctrl+g エディタ`、次に改行の語 (キーだけ残す。40 列では `enter 置く  esc やめる  ctrl+j`)、最後に改行のキー (`enter` `esc` は最後まで残す)。
  端末が shift+enter を enter と区別できないとき (下の「キーの区別」) は、案内を `ctrl+j 改行` にする
- キーの区別: 多くの端末は shift+enter と enter を同じバイトで送る。viewer は起動時 (と外のエディタから戻ったとき) に `CSI > 1 u` (kitty keyboard protocol の disambiguate) と `CSI > 4 ; 1 m` (xterm の modifyOtherKeys 1) を有効にし、`CSI ? u` で問い合わせる。
  終わるとき (q、シグナル、外のエディタを起動する前) は `CSI < u` と `CSI > 4 ; 0 m` で戻す。`CSI ? flags u` の返事が来たら「区別できる」とし、案内を `shift+enter 改行` にする。返事が無ければ `ctrl+j 改行` のまま。
  有効にすると esc・ctrl+文字・alt+文字などが `CSI 27 u`、`CSI 106 ; 5 u`、`CSI 27 ; 5 ; 106 ~` の形で届くことがある。どれも有効にする前と同じキーとして読む
- コメントを直す: コメントの画面で、コメントの上の `e`: そのコメントの文を入れた状態でエディタが開く (題は「コメント N を直す」)。`enter` で置き換える。`esc` でやめる (元のまま)。直した文が空か元と同じなら何もしない (取り消すのは `x`)。
  記録は追記だけ: `{"n":N,"t":"...","op":"edit","thought":9,"text":"直した文"}`。画面に出る文は、いちばん新しい `edit` のもの。
  AI への届き方: まだ届いていない (未送信、または送信済の) コメントを直したら、直した文が `thought 9: …` として届く (直したこと自体は届けない)。
  すでに届いたコメントを直したら、次の `send` で `edit thought 9: <直した文>` (何度直しても 1 件。未送信に数える)。AI の対応 (`settle`) が付いていたら外し、状態は直したことの状態 (未送信 → 送信済 → 既読) になる。
  取り消したコメントの `edit` は届けない。`e` はコメントの画面でだけ効く (`Option` の `key` に使えるキーは SPEC-format.md)
- エディタは文中にカーソルを持つ (readline / emacs 風)。文字の入力と貼り付けはカーソルの位置に入る:
  `←` `→` / `ctrl+b` `ctrl+f` 1 字、`↑` `↓` / `ctrl+p` `ctrl+n` 折り返した見た目の行で上下 (桁は全角を 2 として近い所へ。続けて押す間は最初の桁をめざす)、
  `ctrl+a` `ctrl+e` / `home` `end` 行頭・行末 (改行で区切った行)、`alt+b` `alt+f` / `alt+←` `alt+→` 語単位 (空白と、かな・カナ・漢字・英数・記号の種類の変わり目で区切る)、
  `backspace` / `ctrl+h` 左の 1 字、`delete` / `ctrl+d` 右の 1 字、`ctrl+w` / `alt+backspace` 左の 1 語、`ctrl+k` 行末まで (行末では改行を消して次の行とつなぐ)、`ctrl+u` 行頭まで。
  1 字は見た目の 1 字 (結合文字・異体字セレクタ・ZWJ でつないだ絵文字は 1 字)。`pgup` `pgdn` (`alt+↑` `alt+↓` も) は報告を半画面送り、1 行目の `↑`・最後の行の `↓` は 1 行送る (`ctrl+d` `ctrl+u` `ctrl+e` `ctrl+y` は文を直すキーのまま)。入力欄は報告の中の自分の場所にとどまり、報告と一緒に動く (画面の外に出れば端末のカーソルも隠す)。字を打つ (文を変えるキーを押す) と、まず入力欄が画面に戻る (`j` も文字として入る)。入力欄が画面の外に出ている間も、いちばん下の行は「書いている途中 — 何か打つと戻る  esc やめる」(`page.MsgWritingAway`。黄) を出し続け、ふだんの画面と見分けがつく。`esc` で閉じても書いたものは捨てない: 宛先 (行・宛先なし・直しているコメント) ごとに viewer が動いている間覚え、同じ宛先でまた開くと戻る (ブラウザの下書きと同じ約束)。置いたら忘れる。空にして閉じても忘れる。エディタの案内は文の幅ではなく画面の幅に並べ、改行のキーは、使っている鍵盤の方式のもの (kitty の方式なら `shift+enter`、ほかは `ctrl+j`) を 40 列でも残す (狭ければ `改行` の語、次に `S-enter` と縮め、それでも入らないときだけ落とす)。報告が画面より高ければ、案内に `pgup pgdn スクロール` (落ちる順は ctrl+g と同じ)
- エディタの文は字単位で折り返す。高さ (画面の 3 分の 1) に収まらないときは、カーソルの行が見えるように送る
- エディタが開いている間は、端末の本物のカーソルを入力位置 (文中のカーソルの位置。全角は 2 桁) に置いて見せる。IME の変換中の文字がそこに出るように。
  色の反転で描いた四角は使わない。閉じたら隠す。描き直しは 1 回の書き込みにまとめ、カーソルが飛んで見えないようにする
- カーソルが止まる行の上で `c` を押すと、その行に紐づいたコメントになる。文の行と `- ` のただの行では、記録の宛先は、その行を囲むいちばん近い部品の行の宛先と行の文から作る鍵 (`Line|` + 囲む部品の宛先 (無ければ空) + 改行 + 行の文 (`report.Node.Text`。コードは最初の空でない行)。`report.Target`)。文が変われば別の行。`changes` には `thought N on line "文" in ID: …` (囲む部品が id の無い `Fold` なら `in fold "題"`、囲む部品が無ければ `in …` を付けない。行がもう無ければ ` (now gone)`)。そのコメントは行の右端の状態だけに出し (文の行は開かない)、中身はコメントの画面 (`← 文`) で読む。コメントの画面の `enter` はその行へ行く (中身の行なら `Item` を開く)。`Fold` にも書ける: 記録の宛先は `id`、無ければ題から作る鍵 (`Fold|title=題`。隠すときの鍵と同じ考え方で、題が変われば別の `Fold`)。`changes` には `thought N on fold "題": …` (`id` があれば `thought N on ID (題): …`)。行の右端の状態、開いたときに題のすぐ下に出るコメント (中の行と同じ列に `✎`)、コメントの画面、`e` `x` `u` は `Item` と同じ。コメントを置くと、`r` と同じく `Fold` とその中の緑の `●` が消える
- エディタの置き場所: 画面のいちばん下ではなく、書いている対象のすぐ下に、報告の行の間へ差し込んで出す。エディタと案内の行 (`enter 置く  esc やめる  …`) はひとかたまり。エディタの中の知らせ (案内の行の代わりに出るもの) もこのかたまりの中
  - かたまりは、上と下に薄い横線 (`─`、文の幅いっぱい) を引いて区切る。上の線の上と、案内の行の下に空行を 1 行ずつ置く (固定の `Notice` の中でも同じ。下の空行は、すぐ下が固定の領域の終わりの空行ならそれを兼ねる)。画面の高さが足りないときは、空行から先に削る (入力の行と案内を残す)。見出しがあるときは上の線の中に入れる (`── 宛先なしのコメント ───…`)。「この行は書き換わりました」は上の線の右端。案内の行は下の線の下。線を引くのは書く欄だけ
  - 入力の 1 行目の頭 (印の欄) に `❯` (ふつうの色)。2 行目以降も同じ字下げ
  - `Notice` への `c` (と、カーソルが `Notice` にあるときの `m`): 固定の領域の中、その `Notice` のすぐ下に出す。`c` では見出しを出さない
  - `c`: その行 (開いていれば中身の下。`Fold` は開いていても題のすぐ下で、そこに並ぶコメントの下) のすぐ下。見出し「「…」にコメント」は出さない (対象がすぐ上に見えているので)。対象の行が高すぎて、かたまりと一緒に画面に入らないときだけ出す。字下げは対象の行の題に揃える
  - `m`: カーソルの行のすぐ下。見出しは `宛先なしのコメント` (その行へのコメントではないと分かるように)。カーソルの行が無ければ、画面の中ほど
  - `e`: コメントの画面の中で、そのコメントの 2 段のすぐ下。見出しは「コメント N を直す」
  - かたまりが画面の高さの上から 2/3 より下に来るときは、報告をスクロールして 2/3 より上に収める (対象の行は入るかぎり見えたまま)。入力が増えて行数が伸びても下へはみ出さない
  - 画面のいちばん下の行は、書いている間は空ける (案内はかたまりに移るので)
  - エディタを閉じたら、スクロール位置とカーソルは開く前のまま (書いている間の位置合わせは、報告のスクロール位置を動かさない)
- 書いている間に紐づけ先の行の題が変わるか行が消えたら、エディタの題の横に「この行は書き換わりました」と出す。送ることは止めない
- 貼り付け (ブラケットペースト) の改行は CR・LF・CRLF のどれでも 1 つの改行にする。貼り付けの中の改行で送られることはない
- 書いた時点の題といまの題が違えば、行の下とコメントの画面に「(書いたときは: …)」を添える
- 行の下に出すコメントは、改行ごとに 1 行ずつ字下げして描く。画面に出す文字列には制御文字を混ぜない
- コメントには状態がある: **未送信** (まだ送っていない。黄) → **送信済** (送ったが AI がまだ読んでいない。薄く) → **既読** (`changes` か hook か `wait` で届いた。薄く) → AI が `settle` で書いた状態: **対応中** (`--doing`) / **保留** (`--hold`) / **対応済** (`--done`) (いちばん新しい `settle` が有効)。送信済から後はどれも薄く。
  AI が書いた対応の文は、コメントの画面では 1 行目、そのコメントを `enter` で開けば全部読める。
  画面ではコメントと呼ぶが、記録 (`op: "thought"`)、コマンド (`settle`)、AI 向けの英語の出力 (`thought N`) は変えない

### 行を隠す

人がもう見なくていい行を、pitboard の上で自分で消す。報告は書き換えず、「この内容の行は隠す」という記録を events.jsonl に足し、viewer がその行を描かない。

- `x` でカーソルの行を隠す。確認は出さない (戻せるので)。下の行に「隠しました (H で表示、u で戻す)」(H で表示中は「隠しました (u で戻す)」) と出し、カーソルは次の行へ移る (移った行は 0.4 秒たつまでキーが効かない)。web で `x` を素早く 2 度押したときも、2 度目はページが移った行に届いて捨てられる (隠した行を表示に戻さない)
- 隠せるのは `Item` `Ask` `Link` `Fold` と `- ` のただの行。段落・見出し・題は隠せない
- 記録の鍵は**行の内容** (id ではない)。ただの行は文そのもの (同じ文の行は一緒に隠れる)、`Item` `Ask` `Link` は種類 + id + 題 + `state` + `status`、`Fold` は id (無ければ題)。
  AI が題・`state`・`status` を変えたら別の行になり、また現れる。そのときは一度だけ「隠した行が書き換わったので、また出しました: <題>」と知らせる (押したのに消えていない、と見えないように)。中身・`note`・`path`・選択肢の変化や、隠した `Fold` の中身の変化では現れない (`-h` にもそう書く)
- `H` で、隠した行を薄く、印を `⌀` にして表示する / しないを切り替える。表示中に隠した行の上で `x` (案内は `x 表示に戻す`) を押すと表示に戻る (`unhide`。知らせは「表示に戻しました」)
- 隠した行があるときは、案内の行の右に `隠した行 3` (H で表示中は `隠した行 3 (表示中)`)
- 節の中身が全部隠れたら、節の見出しも描かない。`Fold` の題 (件数など) は AI の文なので触らない
- 隠した行に紐づいたコメントは、コメントの画面には今までどおり出す
- 「報告が書き換わりました」の間は効かない」「viewer が動かしたカーソルは 0.4 秒効かない」の決まりは `x` にも当てはまる。「一度も動かしていないカーソルでは効かない」は当てはまらない (`x` は効く)

### 送る

人は pitboard の上でいろいろ返答して (問いへの答え、コメント、隠す)、**最後にまとめて送る**。送るまで AI には届かない。

- 報告の画面 (とコメントの画面) で `s`: まだ送っていない操作があれば、events.jsonl に `{"n":N,"t":"...","op":"send"}` を追記し、それから AI を起こす。
  無ければ `send` を追記せず、下の行に「未送信のものはありません」
- 起こし方の順: (1) **待っているもの (Stop hook か `pitboard wait`) がいれば何もしない** (それが終わって AI が起きる)。知らせは「送りました」。(2) いなければ、端末への打ち込み (`PITBOARD_SEND` → herdr。下)。
  (3) どれも無ければ「送りました。ただ AI が待っていないので、チャットで一言伝えてください。」+「AI に pitboard wait を動かしてもらうか、PITBOARD_SEND を設定してください (pitboard help send)」
- 待っているもの (Stop hook か `wait`) がいる (`.pitboard/<session>/waiting` の pid のプロセスが生きている) ときは、いちばん上の行の右端に薄く `AI 待機中` (`未送信` の左)。いないときは何も出さない。tick (0.5 秒) ごとに見直す
- エディタの中では送らない (`enter` は書くだけ、`ctrl+s` は何もしない)。書き終えてから `s`
- 案内の行 (いちばん下) に、未送信があるときだけ `s 送る` を `m 書く` の手前に出す (報告・コメントの画面で)。幅が狭くても `s 送る` `m 書く` `? キー` は最後まで残す
- `changes` と hook が届けるのは、**いちばん新しい `send` より前の操作だけ**。それより後の操作は次の `send` まで届けない。`changes` は `seen` をその `send` まで進める
- 打ち込む文: `pitboard: N sent. Run: pitboard -s SESS changes` (N はその `send` で送る件数。SESS はセッション id の、その `.pitboard/` の中で一意になる最短の先頭 (最低 8 字。id が短ければ全部)。
  内容は打ち込まない。AI が `changes` で読む)。AI の会話に残るので短くする。意味は `-h` に書く
- 起こし方: `$PITBOARD_SEND` があれば `sh -c` で実行 (`PITBOARD_SESSION` と `PITBOARD_MESSAGE` を渡す)。無ければ、`herdr` が PATH にあるとき (viewer が herdr の外でも)、
  `herdr agent list` の JSON (`result.agents[]`) から `agent_session.value` がセッション id と一致する agent を探し、`herdr agent prompt <pane_id> <文>` (シェルを通さない)
- 画面の知らせの言葉: 記録の失敗はどれも「記録できませんでした: …」、操作の中の失敗は「できませんでした: …」、外のエディタを空で閉じたら「空だったので書きませんでした」(外のエディタの説明の行は「この線より上を pitboard に置きます。空のまま閉じると何もしません。」)
- 起こせなくても `send` の記録は残す (AI が次に `changes` を呼べば届く)。知らせは「送りました。ただ AI を起こせなかったので、チャットで一言伝えてください。」+ 理由。
  この知らせだけは、1 行に入らなければ 2 行使う (1 行目にこの文、2 行目に理由。それぞれ入らなければ `…` で切る)。理由:
  - `herdr` も `PITBOARD_SEND` も無い: 上の (3)
  - `herdr` はあるが、このセッションの agent がいない: 「herdr にこのセッション (<id の頭 8 字>) の AI がいません。AI を herdr の中で動かすか、PITBOARD_SEND を設定してください」
  - 実行に失敗: 「送れませんでした: <理由>」(stderr の先頭 1 行を添える)
- 5 秒で打ち切る。起こしている間は下の行に「送っています…」。成功したら「送りました」(wait が待っていたときと同じ)。結果の表示は次にキーが押されるまで残す
- 起こしている最中に押されたキーは捨てる (何も出ていない画面に対して押されたものなので)
- 状態の語は上の「コメント」の状態と同じ (未送信は `send` より後の操作、送信済は送ったが AI がまだ読んでいないもの)
- 報告の画面とコメントの画面のいちばん上の行の右端に、未送信の数を `未送信 3` (黄。前に `●` は付けない) と出す。0 なら出さない。未送信の数は人から見た入力の数 (`page.PendingCount`): 行ごとに答え・隠す・取り消しで 1 つ (同じ問いで a b a と押しても 1)、コメントごとに 1 つ (書いた・直した・取り消した)。
  いちばん上の行に文があれば (題など) そちらを `…` で切る。スクロールしても画面のいちばん上の行に出る。`s` を押すと未送信は 0 になり、`AI の番` になる (下の「誰の番か」)。書きかけは数えない
- 取り消しとの関係: 未送信のコメントを取り消したら、送っても届かない (未送信にも数えない)。送ったあと (送信済でも) に取り消したら、`retract` が次の `send` で届く

### 誰の番か

- 右上の語のいちばん先に、`AI の番` (薄く。AI 待ち) か `あなたの番` (ふつうの文字の色。黄は `反応待ち N` `未送信 N` に残す) のどちらか 1 つを必ず出す (`page.Board.AITurn`)
- `AI の番` は次のいずれかのとき: (0) report.md が `check` で落ちる、または無い (AI が直す番。ほかの条件によらない。送る前でも、全部 `settle` したあとでも)。どの画面も、いまディスクにあるファイルで決めるので、一覧・開いていた画面・後から開いた画面は同じ語を出す。(1) 人が `s` で送ってから、report.md が書き換わっておらず (report.md の mtime が、いちばん新しい `send` の `t` より後でない。AI がまだ読んでいなくても)、その `send` が届けたコメント (その前の `send` から後に書いた・直した・取り消しを戻したもの) のうち 1 つでも、まだ `settle` されていない。(2) AI が `settle --doing` にしたコメントが、まだ `doing` のまま
- つまり、送ったコメントを AI が全部 `settle` (`--done` か `--hold`) すれば、報告を書き換えなくても `あなたの番` に戻る。コメントを含まない `send` (Ask への回答や隠すだけ) は AI が `settle` できないので、報告の書き換えまで `AI の番`
- それ以外は `あなたの番`。一度も送っていないボードも (報告が `check` を通れば) `あなたの番`
- `send` の `t` はナノ秒まで書く (同じ秒の書き換えと見分けるため)
- 空の report.md は `check` を通る書き換えと数える (送ったあとなら `あなたの番` になりうる)
- 比べるのはファイルの mtime と送った時刻なので、mtime を戻すコピー (`rsync -t` など) や、ずれた時計 (網の上のファイルシステムなど) では、番を取り違えることがある
- 報告が無い・空のときも、web のページと一覧に出す
- 報告の書き換えと `settle` は、ほかの読み直しと同じく tick ごとに見て、すぐに切り替える

## 画面

- 主画面は報告。`l` (と `tab`) で「コメント」の画面に切り替わり、もう一度で報告に戻る (下の「コメントの画面」)
- 下は静かに。目が行くのは「未送信」だけにする (印は報告の行頭と、いちばん上の行の右端に出す)
- 開いた中身 (字下げされた文) はふつうの色。薄くするのは済んだ項目 (とその中身)・隠した行・パスなどの補助情報だけ。
  `note` は `理由: …`、行の下のコメントに AI の文があれば `対応: …` (`対応中: …` `保留: …`) とし、頭の語だけを薄く
- 日本語入力が入ったままでも動かせるように: 報告・コメントの画面の移動に `ctrl+p` `ctrl+n` (`k` `j` と同じ。人が動かしたとみなす)。
  エディタの外では、全角の英数・記号 (U+FF01〜FF5E) と全角空白を半角に直してからキーとして扱う (`ｊ` → `j`)。エディタの中ではそのまま文字。案内と `?` の一覧では `j k` と書く
- 画面だけを動かすキー (カーソルは動かさない。画面の外に出ることもあり、そのときは今までどおり `↑ カーソルは上` と、行に効くキーはまずカーソルの行を戻して 1 度断る): `ctrl+d` `ctrl+u`・`pgdn` `pgup`・`alt+↓` `alt+↑` (`ESC [ 1 ; 3 B` などと `ESC ESC [ B` の形も読む) で半画面、`ctrl+e` `ctrl+y` と `↓` `↑` で 1 行。報告の端で止まり、固定の `Notice` はそのまま。報告・コメントの画面のどちらでも効く。報告が画面より高ければ、案内の終わりに `^d ^u スクロール` (いちばん先に落ちる)。`?` の一覧にすべて
- マウスのホイール・トラックパッド: 端末に代替スクロール (DEC mode 1007、`CSI ? 1007 h`。入るときに `CSI ? 1007 s` で元を覚え、出るときに `CSI ? 1007 r` で戻す) を頼む。代替画面の中で端末がホイールを `↑` `↓` に変えて送り、それが画面を 1 行ずつ送る (1 刻みの行数は端末が決める)。マウスはつかまえないので、修飾キー無しで文字を選んでコピーできる。Ghostty は 1007 を持ち、herdr はペインごとに 1007 を覚えてホイールを `↑` `↓` で渡す (どちらもバイナリで確かめた)。xterm は 1007 を頼めば効く。kitty・WezTerm・iTerm2・Terminal.app は代替画面ではもとから矢印を送る (資料による。実機では見ていない)
- 下の行の知らせが消えるときは 1 つの決まり (`page.MsgClears`): 次のキー (何もしないキーでも)・エディタを開いたとき・コメントの画面や欄を開け閉めしたとき・ポインタでカーソルを動かしたとき。読み直し (ディスクが変わった) だけでは消えない。端末もブラウザもこれを使う
- 下の行に出す知らせ (「送りました」「送れませんでした: …」など) は、幅に入らなければ折り返す (切らない)。高さが足りなければ報告の行を減らす。エディタを開いている間は、エディタのかたまりの中で案内の行の代わりに出す (次のキーで消える)
- 報告の画面のいちばん下の案内は**常に 1 行**。いまの行でできるキーと、最後に `m 書く` `? キー` (コメントがあれば、その間に `l コメント N`。「コメントの画面」)。`tab` `q` `H` は出さず `?` の一覧に任せる。`s 送る` `u 取り消す` `space 次へ` は、使えるときだけ出す (それぞれの節)。ラベルは短く (`c 行に書く` (幅によらず)、`enter 開く` / `enter 閉じる`)
- 右端の `隠した行 N` は薄く。入らない幅なら出さない。それでも入らなければ `x` (と `space`) → `g` → `enter` → `r` と選択肢 → `c` の順に落とす (`m 書く` と `? キー` は最後まで残す。ただし「j k 動かすと…」は落とさず、`? キー` も入らない幅ではそちらを残す)
- `Ask` の案内: 閉じているとき `enter 開く  c 行に書く  x 隠す`、開いているとき `a b … 答える  enter 閉じる  c 行に書く`
- `Fold` の案内: `enter 開く` (`閉じる`)  `c 行に書く`  `x 隠す`
- どの幅でも 1 行は端末の幅を超えない (描く直前に、幅を超える行は切る)。右上の数と未送信の印は、入らなければ右から落とす
- 右上の語 (`AI の番` か `あなたの番`、`反応待ち N` `未読 N` `AI 待機中` `未送信 N`。この順) は、固定の `Notice` の下、報告の上の 1 行に出し、報告の行と重ねない。報告のいちばん上では、報告の頭の空行がその行になる (行は増えない)。スクロールしているときは報告の上に 1 行取る
- 報告が空 (書いてあるものが無い) なら、薄く `報告はまだ空です。AI が書くと、ここに出ます。`
- `?` で全キーの一覧。説明の欄が取れない狭い幅では、キーの行の下に説明を字下げして出す。高さに収まらなければ `j` `k` で送れる。`q` か `esc` か `?` で閉じる (ほかのキーでは閉じない)
- `j` `k` は止まる行を 1 つずつ動き、画面はカーソルの行を追う。その先に止まる行が無ければ半画面送る。カーソルの行が画面の外にあるときは、カーソルの行の方向への `j` `k` はまず画面をカーソルの行まで戻す (カーソルは動かさない)。次の `j` `k` から動く
- 画面より高い 1 つの行を読む (長いコードのまとまり、コメントの多い行など、止まる行どうしの間に止まらない行が画面より多くあるとき): 次の止まる行が画面の外 (下) にあり、いまの行との間にまだ画面に出ていない行があるとき、`j` はカーソルを動かさず画面を半画面進める (最後は、次の止まる行が画面に入る所まで)。間が全部見えたら、次の `j` で次の止まる行へ移る。`k` も逆向きに同じ (前の止まる行が画面の外 (上) で、間に出ていない行があるとき)。`j` でカーソルの行を読み下って頭が画面の上に出たあとは、`k` はその行を半画面ずつ読み上り (頭が画面に入る所まで)、それから前の止まる行へ移る
  - そのあいだカーソルの行は画面の外に出てよい (`>` は見えない)。下の行の右に薄く `↑ カーソルは上` (`↓ カーソルは下`) と出す。この印は案内の行のどのキーより優先する (`s 送る` `m 書く` `? キー` も先に落とす。最も狭い幅では左に寄せて出す)
  - カーソルの行が画面の外にあるとき、行に効くキー (選択肢のキー `x` `r` `c`) はまずカーソルの行を画面に戻し、そのキーは受け付けない
  - `space` や `g` で飛んだら、ふつうの位置に戻る
- `g` で節へ飛ぶ: 「飛ぶ」状態に入り、報告の上から順に、飛び先に `a` `b` `c` … を振る。`g` は振らない (`a`〜`f`、`h`〜`z` の 25 まで)。字は `g` を押したときに決め、抜けるまで変えない。その間に報告が書き換わったら「飛ぶ」状態を抜け、「報告が書き換わりました。カーソルの行を確かめてください」を出す。飛び先は `Notice` (それぞれ)、`Section` (それぞれ)、最上位の `Fold` (`Section` の中の `Fold` は入れない)
  - 画面にある飛び先は、見出しの行頭 (カーソルの列) に黄の字。いちばん下の案内の行は飛び先の一覧に置き換える (`esc やめる  a あなたへ  b 進行中`。`esc やめる` は必ず出し、先頭)。一覧は折り返して min(3, 画面の高さ/3) 行まで (最低 1 行)。入りきらなければ題を揃って縮め (短い題は縮めない。6 桁より短くはしない)、それでも入らなければ後ろの飛び先を一覧から外して `… +N` とする (外した飛び先の字も効く)
  - 字を押すと、その節の最初の止まる行へカーソルを移し、見出しを画面のいちばん上 (固定の `Notice` と右上の数の行の下) に来るようにスクロールする。`Fold` なら `Fold` の行へ (開かない)。`Notice` ならその `Notice` へ。止まる行の無い節はスクロールだけ。viewer が動かしたカーソルとして、0.4 秒は `x`・選択肢を受け付けない
  - `esc`・`g` (いつでも)・振られていない字・ほかのキー: 何もせず抜ける。コメントの画面・エディタ・`?` の中では効かない
  - 案内の行に `g 飛ぶ` (飛び先があるとき)。狭いとき落とす順は `space` の次
- 行へのリンク (`[文](#id)`。書き方は SPEC-format.md): 報告の中の別の行を指す (返事の行から、その作業が並んでいる行へ、など)。`structure` の色 (端末は下線、ブラウザはホバー・フォーカスで下線)。行き方は `g` の中で (新しいキーは足さない。端末に cmd+enter は届かない)。決めるのは `internal/page` (`LinksOf`: 行の題、続けて中身の順、同じ行へのリンクは 1 つ、自分自身へは数えない。`Follow`: その行の key と、開く `Fold`)
  - `g` のあいだ、カーソルの行のリンクに出てくる順に `1`〜`9` を振る。カーソルの行のものだけ (ほかの行のリンクには振らない)。数字はリンクの文の直前に `structure` の太字で出し、案内の一覧には字の飛び先のあとに `1 <指す行の題>` と並べる (字の飛び先を縮め・落としても、数字と戻るは落とさない)
  - 数字を押すと、指す行を囲む `Fold` を開き、その行へカーソルを移して画面に入れる (viewer が動かしたカーソルとして、0.4 秒は `x`・選択肢を受け付けない)。指す行が隠した行 (H で表示していない) なら動かず「隠した行です。H で表示すると行けます」
  - 戻る: `g` で飛ぶたび (字でも数字でも、ブラウザではリンクのクリックでも) 飛ぶ前の行と位置を覚える (20 まで)。`g` のあと `-` で、いちばん新しいものへ戻る (カーソルとスクロールだけ。開閉は戻さない)。覚えたものがあれば一覧に `- 戻る`。飛び先・リンク・戻るのどれかがあれば `g` は効く
  - リンクがちょうど 1 つの行では、案内の行に `g 1 → <指す行の題 (16 字まで)>` を出す (あることを知るため。狭いときいちばん先に落とす: `DropRank` の `link`)
  - ブラウザ: 中身の中のリンクはボタン (Tab で届き、クリックか enter で行く)。行の題の中のものは行のボタンの中なので span だが、クリックで行く。ブラウザの「戻る」は使わない。飛んだあとはバーに `g - ← 戻る` (押すと戻る)
  - 見るときに指す行が無い (check のあとで書き換わった) リンクはただの文として描き、数字も振らない
- 端末の `Code` の長い行は折り返し、続きの行はその行の中身の最初の列 (字下げと、`diff` なら印とそのあとの空白を過ぎた所) の下から始める。列は描いたとおりに数える (タブは 4 桁)
- 題の折り返しと右端の語の置き方は SPEC-format.md の「描き方」。スクロールとカーソル移動は行 (部品) 単位のまま。カーソルの行の題が折り返していて画面の端で切れるときは、その題が全部入るようにスクロールする (画面より高いときは頭を出す)

### お知らせ (`Notice`)

AI が「まずこれを見て」と伝える部品 (書き方と描き方は SPEC-format.md)。報告のどこをスクロールしていても見える。

- 画面を開いたとき、最初のカーソルは `Notice` があればそこに置く (置かれただけのカーソルでは答えを受け付けない決まりはそのまま)。`k` でいちばん上の行からさらに上へ行くと `Notice` に入る (カーソルの順は `Notice` が先)
- 固定の領域は画面の高さの 1/3 まで。入らなければ `ほか N 件のお知らせ` にまとめる。カーソルのある `Notice` は必ず見える (SPEC-format.md の「描き方」)。報告とカーソルの行は低い画面でも残る
- `?` の一覧: 「報告のいちばん上からさらに k で、上に固定されたお知らせへ」
- `Notice` の上で `x` で隠す (ほかの行と同じ記録・同じ `changes`・同じ `u`。鍵は種類 + id + 文なので、AI が文を書き換えたらまた現れる)。`c` でコメント
- 反応待ち・未読の印は付かず、`space` の飛び先と右上の数にも数えない (常に見えているので)
- 報告の誤りの行 (と、壊れた報告のあいだの `AI が報告を直しています`) は今までどおり報告の頭 (スクロールする側) に出す
- 付けた時刻 (`at`) を題の行の右端に薄く出す (今日なら時刻だけ、今日でなければ `11/23 21:46`)。`-h` の作法で、AI には必ず付けさせ (`date '+%Y-%m-%d %H:%M'`)、文を書き換えて知らせ直すときは時刻も新しくさせる。`at` だけの変化では、隠したものはまた出ない

### 反応待ちと未読

報告が長くなっても「どこに手を付ければよいか」を見失わないように、行頭の印の左に印を出す。左から、カーソルの `>` の列、印 (`●`) の列、行頭の記号 (`·` `✓` `?` `→` `▸` `!`)。
カーソルが乗っても印は消えず動かない。印の無い行も同じ幅を空け、行頭の記号の列は全行で揃う。字下げされた行でもカーソルと印の列は左端。
描くときは前の画面と違う行だけを書き直す (最初の 1 枚と端末の大きさが変わったあとは全部)。

- **反応待ち** (黄の `●`): いまの内容 (`sig`) に対する答えがまだ無い `Ask`。選択肢を選ぶか、コメントを書くと消える (コメントは書いたときの行の内容 (`line`) を覚え、`Ask` が書き換わるとまた付く。コメントを取り消しても付く)
- **未読** (緑の `●`): AI が `look="y"` を付けた行 (`Item` `Link` `Fold`) で、人がその行のいまの内容をまだ見ていないもの。`look` の無い行には、内容が変わっても付かない。反応待ちでもあれば黄を優先
- 「見た」になるのは、人がキーで示したときだけ:
  - `r` (読んだ): カーソルの行 (画面に出ていて、「報告が書き換わりました」の間でない。一度も動かしていないカーソルでも、viewer が動かしたカーソルの 0.4 秒の間でも効く) の緑の `●` を消す。`Fold` の行では、`Fold` 自体と、中の未読 (隠した行・反応待ちの行は除く) をまとめて消す。緑の `●` が無い行 (黄の行も) では何もしない
  - その行に選択肢の答えをした、コメントを置いた (`enter` で置いたとき。書き始めただけでは消えない)、隠した (戻した)
  - `A`: いま報告にある行すべて
  - **カーソルを当てる・離す・開く (閉じる)・画面に出るだけでは見たことにしない**
- 案内: 緑の `●` のある行にカーソルがあるときだけ `r 読んだ` (`enter` の次。狭いときは選択肢と同じ順で落とす)
- 鍵は行の内容: 隠すときの鍵 (`hideKey`) に、`note`、開いたときの中身 (`Item` の中身、`Ask` の選択肢)、`Link` の `path` / `url` を加えたもの。`Fold` は題と中身すべて。内容が変われば、また未読になる (`look` が付いている間)
- 記録は `.pitboard/<session>/viewed` に、鍵の SHA-256 の頭 16 バイト (16 進 32 字) を 1 行ずつ追記する (`-` を頭に付けた行は取り消し。`r` と `A` の `u` で使う)。AI には届けない。読めなければ空、ハッシュでない行は読み飛ばす。ほかの viewer が書き足したら読み直す
- `A` (shift+a) で、いま報告にある行をすべて見たことにする
- 隠した行には印を出さず、数えず、飛ばない
- `Fold` の中 (開閉によらず) に反応待ち・未読があれば、`Fold` の行にも同じ印 (黄を優先)
- `space`: カーソルより下にある「印のある行」(黄の `●`、`wait="you"` の `Item`、緑の `●`。優先順は無い) のうち、いちばん近いものへ飛ぶ (下に無ければ先頭から。一周する)。閉じた `Fold` の中なら開いて中の行へ。人が動かしたとみなす (置かれたカーソルの扱いは消える) が、飛んだ直後の 0.4 秒は `x`・選択肢のキーが効かない決まりは守る。印のある行が 1 つも無ければ「印のある行はありません」
- いちばん上の行の右端 (誰の番かの右、`AI 待機中` `未送信` の左) に `反応待ち 2  未読 5` (反応待ちは黄、未読は緑。0 のものは出さない。未読は反応待ちでない未読の数。`look="y"` の `Fold` 自体も数える)
- 案内: 印のある行 (`wait="you"` も) があるとき、`space 次へ` を `m 書く` の手前に出す。狭いときは `x` と同じ順で最初に落とす
- 前へ飛ぶキーは作らない (`b` は `Option` の `key` によく使われるため)。`Option` の `key` に使えないキーは SPEC-format.md

### コメントの画面

端末の viewer の画面は 2 つ: 報告と「コメント」。`l` を押すたびに 報告 → コメント → 報告 … と切り替わる (`tab` も同じ)。どの行に書いたものも、コメントの画面で横断して見る。報告の画面の下にはコメントを出さない。

                                                           あなたの番  未送信 1
     > 未送信  5  aquaやghtknはどうしているか調べてみて
                  ← 依存ツールの入れ方
       既読    1  hook は Stop でいい？
                  ← hook を入れるか決める
       ─ 済んだもの ─
       対応済  2  入れる。このツールの組み込みskillにもその旨を書くといいかも
                  ← skill の置き場所   対応: SKILL.md に 1 行足した

     enter 開く  g 行へ  e 直す  x 取り消す  l 報告へ  s 送る  m 書く  ? キー

- 画面は添字で持ち (報告 0、コメント 1)、`l` は次の添字へ (最後の次は報告)。画面を足すときは並びに足す
- 切り替えても報告のカーソル・スクロール・開閉は動かさない。報告に戻ると、元の所にカーソルがある (画面に入れる)。コメントの画面のカーソルも、戻ってきたとき同じコメントにある
- 見出しは置かない。いちばん上の行は報告と同じく右上の語 (`あなたの番` `未送信 N` など) の行で、その下からコメントを並べる。AI がまだ済ませていない数は報告の案内の `l コメント N` で見る。コメントが 1 件も無ければ、薄く `コメントはまだありません。m で書けます`
- 並べる順は `page.Pending`: 済んでいないもの (未送信・送信済・既読・対応中・保留。新しい順) を先に、薄い区切り `─ 済んだもの ─` の下に `対応済` のもの (対応済になったのが新しい順)。区切りは対応済のものがあるときだけ
- 1 件は 2 段: 1 段目に状態の語 (幅をそろえた列。色はコメントの状態のとおり)、番号 (薄く、幅をそろえる)、本文 (改行は空白に。2 行まで折り返し、超えたら 2 行目を `…` で終える。続きの行は本文の列から)。2 段目に薄く `← 行の題` (書いた時点の題と違えば `(書いたときは: …)` を添える。宛先なしは `(宛先なし)`、報告にもう無い行は `(報告にもうない行)`)、AI の対応があれば続けて `対応: ` (`対応中: ` `保留: `) とその文の 1 行目 (頭の語だけ薄く)。2 段目は 1 行に切る。`対応済` の本文は薄く
- キー:
  - `j` `k` で動く。入りきらなければ画面の中で送る (`ctrl+d` などの画面だけを動かすキーも効く)
  - `enter`: そのコメントを開く / 閉じる。開くと 2 段目の代わりに、紐づいた行の題 (`行: …`。書いたときは: …)、全文、AI の対応の文の全部 (無ければどこまで進んだか) を出す。AI の対応の文を全部読めるのはここ
  - `g`: そのコメントの行へ。報告の画面に戻り、その行を囲む `Fold` を開いて、カーソルをその行に移し画面に入れる (行へのリンクで飛ぶのと同じ。`g -` で戻れる。viewer が動かしたカーソルとして 0.4 秒は `x`・選択肢を受け付けない)。行へ行けないときは動かず、断りの文 (`page.Refusals`) を出す: 宛先なし「宛先なしのコメントです。行はありません」、報告にもう無い行「その行は報告にもうありません」、隠した行 (H で表示していない)「隠した行です。H で表示すると行けます」。行へ行けるときだけ案内に `g 行へ`
  - `e` で直す (上の「コメントを直す」)、`x` で取り消す (下の「コメントを取り消す」)
  - `l` `tab` `q` `esc` で報告へ (`q` はここでは終了しない)
  - `m` `s` `?` `u` は報告と同じ。`c` と選択肢のキー・`space` `A` `H` は効かない (`g` は飛ぶ先を選ばず、そのコメントの行へ)
- 案内: カーソルのコメントに `enter 開く` (開いていれば `enter 閉じる`)、`g 行へ` (行へ行けるときだけ)、`e 直す` `x 取り消す`、続いて `l 報告へ`、そのあと報告と同じ (`u 元に戻す`・`s 送る`・`m 書く`・`? キー`)
- 報告の画面の案内: コメントが 1 件でもあれば、`? キー` の手前に `l コメント N` (N は AI がまだ済ませていない数。ブラウザのバーの `コメント N` と同じ)。狭いときは `m 書く` と一緒に落ちる (`? キー` より先)
- 右上の語 (`あなたの番` `未送信 N` など) はコメントの画面にも出す
- 行の右端 (AI が書いた `status` の左) に、その行への人の入力 (コメント・答え) のうち**いちばん新しいもの**の状態を 1 語で出す:
  状態の語は上の「コメント」のとおり (`対応中` `保留` `対応済` はコメントだけ)。`未送信` は黄、ほかは薄く。
  答えは押したキーも出す (`a 未送信` → `a 送信済` → `a 既読`。AI が行を書き換えたら消える)。いちばん新しいのがコメントのときも、いまの答えのキーは頭に残す (`a 未送信`)。
  `✎N` は出さない。コメントが 2 件以上あるときだけ、状態の左に薄く件数 (`2 既読`)。開くと中身の下に、そのコメントと状態が並ぶ
- 行の下のコメントのうち `対応済` のものは、1 件でも、ほかのコメント (未送信・送信済・既読・対応中・保留。書いた順) の後ろの薄い 1 行 `✎ 対応済 N 件` (`page.DoneFoldWord`) に畳む。畳んだ分は行の下では出さない (`対応済` が増えても件数だけ変わる)。全部コメントの画面 (`l`。ブラウザはコメントの欄) で読む。行の上の `enter` は開くか閉じるかだけ (端末・ブラウザとも)。畳んだ 1 行はほかのコメントの行と同じくカーソルが止まらず、押しても何も起きない。コメントの画面は畳まない
- 色はパレット (`internal/page` の `page.Palette`) の 6 つだけで、それぞれ 1 つの意味にしか使わない。両方の画面が同じ名前を自分の色に写す (ブラウザは CSS の同じ名前の token、端末はエスケープ)。それ以外はふつうの文字の色で、区別は間と太さ:
  - `need` 黄 = **人の手が要る** (反応待ちの `●`、`未送信 N`、行の右端の `未送信`、`wait="you"` の `Item` の `status`、お知らせの題、断りの文 (キーが効かなかった理由))
  - `move` 緑 = **動いている・未読** (未読の `●`、`state="doing"` の `Item` の右端の語 (`status`、無ければ `作業中`)、コメントの `対応中`、diff の `+` 行)
  - `quiet` 薄い = **済んだ・待っている・添え書き** (それ以外の `status`、`送信済` `既読` `保留` `対応済`、済んだ項目、リンク先、diff の `@@`)
  - `structure` 青 = **見出し・リンク・カーソル・フォーカス** (節の見出し、最上位の `Fold`、小見出し、欄の見出し、リンクの題、`>`、`g` の字)
  - `yours` 青緑 = **人が入れたもの** (答えのキー、選んだ答え)
  - `bad` 赤 = **誤り・消した行** (書き方の誤り、diff の `-` 行)
  ただの知らせの文 (「コメントを置きました」など) と右上の `あなたの番` はふつうの色 (`page.ColorNormal`。名前の付いた色ではない)。diff の `+` `-` `@@` は同じ太さ。`?` の一覧の終わりに、この 6 色を同じ語で並べる。
  端末もこの 6 色の外の色を使わない (紫は無い): インラインの code とコードの塊はふつうの色 (code を見分ける色の外の印は無い)。エディタの見出しは `structure`。知らせの文はふつうの色、断り (`page.Refusals`) は `need`、報告の書き方の誤りと読めなかったことは `bad`。`g` の字と数字は `structure`。diff の `@@` は `quiet`、`+` は `move`、`-` は `bad`。
  端末の最上位の `Fold` は開いても閉じても青の太字 (▸/▾ の形だけが違う。そのままにする)。
  `status` の色は語ではなく属性で決める (`あなた待ち` の前方一致はやめた)
- `wait="you"` の `Item` は反応待ちに数えないが、`space` で飛ぶ先には含める (ほかの印と同じ扱いで、近い順)
- 起動時に `.pitboard/<session>/report.md` がなければ、「AI はまだ報告を書いていません」と出して待つ (ファイルができたら描く)
- `-s` なしで、カレントディレクトリと親のどこにも `.pitboard/` が無ければ「このディレクトリと親に pitboard の置き場 (.pitboard/) がありません。AI を動かしているディレクトリで開いてください」、
  `.pitboard/` はあるがセッションが無ければ「pitboard にはまだ報告がありません。AI が報告を書くと、ここに出ます」と出して待つ。
  `-s` のセッションがまだ無ければ「セッション <id> の報告はまだありません」。
  セッションを待っている間 (と `-s` のセッションがまだ無い間) は、案内の行の右に、見ている場所 (`.pitboard/` のある、または探し始めたディレクトリ。ホームは `~`。長ければ頭を `…` で切る) を薄く出す

### 画像を貼る

- エディタで `ctrl+v`: クリップボードに画像があれば `.pitboard/<session>/images/<N>.png` に保存し、カーソルの位置に `[Image #N]` を入れる。
  N はセッションの画像の通し番号 (1 から。`images/last` と、ある画像ファイルの大きいほうの次。消しても再利用しない)
- 取り出しは外部コマンド (依存を増やさない): macOS は `osascript` でクリップボードの PNG (`«class PNGf»`) を書き出し、無ければ TIFF (`«class TIFF»`) を書き出して `sips` で PNG に。
  Linux は `wl-paste --type image/png`、無ければ `xclip -selection clipboard -t image/png -o`。
  どれも無い・画像が無いときは「クリップボードに画像がありません」と出して何も入れない。3 秒で打ち切る。20 MiB を超える画像は保存せず「画像が大きすぎるので貼りませんでした (20 MiB まで)」
- 端末からの貼り付け (bracketed paste) が、ある画像ファイル (`.png` `.jpg` `.jpeg` `.gif` `.webp`、大文字も) の絶対パス 1 つだけ (前後の空白、`'…'` `"…"` の囲み、`\ ` などのエスケープ、`file://`、`~/` は許す) なら、
  `images/<N>.<拡張子>` にコピーして `[Image #N]` に置き換える (ファイルを端末へドラッグしたとき)。それ以外は文のまま
- `[Image #N]` は文の中のただの文字。消せば、その画像は使われない (ファイルは残す)。画面では薄い色 (エディタ、コメントの画面、行の下)
- AI への届き方: `changes` / `wait` / hook の出力で、コメントの行の下に `  image N: <絶対パス>` (上の「コマンド」)
- 画像ファイルの権限は 0600、`images/` は 0700

### u で取り消す

- `u` は、この viewer を開いてからした操作を、新しい順に 1 つずつ取り消す。対象: 選択肢の答え、コメントを置く、直す (`e`)、取り消す (`x`)、行を隠す / 表示に戻す、`r`、`A`。`s` (送る) は取り消せない
- 報告・コメントの画面のどちらでも効く。書いている途中のエディタの中では文字。カーソルは動かさない (取り消しで行やコメントが消えたときだけ、隠すときと同じく次へ)
- 記録は追記だけ: `{"op":"undo","undo":N}` を足す (`r` と `A` は viewed に `-<hash>` を足す。AI には届かない)
- まだ送っていない操作: 無かったことになる (前の状態に戻る。`b` の前に `a` と答えていれば `a` に戻る)。AI にも届かない
- もう送った操作: 取り消しが新しい未送信の入力になる。行の右端は送るまで `取り消し 未送信`。`changes` には、答え・隠す・戻すは `retract answer unit = a (選択肢の文)` `retract hide: 題` のように、コメントは `retract thought N`、直しは元の文での `edit thought N`、コメントの取り消しは `unretract thought N`。送ったが AI がまだ読んでいないものを取り消して送ったら、どちらも届けない
- 下の行に何を取り消したかを 1 行 (例: `y を取り消しました: hook を入れるか決める`、`答え a を取り消しました: …`、`コメントを取り消しました: …`、`コメントの直しを取り消しました: …`、`取り消したコメントを戻しました: …`、`隠したのを取り消しました: …`、`表示に戻したのを取り消しました: …`、`r (読んだ) を取り消しました: …`、`A (すべて読んだことにする) を取り消しました`)。何も無ければ `取り消せる操作がありません`
- 案内: 取り消せるものがあれば `u 元に戻す` (コメントの `x 取り消す` と同じ語にしない。語は `page` の `WordUndo` `WordRetract`)。狭いときは最初に落とす (`x` より先)

### コメントを取り消す

- コメントの画面で、コメントの上の `x`: そのコメントを取り消す (`retract`)。コメントの画面・報告の行の下・行の右端から消える。対応の付いたものも取り消せる
- 下の行に「取り消しました (u で戻す)」。`u` で戻せる (下の「u で取り消す」)
- 取り消すとカーソルは次の件 (無ければ前の件) へ移る。移った件は、画面に出てから 0.4 秒たつまで `x` が効かない
- AI への届き方 (`changes`): まだ届いていないコメントを取り消したら、コメントも取り消しも届けない (未送信にも数えない)。
  届いたコメントなら `retract thought 9: <本文の頭>`。取り消しが届いたあとで戻したら `unretract thought 9: <本文の頭>`。届く前に戻したら何も届けない
- 取り消したコメントへの `settle` はエラーにしない

## ブラウザ

`pitboard serve` は同じボードをブラウザに出す (`internal/web`)。決まり (行が何か・印・右端の語・できる操作・操作の記録と断り・人に見せる文) はすべて `internal/page` にあり、端末の viewer と同じ関数を通る。ブラウザが持つのは、開閉・選んでいる行・エディタ・描き方だけ。端末とブラウザを同時に開いてよく、片方でしたことは 0.5 秒ごとの見張りでもう片方に出る (ブラウザへは SSE で「変わった」を送り、ページが読み直す)。

- サーバーはユーザーに 1 つ: `pitboard [-s S] serve` は、どのディレクトリでも、ボード (いまと同じく、根のディレクトリとセッション) を決め、サーバーが動いていなければ自分を `--foreground` で別のプロセス (新しいセッション・プロセスグループ) として起動して答えるまで待ち、そのボードをサーバーに登録して (鍵付きのローカルの呼び出し)、`http://127.0.0.1:7482/s/<id>/` を出して開き、すぐ終わる (終了コード 0)。`<id>` は登録済みのボードの中で一意な、セッションのいちばん短い頭 (8 文字以上。同じセッション名が別のディレクトリにあれば `~2` などを付ける)。一度付いた id は変わらず、ほかのボードに付くこともない (外したボード・消えて外れたボードの id も、`boards.json` に墓標 (id・ディレクトリ・セッション) として残し、サーバーを起動し直しても別のディレクトリやセッションには付けない。同じディレクトリの同じセッションをもう一度登録すると、元の id に戻る)。別のセッション・別のプロジェクトで実行すればそのボードが加わるだけで、起動し直さず、開いているタブはそのまま使える。セッションのディレクトリがまだ無ければエラー (`path` が作る)。セッションが 1 つも無ければ一覧だけを開く
- 状態はユーザーの状態ディレクトリ (`$XDG_STATE_HOME/pitboard/`、無ければ `~/.local/state/pitboard/`、0700) に置く: `token` (0600。URL と cookie の鍵。256 ビットの 16 進。最初に要るときに作り、起動し直しても、`--stop` でも、ひとりでに止まっても消さず使い続ける。リンク・自分のものでない・0600 より緩い・形の違うものは使わず作り直す。`serve --rotate` で作り直す)、`serve.json` (0600。pid・プロセスの開始時刻 (`waiting` と同じ、使い回された pid を見分ける)・ポート・鍵・開始時刻。終わるときに消す。古いもの (プロセスが無い) は無視して置き換える)、`serve.log` (0600。鍵は書かない)、`boards.json` (0600。登録したボード (id・ディレクトリ・セッション) と、外したボードの墓標)。サーバーは起動のとき、状態ディレクトリが 0700 より、`serve.log` `serve.lock` `serve.json` `boards.json` `token` が 0600 より緩ければ (umask 022 で先に作られたなど) 締め直し (リンクは触らない)、`boards.json` のボードを同じ id で戻す。`.pitboard/<session>` が消えたボードは黙って墓標にする。動いている間に消えたボードも見張りが外す (見張りが 3 回続けて見つけられなかったとき。一時的に動かして戻しただけなら外さない)。外れたボードのタブには、すぐ上の帯で「この pitboard は見つからなくなりました。そのディレクトリで pitboard serve をもう一度動かすと戻ります」と出す (SSE の `gone`、以後の呼び出しは 404 で同じ文)。同じディレクトリで登録し直せば同じ id で `/s/<id>/` がまた答える (200)
- 同時に何度 `serve` しても同じサーバーに登録され、同じ URL を出す (状態ディレクトリの `serve.lock` を flock で取ってから探す・起動する)。`serve.json` の開始時刻が空なら、その pid が生きていてもサーバーとは見なさない。`serve.json` `boards.json` は、書くたびに名前の違う一時ファイルを同じディレクトリに O_EXCL・0600 で作り、権限を確かめてから置き換える (同時に書くもの同士が互いの一時ファイルを消さない)。サーバーの中では `boards.json` の書き込みを 1 つずつにし、どの書き込みもその時点のボードをすべて書く。`pitboard serve -h` は serve の使い方
- 道: ボードごとに `/s/<id>/` (ページ)、`/s/<id>/api/page|events|act|send|image…`。スクリプト・スタイル・アイコンはボードの間で共通 (`/main.js` `/render.js` `/parts/*.js` など)。`/_gallery` は部品と層のすべての状態の一覧 (同じ鍵。`docs/spec/web-states.md`)。取り消しの履歴は (ボード, タブ) ごと
- `/` は登録したボードの一覧: 1 行に 1 つ、報告の `Title`・ディレクトリ・ボードの右上と同じ数 (反応待ち・未読・AI 待機中・送信済・未送信)。どれかのボードが変わるたびに出し直す。`j` `k` で動き、`enter` (クリック) でそのボードへ。見た目はボードと同じ静かなもの。一覧より多くのことはしない (いずれ複数セッションをまとめて見る画面の芽)
- 裏のサーバーは、どのボードのページ (一覧も) の SSE も 1 つもつながっていない時間が 30 分続くと自分で止まる。`serve --stop` はそのサーバーを止める (SIGTERM、止まるまで待って言う)。`serve --status` はサーバー (ポート・pid・開始時刻) とボード (id・ディレクトリ・セッション。`--url` で URL も)。`serve --forget [-s S]` はそのボードを外す (動いていればサーバーから外して、開いているタブにすぐ SSE の `gone` を送る。いなければ `boards.json` で墓標にする)。`--foreground` は端末に付けたまま動かす (ctrl+c で止まる。自分では止まらない。そのボードを登録して出す)。`serve --rotate` は鍵を作り直す: それまでの URL と cookie はすべて効かなくなる。サーバーが動いていれば止めて、新しい鍵で起動し直し (ポートは前と同じ。ふさがっていれば既定の探し方)、URL を出す (開くかどうかはふつうの `serve` と同じ)。動いていなければ鍵を変えたと言うだけ
- ブラウザを開くのは、そのボードのページ (一覧なら一覧) の SSE がつながっていないときだけ: サーバーの起動から 3 秒 (`web.OpenWait`) の間はつながるのを待ち (起動し直したとき、開いていたタブが戻ってくる)、つながれば開かない。URL はいつも出す。`--open` は必ず開き、`--no-open` は開かない (両方はエラー)。コマンドは鍵付きの `/api/watching?id=` でたずねる (cookie では受けない)
- 前の版 (セッションごとのサーバー) から: セッションのディレクトリにある古い `serve.json` は無視して消す。古いサーバーがまだ動いていれば `--stop` が止める (できる範囲で)
- 待ち受けは 127.0.0.1 だけ (ポートは既定で 7482 = 電話のキーで「PITB」(`mo` の 6275 = MARK と同じ流儀)。ふさがっていれば 7483 … 7491 と次を試し、それも無ければシステムが選ぶ空き。`--port N` はその番号だけで、ふさがっていればエラー。cookie はポートごとなので、同じポートに前にいたサーバーの cookie は通らず、出た URL を開けば置き換わる)。鍵 (`token`。起動し直しても同じ) 付きの URL を 1 行出し (いつも `?t=` 付き: 新しいブラウザでも開ける)、既定のブラウザで開く (上の決まり。開けなくてもエラーにしない)。鍵は最初の読み込みで HttpOnly・SameSite=Strict・Max-Age 30 日の cookie になり (サーバーに 1 つ。どのボードにも効く。ページ (`/` `/s/<id>/`) とその SSE を cookie で開くたびに 30 日に延ばす)、ほかの要求はすべてそれが要る。読み込んだあとは `?t=` の無い同じボードのページへ送り直す (アドレス欄・履歴に鍵を残さない。ボードの道でなければ `/`)。道の中の id は秘密ではなく、cookie 無しでは何も見えない。知らない id・`..` などは 404。`Host` が `127.0.0.1:PORT` / `localhost:PORT` でない要求、`Origin` の違う POST は断る。状態を変えるのは JSON の POST だけ。どの応答にも CSP (自分のスクリプト・スタイル・画像と blob: の画像だけ) などを付ける
- 登録と外す (`/api/register` `/api/forget`) は、0600 の `serve.json` にある鍵を `Authorization` ヘッダーで送るコマンドからだけ受ける (cookie では受けない。`Origin` は無いか、このサーバーのもの)。登録できるのは、絶対パスの既存のディレクトリ (リンクなら実体のパスで覚える) に、リンクでない `.pitboard/` と `.pitboard/<session>/` があり、どちらも自分のもののときだけ。画像は `.pitboard/<session>/images/` の中の、リンクでない普通のファイルだけを出す
- 報告とコメントの文は data: DOM は `textContent` と要素の生成だけで組む。リンクは http/https だけ (`noopener noreferrer`、新しいタブ)
- 操作には行の `Seen` の代わりにトークンを添える。サーバーはそのタブに見せた行をトークンで覚えていて、その行として `page` の操作を呼ぶ。行がもう違えば「報告が書き換わりました。もう一度押してください」で断り、ページを読み直す
- 取り消し (`u`) の履歴はブラウザのタブごと (タブの id は sessionStorage)。1 時間使われないタブの履歴は捨てる
- 画像: 貼り付け・ドロップでアップロードし、`[Image #N]` を入れる。大きさの上限は端末と同じ。中身を見て PNG JPEG GIF WebP だけ受ける。見せるのはセッションの画像を番号で (パスはブラウザから受けない)。入力欄では文の下に、文が指す画像を並べる。画像の見本はどこでも (入力欄・行の下に置いたコメント・コメントの欄) 同じ大きさ: 文の列 (入力欄、コメントの文の列) の幅の半分を一辺とする正方形に収め、縦横の比は変えず、元より大きくしない。複数は 12px 以上の間を空けて折り返して並べる (2 つが横に並ぶ)。文からも 12px 以上空ける。どの見本にも縁 (`line` の色の 1px の線、角丸 8px) を付け、白い画面の画像もページに溶けない。入力欄の見本には右上に小さな `×` を付ける: 押すと文からその `[Image #N]` を消す (Tab で届く。enter でも押せる。そこで `esc` を押すと書くのをやめる)。クリックで全体。入力欄の下に説明の文は置かない (キーはバー、ほかは `?`)

端末と違うところ:

- お知らせは上に固定し、その下に右上の数 (端末と同じ順: お知らせが先)。時刻は端末と同じ `page.AtWord`。固定の帯は地と同じ色で、下に細い線と少しの間を置き、下を流れる本文と分ける (お知らせが無く数だけの帯でも同じ)。開いたお知らせが画面の高さの 3 割を超えたら固定をやめ、ページの頭に置く (端末と同じ)
- コメントは浮いた欄 (広い画面では本文の列の左右の端にそろえ、下端がバーの少し上のダイアログ (宛先なしの入力欄と同じ CSS の `--float-inset` 1 本)、480px 以下では幅いっぱいのシート。どちらも下のバーの上) にまとめる。下のバーの `コメント N` (N は AI がまだ済ませていないもの。未送信があれば黄で `未送信 M` も) のボタンか `l` で開く (開いているとき `l` で閉じる)。AI がまだ済ませていないもの、済んだものの順、それぞれ新しい順に、状態の語・コメントの行の題・AI の書いたこと・画像 (入力欄と同じ見本の大きさ。クリックで全体) を出す。行の題 (クリック、または行の上で `enter` か `g`。欄はいつも全文を出すので、端末のコメントの画面の `enter` (開く) にあたるものは無い) で欄を閉じ、カーソルをその行に移して見える所に出す (たたまれていれば開く)。欄の中でも `j` `k`・`e` (直す)・`x` (取り消す)・`u` (元に戻す) が効く。キーの語は `page` の `CommentHints` (`x 取り消す`) と `Bar` (`u 元に戻す`)。番号は幅の決まった列に置き、文はその右にぶら下げる。`esc` か欄の外のクリックで閉じる。開いている間フォーカスは欄の中にとどまり、閉じると元の所に戻る。欄は中身の高さで、画面の 7 割を超えるときだけその中でスクロールする。欄・キーの一覧・画像は、固定の帯とバーより上に重なり (重なりの順は CSS の `--z-*` の 1 本)、開いている間ページは薄く覆われてスクロールしない。390px ほどの幅では欄もキーの一覧も画面いっぱいのシート。浮いているもの (`m` の入力欄・コメントの欄・`?` の一覧) は 1 つの面の作り: 地は `--surface` (明るい表示はページと同じ白、暗い表示はページより 1 段明るい)、縁は `line` の色の 1px の線、角丸 14px、影は近い影と広い影の 2 重。縁の線とページの地の明るさの比はどちらの表示でも 1.3 以上 (明るい表示 1.77、暗い表示 1.96)。画像の全体は幕の上に、縁 (1px の線・角丸 8px) とページの地を敷いて出す。ギャラリーの違い `float-edge`: 開いている浮いたものすべてに、地と違う色の 1px 以上の縁があり、ページとの比が 1.3 以上。390px ほどの幅でシートになるときは、`m` の入力欄は上の縁と上の角丸だけ残し、欄と `?` は画面いっぱいで縁を付けない。端末のコメントの画面 (`l`) の役をこれでする (`l` でも開く / 閉じる)。行に付いたコメントは、これまでどおり開いた行の下にも出る
- `j` `k` はカーソルの行を動かし、`↑` `↓` はページだけを動かす (端末と同じ。ブラウザのもとのスクロールで、ページはつかまえない。`pgup` `pgdn`・ホイールも)。一覧のページ `/` も同じ
- `tab` キーはブラウザのフォーカス移動に使う (行とボタンを Tab で順にたどれる)。フォーカスがカーソル: Tab やクリックで行に移ると、その行がカーソルの行になる (人が動かしたことになる)。キーはその行にだけ効く。コメントは「コメント N」のボタンか `l` で開く
- 行は Enter かクリックで開閉する。Space は端末と同じく「印のある行へ」(行のボタンの上でも)。カーソルの行は端末と同じく左の列の `>` だけで示す (塗り・枠・線は付けない。キーボードでフォーカスしたときも。`>` がフォーカスの印なので、どちらの配色でもはっきり見える色)。点線などの枠は下のバーのボタン・入力欄・ダイアログのボタン・画像の見本とその `×` だけ
- 文の左端は 1 本: 節の見出し・最上位の `Fold` の題・最上位の文と箇条・最上位の行の題は同じ列から始まる。`>`・`●`・行頭の印は、その左 (ページの左の余白の中) にぶら下げる (スマホの幅でも。390px でも行の題は見出し・段落・バーと同じ左端。一覧のページも。ギャラリーの違い `text-edge` で 1280 と 390 を確かめる)。開いた `Item` `Fold` `Notice` の中身は親の左端から 1 段 (約 1.5 字) 右で、それが中の物の左端になる (中の行の印はその左)。`>` と `●` の列はどの深さでも左端のまま。右端の語はどの深さでも同じ右の端。どの節の見出しの上も同じだけ空け、行は同じ間で並べ、折り返した題は行の間を詰める
- 下に固定のバーは端末の案内の行と同じ: カーソルの行で効くキー (`page` の `Offer`)、続いて `u 元に戻す`・`space 次へ`・`g 飛ぶ`、`s 送る`・`m 書く`・`? キー` (`page` の `Bar`。語も順も端末と同じ)。ひとつずつがボタン (押すとそのキーと同じ)。ほかに「コメント N」。行そのものにはボタンを出さない。知らせの行・バー・「コメント N」は本文と同じ左端と幅。バーは上の帯と同じく地の色で、上に細い線と少しの間を置き、下を流れる本文と分ける。900px 以上ではバーは 1 行、それより狭ければ 2 行まで: 入らなければ端末と同じ順 (`page.DropRank`: u、x と space、m と ?、g、enter、n、y、c) でキーを落とす。ボタンでないキー (`a b 答える`、`j k 動かすと…`、`shift+enter 改行`) もボタンと同じ色。書き換わった行・ページが置いた行の文はバーではなく、その上の知らせの行に出す (バーを 2 行目に押し出さない)。`g` の間は、バーに飛び先の一覧 (`esc やめる  a 題  b 題 …`) を同じ行数の中で出す: 入らなければ題を短く切り、それでも入らなければ後ろから落として `… +N` と数える。字は `>` の列に出す (何もずれない)。書いている間のバーはエディタのキーだけ (`page.EditorHints`: `enter 置く  esc やめる  shift+enter 改行`)。バーのボタンにもフォーカスの印 (細い線) を出す
- 切れ目の無い長い語 (URL・英字の列) は、題・段落・箇条・コメント・リンク先のどこでもどこで折り返してもよい。黙って切れる所は無い。`Code` も中でスクロールしない: 端末と同じく長い行はどこででも折り返し、続きはその行の字下げ (diff なら印のあと) の下から (タブは 4 桁)。状態の語・時刻・数は折り返さない
- 390px ほどの幅: 右端の語が題の 1 行目の横に幅の 4 割で入らない行があれば、その並び (同じ親の行) のすべての行で右端の語を次の行に右寄せで出す (行ごとに混ぜない)。右端の語の無い行は 1 行の高さのまま、行の間は同じ。その並びの行の下のコメントも、状態の語を次の行に出す。`>`・`●`・印の間は 2px 以上空ける
- 最上位の `Fold` は見出しなので、その中の行は見出しの左端に並ぶ (節の行と同じ)。中の `Fold` の中身は 1 段右
- リンク: 題は青 (`structure`)、行き先は URL でもパスでも薄く、URL はポインタかフォーカスが乗ったときだけ下線
- 閉じた `Ask` の右端は、選んだキーと、その答えの文を入るだけ (切れば `…`)
- コメントの欄の左端は 2 本: 番号 (見出し・欄の注意と同じ) と文 (行・返事・画像と同じ)。「まだ送っていません (s で送る)」は欄に 1 回だけ。開くといちばん上 (見出しが見える) から
- AI の返事は頭の語 (`page.SettleHead`) のあとに続け、2 行目からも頭の語のあとの列に並べる
- `m` (宛先なしのコメント) の入力欄は、どの行の下にも開かない: コメントの欄と同じ所 (本文の列の左右の端にそろえた下の方、下端はバーの少し上で、書くと上へ伸びる。480px 以下ではシート) に浮かべ、上に小さく薄い字で「宛先なしのコメント」(青い見出しにはしない)。キーは同じ。行への入力欄は、置いたコメントが座る列 (1 段右) から。入力欄はどちらも 1 枚のカード (上の面と同じ地・縁・角丸。浮かない行の下のものには影は無い): 中に、上から見出し、文の欄 (それ自体には縁を付けない。カードが欄)、文が指す画像の見本。フォーカスはカードの縁を `structure` の色にして示す
- 浮いた欄 (`m` の入力欄・コメントの欄) が開いている間も、その下に隠れて読めない行は作らない: ページの終わりに欄の高さ (と少しの間) だけ余白を足し (欄が伸びればそのつど合わせる。`render.js` の `pad`、`--float-h`)、どの行も欄の上までスクロールして読める。ホイールやトラックパッドは、ページの上ならページを、欄の上なら (欄があふれていれば) 欄を動かす (入力欄にフォーカスがあっても)。欄の高さは画面の 55% まで (入力欄は伸びて上限で中がスクロールし、その先は欄がスクロールする。画像の見本は 1 列に折り返す)。書きながら `alt+↑` `alt+↓` (端末と同じ) で、入力欄から出ずにページを半画面ずつ動かせる (`?` に書く)。ギャラリーの違い `content-above-float`: 高いページで `m` に長い文と画像を入れ、終わりまでスクロールして、最後の行が欄の上にあること
- 下書きはボードと宛先ごと (sessionStorage のキーに `/s/<id>` を含む)
- 入力欄は書いた行数に合わせて伸び、画面の 4 割で止まってその中でスクロールする
- 隠した行を `H` で出したときは、どの種類 (お知らせも) も薄く、印は `⌀`
- コメントの改行は、行の下でも欄でも AI の返事でも保つ
- 飾りは置かない: 本文 (行) には枠線・カード・塗り・角丸・グラデーション・色の帯は無し。区別は間と太さと、意味のある色 (人が要る・動いている・誤り) だけ。縁を付けるのは、ページの上に浮くもの (入力欄・コメントの欄・`?` の一覧・画像の全体)、入力欄のカード、画像の見本 (外から来た中身) だけ。固定の帯とバーは細い線のまま
- 開ける行 (`Fold`・開ける `Item`・`Notice`) の行頭の印 (`page.SignClosed` / `SignOpen`) は、字ではなく三角を描く: 題の大文字くらいの高さ (幅 0.8 字ほど)、閉じていれば右向き・開いていれば下向き、1 行目の高さの真ん中、色はいまの印と同じ。列の幅と左端は変えない
- エディタ: enter で置く、shift+enter で改行、esc でやめる (書きかけはそのタブに残り、次に同じ所で開くと戻る)。日本語入力の確定の enter では置かない。ctrl+g (外のエディタ) と ctrl+v のクリップボード読み取りは無い (貼り付けはブラウザの貼り付け)
- `q` (終了) は無い。止めるのは `pitboard serve --stop` (または 30 分つながりが無いと自分で止まる。`--foreground` なら ctrl+c)
- キーが効かないときの守り (人が動かしていない選択・書き換わった行・自分で動かした行の 0.4 秒) と、断るときの文・操作のあとの文は端末と同じ (`internal/page` の `Allow` が決める。ページは「どうやってその行に来たか」と経った時間を送るだけ)。下のバーのキーは、いまその行で効くものだけ (`Offer`。断られるキーは出さない。書き換わった行では端末と同じく「報告が書き換わりました…」)。端末が何も言わない操作 (答え・コメントを置く・読んだ) にも、読み上げ用に page の文を出す
- サーバーに届かない (止まった・`--rotate` で鍵が変わった) ときは、上に「つながっていません。pitboard serve が出した URL を開き直してください」を本文の左端に左寄せで出し続け、表示とバーを薄くし、バーのボタンを押せなくする。ボードが外されたとき (`--forget`、または置き場が 3 回続けて見つからない) は、そのタブにすぐ「この pitboard は見つからなくなりました。そのディレクトリで pitboard serve をもう一度動かすと戻ります」を出す。同じ置き場がまた登録されれば同じ id に戻るので、ページは時々たずね、戻ればひとりでに帯を消して読み直す。外した id は別のボードには付けない。つながらないときは裏で静かに試し続け、届いたら消して読み直す (サーバーが同じポート・同じ鍵で起動し直せば、帯が消え、開いている欄・書きかけはそのまま。SSE も待たずにつなぎ直す)。ポートが変わった (7482 がふさがっていた) ことはページには分からないので、文は同じ
- 操作の結果の文は、画面の下に出し、読み上げにも出す (`aria-live`)。端末が何も言わない操作 (コメントを置く・直す) にも短い文を出す。消えるときは端末と同じ `page.MsgClears` (どのキーでも。行の上の enter で開く・閉じるときも、esc も)。文はふつうの色で、キーが効かなかった理由 (断り) だけ黄
- `?` の一覧は、いちばん上から開き、見出しにフォーカスを置く。キーは等幅で決まった幅の列、説明はふつうの色 (補足だけ薄く)、「黄の ●」「緑の ●」はその色。終わりに 6 色の意味 (`page.Palette`)。画面の 85% の高さまで、その中でスクロールする。コメントの欄と同じ面 (縁・角丸・影)。閉じるボタンは `esc 閉じる` (画像も)
- 一覧のページ `/` はボードを 1 行ずつ (題・場所・右上と同じ数)。置き場が見つからないボードは、その文を薄く出す
- ブラウザのページを変えたら `scripts/check.sh` (vet・test・ギャラリー) が通るまで終わりではない (docs/spec/web-states.md)

## コマンド

    pitboard [view]          viewer
    pitboard serve [--port N] [--no-open] [--foreground]
                             同じボードをブラウザで、裏で動かす (下の「ブラウザ」)
    pitboard serve --stop | --status [--url]
                             裏のサーバーを止める・サーバーとボードの一覧
    pitboard serve --forget  そのボードをサーバーから外す
    pitboard path            そのセッションの report.md のパスを出す (無ければセッションのディレクトリを作る)
    pitboard changes         AI にまだ届けていない人の操作を 1 行ずつ出し、届けた位置を覚える (.pitboard/<session>/seen)
    pitboard settle N TEXT   コメント N の状態と対応を書く: `settle N [--doing | --hold | --done] TEXT` (省いたら `--done`)。
                             状態を先に書かない形は 1 組だけで、N (と状態) のあとの語は全部 TEXT (`settle 9 fixed 5 bugs` → 9 に「fixed 5 bugs」)。
                             2 組以上は、各組の前に状態を書いたときだけ: `settle --done 9 TEXT --hold 5 TEXT …` (状態と番号が並んだ所で区切る)。
                             1 組に状態が 2 つあればエラー (直し方を添える)。番号のどれかが無い・`--done` の文が空なら、1 つも書かない
                             (`--doing` `--hold` は文を省ける)。記録は `{"op":"settle","thought":N,"text":"…","state":"doing"}` (done は state を省く)
    pitboard open            状態が doing / hold のままのコメントを 1 件 1 行で出す (下を見よ。無ければ何も出さず終了コード 0)
    pitboard wait [--timeout DURATION]
                             人が送るまで待ち、送られたら changes と同じものを出して終わる (下の「wait」)
    pitboard check           report.md を確かめる (SPEC-format.md の「check が見ること」)。誤りがあれば行番号つきで出し、終了コード 1
    pitboard hook EVENT      Claude Code の hook から呼ぶ (下の「hook」)
    pitboard --skill         Claude Code の skill ファイル (SKILL.md) を stdout に出す
    pitboard -h              使い方のうち毎回要る分 (英語)。AI はこれを全部読んで使う: 目次、始め方、報告の書き方、作法、changes の読み方、コメントへの対応 (settle)、送る。最後に話題の一覧
    pitboard help [TOPIC]    要るときだけ読む話題 (英語)。TOPIC なしは話題の一覧 (-h の最後と同じ)。知らない話題はエラーで、話題の名前を並べる
                             format   部品と属性の全部、色、id、文の決まり (check が叱ったとき)
                             changes  changes が出す行の全部: retract / edit / unretract / → now (届いたとき)
                             send     送ったものが届く道の詳細: wait、PITBOARD_SEND、herdr、tmux
                             hooks    Claude Code の hook の設定 (~/.claude/settings.json)
                             browser  serve (ブラウザで見る)

状態が `doing` / `hold` のままのコメント (取り消したもの・直して状態が外れたものは除く) があれば、`changes` (新しい入力が無くても) と `wait` (届いて終わるとき) の出力の最後に、その番号だけを 1 行で出す。AI が `--done` にし忘れても、道具が毎回見せる。何度も出るので、コンテキストを使わないよう番号だけにする。`settle` の出力には出さない:

    open: 186 201 202 (oldest 2h). Details: pitboard -s 38d12f95 open

番号はその状態になった順に古いものから。20 個を超えたら古い 20 個と `…`。`oldest` はいちばん古いものがその状態になってからの時間 (`s` `m` `h` `d` のどれか 1 つの単位)。`-s` は短い id (「送る」と同じ)。報告の誤りの行より前に置く。

詳しい一覧は `pitboard -s S open` だけが出す。1 件 1 行で、状態、番号、その状態になってからの時間、文の頭 30 字。古い順に全部:

    doing 186 (12m): コメント欄が画面下部すぎる…
    hold 147 (3h): もしかしてこれってmoとかみたいに…

`changes` `settle` (失敗したときも) `wait` (届いて終わる・タイムアウトで終わるとき) と hook の出力 (出すものがあるとき) の最後に、まだ言っていない警告 (下の「行を消したときの警告」) をそのまま 1 件 1 行で足し、報告に誤りがあれば `report.md has N problem(s). Run: pitboard -s <短い id> check` を 1 行足す (短い id は「送る」と同じ)。どちらも無い・報告が無い・読めないときは何も足さない。終了コードは変えない。

壊れた報告は人に届かない: report.md に誤り (`check` が終了コード 1 にするもの。行を消したときの警告は数えない) があるあいだ、viewer とブラウザは最後に読んだ誤りの無い版を出し続け、報告の頭に薄い 1 行 `AI が報告を直しています` (`page.MsgFixing`。お知らせではなく、黄でもない) を出す。誤りの無い版が来ればそれに替わり、1 行も消える。誤りの無い版をまだ読んでいない (誤りのある報告で開いた・最初の報告から誤りがある・空か消えた報告の次) ときは、誤りを出す。出している版の行への答え・隠す・読んだは、ほかの書き換えと同じく今の report.md の同じ行と比べる: 壊れた版でもその行が同じなら記録し、書き換わっていれば `報告が書き換わりました。もう一度押してください` で断る。AI は上の 1 行と `check` で知るので、受け取りを断るコマンドは無い。

### 行を消したときの警告

AI が報告を書き直して、人がまだ用のある行を消したら、道具が AI に言う (気をつけるだけでは防げないので)。

- 覚える: セッションの `rows.json` に、id のある行と id の無い Fold (題と、用が済んだかを決めるもの: 注目の印 (`Ask`・`wait="you"`・`look="y"`)・隠すキー・読んだかの鍵) を、AI の動かすコマンド (`check` と、上の 1 行を足すもの) のたびに今の報告から足す。人の画面が報告を見せたときにも足す (viewer は読み込むたび、ブラウザはページを渡すたび。`board.Store.RememberShown`。変わったときだけ書く): AI がコマンドを 1 つも動かさないうちに消した行も警告する。行の言っていたこと (`Sig`) も覚える。id の無い Fold はコメント・隠すが向かう `Fold|title=<題>` で覚える。誤りのある報告は覚えない (壊れた版の題で上書きしない。警告の題は最後の正しい版のもの)
- 警告: 覚えた行が報告から消えていて、(a) 注目の印があり、人の用がまだ済んでいない: `warning: row "ID" (題) was removed but the person has not hidden or answered it`、(b) 送ったコメントで `対応済` でないものがある: `warning: row "ID" (題) was removed but it has an open comment (N)`。id の無い Fold は `warning: Fold "題" was removed but …`。題は 24 字で切る
- 用が済んだ: 今効いているものだけで数える (`u` で戻した答え・隠すは数えない)。`Ask` と `wait="you"` は答えか隠すか送ったコメント (答えは、覚えた行の言っていたことに付いたものだけ数える: 書き換わる前の問いへの答えは、画面の黄の ● と同じく、答えたことにならない)。`look="y"` はそれに加えて読んだこと (`A` で全部読んだ・隠してから戻したも読んだに入る)。読んだだけでは `ask`・`Ask`・`wait` の用は済まない
- 送っていないコメントは警告しない (AI はまだ知らない)
- 1 度だけ言う: 次に AI が動かす `check` 以外のコマンド (上の行を足すもの) の出力の最後に警告を出し、その行を忘れる (`rows.json` から消す)。それまでは `check` が誤りのあとに毎回出す。行が戻ってまた消えれば、また言う。`wait` を始めるときの標準エラーには出さない (届いて終わるときに出す)。警告は終了コードを変えない。viewer とブラウザには出さない。止めるコマンドは無い
- 言う前に消えるとき: 行が戻ったとき、用が無くなったとき (コメントが対応済になった。そのとき行も忘れる)。用の無い消えた行は黙って忘れる
`wait` は始めるときにも 1 度見て、誤りがあれば誤りの行を標準エラーに出してから待つ。

`-s SESSION` を拾うのは、コマンドの直前か直後だけ (`pitboard -s X cmd …` と `pitboard cmd -s X …`)。TEXT の中の `-s` はそのまま文として残る。

`changes` の出力 (AI が読む。短く、文脈つきで)。括弧の中は押した時点の題。いまの題が違えば `(… → now: …)`、行が無ければ `(… → now gone)`:

    answer base = b (中身は Markdown、項目の区切りと付随情報は道具が持つ)
    thought 7 on hook (hook を入れるか決める): post-tool だけ入れたい
    thought 8: 経過は要らないかも
    thought 10: これを見て [Image #3]
      image 3: /abs/path/.pitboard/<session>/images/3.png
    hide (2): 報告はセッションごと / 経過は要らないかも
    unhide (1): 報告はセッションごと
    retract thought 9: 経過は要らないかも
    edit thought 7: post-tool と stop を入れたい

出力は詰める (送るたびに AI の会話に積もるので):
- `hide` / `unhide` は最後に 1 行ずつまとめる: `hide (N): 題1 / 題2 / …` (題は 20 字で切る)
- 同じ問いの答えを選び直したときは、最後のものだけ出す。前の版の `y` / `n` は出さない
- コメントの紐づけ先の題 (書いたときの題といまの題) は 30 字で切る
- コメント (と `edit thought`) の文に `[Image #N]` が残っていて画像ファイルがあれば、その下に `  image N: <絶対パス>` を 1 行ずつ (同じ番号は 1 回)
- `wait` と hook の出力も同じ
- `retract ` `edit thought ` `unretract ` で始まる行か、` → now` を含む行があれば、最後に `(what these lines mean: pitboard help changes)` を 1 行足す (-h はそれらを詳しく書かないので、読むべき話題へ導く)

`hide` は、人がその行をもう見なくてよいと判断した印。対応は要らない。報告を書き直すついでにその行を落としてよい (`-h` にも書く)。

### wait

端末に依存しない「送る」: AI のほうが待つ。Claude Code では Stop hook (下の「hook」) が待つので、AI は何も動かさない。hook を入れていないときは、AI が止まる前に `pitboard -s SESSION wait` をバックグラウンドで動かす (Claude Code なら Bash の run_in_background)。人が `s` を押すとこのコマンドが終わり、AI が起こされる。

- まだ届けていない `send` があれば (いちばん新しい `send` > `seen`)、すぐに `changes` と同じ出力をして終わる (`seen` も進める)
- 無ければ、0.3 秒ごとに events.jsonl の大きさと更新時刻を見て、変わったときだけ読む。届けていない `send` があれば `changes` と同じ出力をして終了コード 0 (hook が先に届けたら、また待つ)
- `--timeout` (既定は無し。例 `30m`、`--timeout=30m` も可) を過ぎたら、何も出さず終了コード 0。SIGINT / SIGTERM でも何も出さず終了コード 0
- 待っている間は `.pitboard/<session>/waiting` に自分の pid と開始時刻 (`ps -o lstart=`。取れなければ pid だけ) を書き (`O_EXCL` で作る)、終わるときに (自分の pid のままなら) 消す。プロセスがもういない pid、開始時刻が違う pid (別のプロセスに使い回された) は無いものとして扱い、上書きする。viewer の見直しで `ps` を呼ぶのは同じ pid につき 5 秒に 1 回まで
- 同じセッションで 2 つめの `wait` が起動したら、古いほうに任せて `already waiting (pid N)` と出して終了コード 0
- Stop hook が動いたセッション (`.pitboard/<session>/stophook` がある) では `wait` は要らないので、AI にそう伝える。`wait` の出力の最後に 1 行 `The Stop hook now waits for the person's sends: they arrive by themselves. Do not run 'wait' again in this session.` を足す (報告の誤りの行より後)
  - `wait` が待っている間に hook が動いたとき (hook は黙って終わり、印だけ残す): 届いて終わるとき・タイムアウトで終わるときの出力の最後に足す。シグナルで終わるときは何も出さない
  - 印がすでにあるときに起動した `wait` は待たない: 届けていない `send` があれば `changes` と同じ出力をし、その 1 行を出して、すぐ終了コード 0
  - 印が無ければ `wait` は上のとおり。`changes` の出力には足さない
- 届く道は hook、wait、端末への打ち込み。`s` が起こすのは待っているもの (Stop hook か wait) か打ち込み (上の「送る」)。`post-tool` の hook は `s` では起こさず、作業中に届ける

### hook

    pitboard hook post-tool       ツール実行のあと (PostToolUse。AI の作業中に届ける)
    pitboard hook stop            AI が止まったあと (Stop。`"asyncRewake": true` で入れる。人が送るまで待ち、AI を起こす)

Claude Code ではこれが勧める届け方 (AI はコマンドを 1 つも動かさない)。設定は `pitboard help hooks`:

    "PostToolUse": [{ "hooks": [{ "type": "command", "command": "pitboard hook post-tool" }] }],
    "Stop":        [{ "hooks": [{ "type": "command", "command": "pitboard hook stop", "asyncRewake": true, "timeout": 86400 }] }]

- stdin に hook の JSON が来る。`session_id` と `cwd` を使う。`-s` `$PITBOARD_SESSION` と作業ディレクトリは見ない。stdin は 1 MiB までしか読まず、超えたら何もせず終了コード 0
- ボードは `cwd` から親へさかのぼって探す (コマンドと同じ。AI が `cd` しても届く)。`session_id` そのものの名前か、その先頭 (8 字以上) の名前のボード。同じディレクトリでは id そのもの、次にいちばん長い先頭
- **ボードが無いセッションでは何も出さず、何も作らず、終了コード 0** (`cwd` から上にボードが無い、stdin が JSON でない、`session_id` が無いか使えない文字、のどれでも)。hook は全セッションで走るので、使っていないセッションに一切影響しない
- それがあっても、読めない・書けないときは何も出さず終了コード 0 (毎回エラーを出すとセッションが使いづらくなる)。events.jsonl がまだ無ければ作らない
- 文面は `pitboard (the person acted on the board):` の 1 行、`changes` の行、最後に `Settle each thought with "pitboard -s <ボードの名前> settle N [--doing|--hold|--done] TEXT" (several: --STATE N TEXT --STATE N TEXT ...) once you know what to do with it.`
- `post-tool`: `changes` と同じく、まだ届けていない人の操作を届け、届けた位置を覚える。出力は stdout に `{"hookSpecificOutput":{"hookEventName":"PostToolUse","additionalContext":"..."}}`。届けるものが無ければ何も出さず終了コード 0
- `stop`: `asyncRewake` の hook は AI が止まったあとも裏で動き続け、終了コード 2 で終わると Claude Code が AI を起こして標準エラーの文を読ませる (終了コード 0 なら何も起きない)
  - AI の対応が要るもの (`hide` / `unhide` 以外) がすでに送られていて届けていなければ、すぐ届ける。無ければ `wait` と同じに待ち (同じ `waiting` ファイル、同じ `AI 待機中`、同じ見張り方)、次に送られたら届ける
  - 届ける: 文面を標準エラーに出し、終了コード 2 (stdout には何も出さない。pitboard 自身のエラーの行も出さない)。届けた位置を覚える
  - 送られたものが `hide` / `unhide` だけのときは起こさず、待ち続ける (次に届けるものと一緒に届く)
  - 同じセッションでほかの `wait` か hook がすでに待っていれば、任せて、何も出さず終了コード 0
  - SIGINT / SIGTERM / SIGHUP では何も出さず終了コード 0 (`waiting` を消す)。Claude Code は設定の `timeout` 秒で hook を終わらせる (既定は短すぎるので 86400 を書く)。そのあとは、チャットに何か書かれるか AI が次に止まったときに、また待ち始める
  - `stop_hook_active` は見ない
  - ボードのあるセッションで起動するたびに、印 `.pitboard/<session>/stophook` (空のファイル) を書く: このセッションには Stop hook が入っている。`wait` がこれを見て、もう要らないと AI に伝える (上の「wait」)。印は消さない

### 組み込み skill

skill は薄くする (道具を更新しても skill が古くならないように)。repo の `skills/pitboard/SKILL.md` が skill そのもので、`pitboard --skill` はこれと同じ文を出す。`//go:embed` は `cmd/pitboard/` から上のディレクトリを指せないので、同じ文を `cmd/pitboard/skill.go` に定数で持つ。正は SKILL.md で、ずれるとテスト (`TestSkillMatchesSKILLmd`) が落ちる。
中身は frontmatter (`name: pitboard`、英語の description) と、「`pitboard -h` を全部読んでから使う。書いてあるのは、いま入っている版の使い方」、どの場面でどの話題 (`pitboard help TOPIC`) を読むかの表、要点の数行だけ。`-h` に書いてあることは繰り返さない。
入れ方は `gh skill install qawatake/pitboard pitboard`、または `pitboard --skill > ~/.claude/skills/pitboard/SKILL.md`。

使い方は全部バイナリに置き、毎回要る分と要るときだけの分に分ける (毎回読む量を小さくするため。skill の progressive disclosure と同じ考え)。
- `pitboard -h` (毎回全部読む): 目次、何のための道具か、始め方 (セッション id の取り方、`path`、viewer を横に開いてもらう)、報告の書き方の要点と例、作法、`changes` の読み方の要点、コメントは必ず `settle` する、送る (止まる前に wait、`s` で打ち込まれる文と、そのときにすること)。最後に話題の一覧
- `pitboard help TOPIC` (要るときだけ): 上の「コマンド」の format / changes / send / hooks / browser
- 道具の出力が話題へ導く: `check` は誤りを出したあと `(every part, attribute and text rule: pitboard help format)` を 1 行足す。`changes` / `wait` / hook は上の「`changes` の出力」のとおり `pitboard help changes` を指す

AI の作法 (報告の書き方の勧め、返事の置き場所、`settle` の仕方など) の正は `-h` の "Manners"。ここには書かない。

## 作り

- Go、標準ライブラリだけ
- 0.5 秒ごとに report.md と events.jsonl の変化を見て描き直す
- 人が指していない行に答えが付くことが絶対に起きないこと (id で追う。カーソルの行が画面の外にあるとき、「報告が書き換わりました」を出している間、人が一度も動かしていないカーソルでは、答えを受け付けない)
- SIGTERM / SIGINT / SIGHUP で止められたときも、端末を元に戻してから終わる (raw mode、代替画面、カーソル、ブラケットペースト)。終了コードは 128 + シグナル番号
- 外のエディタ (`ctrl+g`) を開いている間は SIGINT を無視する (エディタの中の ctrl+c で、エディタを閉じたあとに viewer が終わらない)。エディタから戻ったら元に戻す
