# pitboard (仮称) 仕様 v0

AI のセッションの横のペインに置く板。`sketch/pv` の試作を土台に、最小の形で作る。

名前の見立て: レース中のドライバーには話しかけられないので、周回ごとにボードの前を通るときに読ませる。
人が書いたことは、AI が区切り (ツール実行の合間) を通るときに届く。

## 考え方

書き手を分ける。同じファイルを人と AI の両方が書き換えることはしない。

| | 書く人 | 置き場所 | 形式 |
|---|---|---|---|
| 報告 | AI だけ | `.pitboard/report.md` | 下の「報告の書き方」。AI は普通のファイル編集 (Edit/Write) で書く |
| 人の操作 | 人だけ (viewer 経由) | `.pitboard/events.jsonl` | 追記だけの記録 |

- 置き場所は `.pitboard/<session>/` (SPEC-format.md の「置き場所」)。カレントディレクトリから親へさかのぼって探す
- 構成 (どんな節を作り、何を並べるか) は AI が自由に決める。部品の種類と描き方は道具が固定する
- 人の操作は報告を書き換えない。「id への反応」として記録し、AI がそれを読んで報告を書き換える

## 報告の書き方 (部品)

`sketch/BRIEF.md` `BRIEF2.md` `BRIEF3.md` の描き方をそのまま使う。変わるのは **id** だけ。

- 項目・問い・リンクの行末に `^id` を付ける (`- [ ] hook を入れるか決める ^hook`)。id は `[a-z0-9-]{1,16}`、ページ内で一意
- viewer は `^id` を画面に出さない
- **カーソルが止まるのは id を持つ行と、折りたたみと、`- ` のただの行**。ただの行でできるのは `x` (隠す) だけ。段落・見出し・題は読むだけの行
- 再読み込みのあと、カーソルは id で追う。id が消えたら近くの止まる行に移り、下の行に「ページが変わりました」と出す (試作の「文面で追う」処理は捨てる)
- id が同じでも、カーソルの行の題か部品の種類が変わったら同じく「ページが変わりました」を出し、j/k まで反応を受け付けない (`status` `note` `state` だけの変化では出さない。`Fold` の題の変化でも出さない)
- 人が一度も動かしていないカーソル (起動直後と、止まる行が無い状態から止まる行が現れたとき) では `y` `n`・選択肢のキー・`x` が効かない。`c` `m` `enter` は効く。このとき下の行に `j k 動かすと y n が効く` (`Ask` では `j k 動かすと答えられる`、ただの行と `Fold` では `j k 動かすと x が効く`) と出す。幅が狭くても落とさない (`j k → y n` などに縮める)
- viewer がカーソルを動かしたとき (`x` で隠したあと、`H` の切り替えで行が消えたあと、節ごと消えたあと) は、その行にカーソルが乗った画面を描いてから 0.4 秒たつまで、`x` `y` `n`・選択肢のキーを受け付けない (捨てる。ためておいて後で効かせない)。0.4 秒たてば j/k を押さなくても効く (続けて隠せるように)
- `y` `n`・選択肢のキー・`x` は、押した時点の報告を読み直し、画面に出している内容と同じときだけ記録する。違えば「ページが変わったのでやり直してください」
- 再読み込みでカーソルの行が画面の外へ出たら (AI が上に行を足したなど)、画面のほうがカーソルの行についていく。端末の大きさが変わったとき、下の思いつきの欄が伸びたときも同じ (カーソルの行が見えていた場合)

部品の一覧 (これ以外は足さない):

| 書き方 | 部品 | 人ができる反応 |
|---|---|---|
| `# 題` | ページの題 | - |
| `## 見出し` | 節 | - |
| 段落 | 文 | - |
| `- 文` | ただの行 | (id があれば) 思いつきを紐づける |
| `- [ ]` `- [~]` `- [x]` + 文 | 項目 (未完了 / 進行中 / 済み) | `y` / `n` / 思いつき |
| 行内の `{状態}` `{状態: 理由}` | 右端の状態 | - |
| `- [?] 文` と下の `- (a) 文` | 問い | 選択肢の文字キー (`a` `b` …) / 思いつき |
| 項目の下の字下げされた文 | 開いたときの中身 | - |
| `[題](path)` | リンク。開かない (パスか URL を見せるだけ) | `y` / `n` / 思いつき |
| `<details><summary>題</summary>` | 折りたたみ | - |
| ` ``` ` で囲んだ行 | コード。` ```diff ` なら `+` 緑 `-` 赤 `@@` シアン。長い行は折り返す | - |

## 人の操作 (events.jsonl に 1 行ずつ)

    {"n":1,"t":"...","op":"react","id":"hook","value":"y"}        y / n / 選択肢の文字
    {"n":2,"t":"...","op":"thought","id":"hook","text":"..."}     思いつき。id はカーソルが止まる行の上で書いたときだけ付く
    {"n":3,"t":"...","op":"settle","thought":2,"text":"todo にした","by":"ai"}   AI が書く、思いつきの行き先
    {"n":4,"t":"...","op":"hide","key":"...","title":"画面に出ていた文"}       人が行を隠す (unhide で戻す。同じ key)
    {"n":5,"t":"...","op":"retract","thought":2}                    人が思いつきを取り消す (直後の u で unretract)

`n` は通し番号。追記は flock の下で行う。

### 反応

- 項目・リンクの上で `y` (OK・済み) / `n` (不要・だめ)。問いの上で選択肢の文字
- 押した反応は、その行の右端に `y` `n` `a` として出す。**報告は書き換えない**
- 反応と思いつきの記録には、押した (書き始めた) 時点の行の題を `title` として入れる (選択肢の文は `option`)
- 同じ行に押し直したら、新しいほうが有効 (記録は両方残す)
- AI が報告のその行を書き換えたら (行の文面か状態が変わったら)、反応の表示は消す

### 思いつき

- `m` で画面の下にエディタが出る (試作 ita の editorLines と同じ。読んでいるものは上に残る)。どこにカーソルがあっても効く。
  enter 書く、ctrl+s 書いてすぐ AI に送る (下の「送る」)、ctrl+j / shift+enter / alt+enter 改行、ctrl+g で `$VISUAL` / `$EDITOR` / `vim`、esc やめる。
  案内は 1 行 (`enter 書く  ctrl+s 送る  esc やめる  ctrl+j 改行  ctrl+g エディタ`)。狭いときは後ろから落とす (`enter` `ctrl+s` `esc` は最後まで残す)
- エディタは文中にカーソルを持つ (readline / emacs 風)。文字の入力と貼り付けはカーソルの位置に入る:
  `←` `→` / `ctrl+b` `ctrl+f` 1 字、`↑` `↓` / `ctrl+p` `ctrl+n` 折り返した見た目の行で上下 (桁は全角を 2 として近い所へ。続けて押す間は最初の桁をめざす)、
  `ctrl+a` `ctrl+e` / `home` `end` 行頭・行末 (改行で区切った行)、`alt+b` `alt+f` / `alt+←` `alt+→` 語単位 (空白と、かな・カナ・漢字・英数・記号の種類の変わり目で区切る)、
  `backspace` / `ctrl+h` 左の 1 字、`delete` / `ctrl+d` 右の 1 字、`ctrl+w` / `alt+backspace` 左の 1 語、`ctrl+k` 行末まで (行末では改行を消して次の行とつなぐ)、`ctrl+u` 行頭まで。
  1 字は見た目の 1 字 (結合文字・異体字セレクタ・ZWJ でつないだ絵文字は 1 字)。`pgup` `pgdn` は上の報告を送る
- エディタの文は字単位で折り返す。高さ (画面の 3 分の 1) に収まらないときは、カーソルの行が見えるように送る
- エディタが開いている間は、端末の本物のカーソルを入力位置 (文中のカーソルの位置。全角は 2 桁) に置いて見せる。IME の変換中の文字がそこに出るように。
  色の反転で描いた四角は使わない。閉じたら隠す。描き直しは 1 回の書き込みにまとめ、カーソルが飛んで見えないようにする
- カーソルが止まる行の上で `c` を押すと、その行に紐づいた思いつきになる (エディタの題に行の文面を出す)
- 書いている間に紐づけ先の行の題が変わるか行が消えたら、エディタの題の横に「この行は書き換わりました」と出す。送ることは止めない
- `c` で書いている間、エディタの欄が伸びても紐づけ先の行が画面に見えているようにする
- 貼り付け (ブラケットペースト) の改行は CR・LF・CRLF のどれでも 1 つの改行にする。貼り付けの中の改行で送られることはない
- 書いた時点の題といまの題が違えば、行の下と `tab` の一覧に「(書いたときの題: …)」を添える
- 行の下に出す思いつきは、改行ごとに 1 行ずつ字下げして描く。画面に出す文字列には制御文字を混ぜない
- 思いつきには状態がある: **未送信** (まだ送っていない。黄) → **未読** (送ったが AI がまだ読んでいない。薄く) → **受け取った** (`changes` か hook で届いた。薄く) → **済** (AI が `settle` で行き先を書いた。薄く)。
  画面に出す状態はこの 3 語だけ。行き先の文は `tab` の一覧で、その思いつきを開いて読む

### 行を隠す

人がもう見なくていい行を、板の上で自分で消す。報告は書き換えず、「この内容の行は隠す」という記録を events.jsonl に足し、viewer がその行を描かない。

- `x` でカーソルの行を隠す。確認は出さない (戻せるので)。下の行に「隠しました (H で表示)」(H で表示中は「隠しました」) と出し、カーソルは次の行へ移る (移った行は 0.4 秒たつまでキーが効かない)
- 隠せるのは `Item` `Ask` `Link` `Fold` と `- ` のただの行。段落・見出し・題は隠せない
- 記録の鍵は**行の内容** (id ではない)。ただの行は文そのもの (同じ文の行は一緒に隠れる)、`Item` `Ask` `Link` は種類 + id + 題 + `state` + `status`、`Fold` は id (無ければ題)。
  AI が題・`state`・`status` を変えたら別の行になり、また現れる。中身・`note`・`path`・選択肢の変化や、隠した `Fold` の中身の変化では現れない (`-h` と skill にもそう書く)
- `H` で、隠した行を薄く、印を `⌀` にして表示する / しないを切り替える。表示中に隠した行の上で `x` を押すと戻る (`unhide`)
- 隠した行があるときは、案内の行の右に `隠した行 3` (H で表示中は `隠した行 3 (表示中)`)
- 節の中身が全部隠れたら、節の見出しも描かない。`Fold` の題 (件数など) は AI の文なので触らない
- 隠した行に紐づいた思いつきは、思いつきの欄と一覧には今までどおり出す
- 「一度も動かしていないカーソルでは効かない」「ページが変わりましたの間は効かない」「viewer が動かしたカーソルは 0.4 秒効かない」の決まりは `x` にも当てはまる

### 送る

人は板の上でいろいろ返答して (y / n、答え、思いつき、隠す)、**最後にまとめて送る**。送るまで AI には届かない。

- 報告の画面 (と欄・`tab` の一覧) で `s`: まだ送っていない操作があれば、events.jsonl に `{"n":N,"t":"...","op":"send"}` を追記し、それから AI を起こす (AI のいるターミナルへ 1 行打ち込む)。
  無ければ `send` を追記せず、下の行に「送るものはありません」
- エディタで `ctrl+s`: 書いて、すぐ送る (`enter` は書くだけ)
- `changes` と hook が届けるのは、**いちばん新しい `send` より前の操作だけ**。それより後の操作は次の `send` まで届けない。`changes` は `seen` をその `send` まで進める
- 打ち込む文: `pitboard: the person sent N item(s) from the board. Run "pitboard -s SESSION changes" and act on them.` (N はその `send` で送る件数。内容は打ち込まない。AI が `changes` で読む)
- 起こし方: `$PITBOARD_SEND` があれば `sh -c` で実行 (`PITBOARD_SESSION` と `PITBOARD_MESSAGE` を渡す)。無ければ、`herdr` が PATH にあるとき (viewer が herdr の外でも)、
  `herdr agent list` の JSON (`result.agents[]`) から `agent_session.value` がセッション id と一致する agent を探し、`herdr agent prompt <pane_id> <文>` (シェルを通さない)
- 起こせなくても `send` の記録は残す (AI が次に `changes` を呼べば届く)。知らせは「送る印は付けました。AI を起こせなかったので、チャットで一言伝えてください。」+ 理由。
  この知らせだけは、1 行に入らなければ 2 行使う (1 行目にこの文、2 行目に理由。それぞれ入らなければ `…` で切る)。理由:
  - `herdr` も `PITBOARD_SEND` も無い: 「AI を起こす方法がありません。PITBOARD_SEND を設定してください (pitboard -h の "Send")」
  - `herdr` はあるが、このセッションの agent がいない: 「herdr にこのセッション (<id の頭 8 字>) の AI がいません。AI を herdr の中で動かすか、PITBOARD_SEND を設定してください」
  - 実行に失敗: 「送れませんでした: <理由>」(stderr の先頭 1 行を添える)
- 5 秒で打ち切る。起こしている間は下の行に「送っています…」。成功したら「AI に送りました」。結果の表示は次にキーが押されるまで残す
- 起こしている最中に押されたキーは捨てる (何も出ていない画面に対して押されたものなので)
- 状態の語: **未送信** (`send` より後の操作) と **未読** (送ったが、AI がまだ `changes` を呼んでいない)
- 報告の画面と欄・`tab` の一覧のいちばん上の行の右端に、未読の数を `送信済み 2` (薄く)、未送信の数を `● 未送信 3` (黄) と出す。0 なら出さない。
  いちばん上の行に文があれば (題など) そちらを `…` で切る。スクロールしても画面のいちばん上の行に出る。`s` を押すと未送信は 0 になり、AI が読むと送信済みが消える。書きかけは数えない
- 取り消しとの関係: 未送信の思いつきを取り消したら、送っても届かない (未送信にも数えない)。送ったあと (未読でも) に取り消したら、`retract` が次の `send` で届く

## 画面

- 主画面は報告。`tab` で「思いつき」の一覧に切り替わる (新しいものが上。1 件 1 行で本文と状態だけ。enter で開くと、全文、紐づいた行の題、行き先の文が全部読める。欄に出さないので、ここが唯一の場所)
- 下は静かに。目が行くのは「未送信」だけにする
- 開いた中身 (字下げされた文) はふつうの色。薄くするのは済んだ項目 (とその中身)・隠した行・パスなどの補助情報だけ。
  `note` は `理由: …`、行の下の思いつきに行き先があれば `行き先: …` とし、頭の語だけを薄く
- 日本語入力が入ったままでも動かせるように: 報告・欄・一覧の移動に `↑` `↓` と `ctrl+p` `ctrl+n` (`k` `j` と同じ。人が動かしたとみなす)、`pgup` `pgdn` で半画面。
  エディタの外では、全角の英数・記号 (U+FF01〜FF5E) と全角空白を半角に直してからキーとして扱う (`ｊ` → `j`)。エディタの中ではそのまま文字。案内と `?` の一覧では `j k ↑↓` と並べて書く
- 下の行に出す知らせ (「AI に送りました」「送れませんでした: …」など) は 1 行に収める。長ければ `…` で切る
- 報告の画面のいちばん下の案内は**常に 1 行**。いまの行でできるキーと、最後に `m 書く` `? キー`。`tab` `q` `H` `s` は出さず `?` の一覧に任せる。ラベルは短く (`c 行に書く`、`enter 開く` / `enter 閉じる`)
- 右端の `隠した行 N` は薄く。入らない幅なら出さない。それでも入らなければ `x` → `enter` → `n` → `y` (選択肢も) → `c` の順に落とす (`m 書く` と `? キー` は最後まで残す。ただし「j k 動かすと…」は落とさず、`? キー` も入らない幅ではそちらを残す)
- `Ask` の案内: 閉じているとき `enter 開く  c 行に書く  x 隠す`、開いているとき `a b … 答える  enter 閉じる  c 行に書く`
- `tab` の一覧の案内は `enter 開く` `tab 報告へ` `m 書く` `? キー` の 1 行
- `?` で全キーの一覧。高さに収まらなければ `j` `k` で送れる。`q` か `esc` か `?` で閉じる (ほかのキーでは閉じない)
- `j` `k` は止まる行を動く。その先に止まる行が無ければ 1 行送る。カーソルの行が画面の外にあるときは、カーソルの行の方向への `j` `k` はまず画面をカーソルの行まで戻す (カーソルは動かさない)。次の `j` `k` から動く
- 画面に見えているものには、カーソルで届く: 報告の最後の止まる行から (その下の文を送りきったあと) さらに `j` で、下の思いつきの欄の 1 件目に入る。止まる行が 1 つも無い報告では、文を送りきったあとの `j` で入る。欄の 1 件目で `k` を押すと、報告の最後の止まる行へ戻る (人が `k` で戻ったので、その行ではすぐキーが効く)
- `Ask` の印は、問いが長くて開ける場合も `?` のまま

### 思いつきの欄

報告の画面の下 (案内の行の上) に、スクロールしない「思いつき」の欄を置く。どの行に書いたものも横断して見せる。

    (空行)
    思いつき                                                    s で送る
      aquaやghtknはどうしているか調べてみて                       未送信
      入れる。このツールの組み込みskillにもその旨を書くといいかも   済
    (空行)
    y よし  n だめ  c 行に書く  x 隠す  m 書く  ? キー       隠した行 1

- 欄の上と下に空行を 1 行ずつ入れ、報告の本体と案内の行から離す
- 見出し 1 行: `思いつき` (節の見出しと同じ色) と、右に、未送信があるときだけ `s で送る` (黄。数は右上の `● 未送信 N` に任せる)。思いつきが 1 件も無ければ欄ごと出さない
- その下に最大 3 件。2 桁字下げして 1 件 1 行、**本文と状態だけ** (本文の頭。改行は空白に。行頭の印、`← 行の題`、行き先の文は出さない)。本文はふつうの色、`済` の行は本文も薄く
- 並べる順: 行き先の無いもの (新しい順) を先に、残りの枠に行き先の付いたもの (行き先が付いたのが新しい順)
- 画面の高さが 20 行未満なら、見出しの 1 行だけ (上下の空行も省く)。報告の本体が最低 6 行は見えるよう、件数を減らす
- カーソルが欄にある間 (上の `j` で入る)、欄は画面の高さの半分まで広がり、全件を同じ並びで出す。`j` `k` で動き、入りきらなければ欄の中で送る。高さが低く見出しだけのときも、入れば広がる。報告に戻ると 3 件に縮む
- 欄の行の上で `enter`: その思いつきの全文、紐づいた行の題 (書いたときの題)、行き先の文を、行の下に開く / 閉じる。`x` で取り消す (下の「思いつきを取り消す」)。`y` `n` `c` は効かない。`m` `s` `?` `tab` `q` は今までどおり。
  案内は `enter 開く  x 取り消す  m 書く  ? キー`。カーソルが欄にある間、報告の行には `>` を出さない
- `tab` の一覧は同じものを全画面で見る画面として残す
- 書いている間 (エディタが開いている間) は欄を出さない
- 紐づいた思いつきがある行は、右端に `✎2` のように数を出す。開くと中身の下に、その思いつきと状態が並ぶ
- 起動時に `.pitboard/report.md` がなければ、「AI はまだ報告を書いていません」と出して待つ (ファイルができたら描く)
- `-s` なしで、カレントディレクトリと親のどこにも `.pitboard/` が無ければ「このディレクトリと親に板 (.pitboard/) がありません。AI のセッションを動かしているディレクトリで起動してください」、
  `.pitboard/` はあるがセッションが無ければ「板はまだありません。AI が報告を書くと、ここに出ます」と出して待つ。
  板を待っている間 (と `-s` のセッションがまだ無い間) は、案内の行の右に、見ている場所 (`.pitboard/` のある、または探し始めたディレクトリ。ホームは `~`。長ければ頭を `…` で切る) を薄く出す

### 思いつきを取り消す

- 思いつきの欄 (`j` で入った所) と `tab` の一覧で、行の上の `x`: その思いつきを取り消す (`retract`)。欄・一覧・報告の行の下・`✎` の数から消える。行き先の付いたものも取り消せる
- 下の行に「取り消しました (u で戻す)」。**次のキーが `u` なら戻す** (`unretract`、カーソルもその思いつきへ)。ほかのキーを押したら戻せない
- 取り消すとカーソルは次の件 (無ければ前の件) へ移る。移った件は、画面に出てから 0.4 秒たつまで `x` が効かない
- 一覧の案内は、行の上では `enter 開く  x 取り消す  m 書く  ? キー`、思いつきが無ければ `tab 報告へ  ? キー`
- AI への届き方 (`changes`): まだ届いていない思いつきを取り消したら、思いつきも取り消しも届けない (未送信にも数えない)。
  届いた思いつきなら `retract thought 9: <本文の頭>`。取り消しが届いたあとで戻したら `unretract thought 9: <本文の頭>`。届く前に戻したら何も届けない
- 取り消した思いつきへの `settle` はエラーにしない

## コマンド

    pitboard [view]          viewer
    pitboard path            そのセッションの report.md のパスを出す (無ければセッションのディレクトリを作る)
    pitboard changes         AI にまだ届けていない人の操作を 1 行ずつ出し、届けた位置を覚える (.pitboard/<session>/seen)
    pitboard settle N TEXT   思いつき N の行き先を書く
    pitboard check           report.md を確かめる (SPEC-format.md の「check が見ること」)。問題があれば行番号つきで出し、終了コード 1
    pitboard hook EVENT      Claude Code の hook から呼ぶ (下の「hook」)
    pitboard --skill         Claude Code の skill ファイル (SKILL.md) を stdout に出す
    pitboard -h              使い方の全文 (英語)。AI はこれを読んで使う: 始め方、報告の書き方、作法、changes の読み方、思いつきの行き先、hook、送る

`-s SESSION` を拾うのは、コマンドの直前か直後だけ (`pitboard -s X cmd …` と `pitboard cmd -s X …`)。TEXT の中の `-s` はそのまま文として残る。

`changes` の出力 (AI が読む。短く、文脈つきで)。括弧の中は押した時点の題。いまの題が違えば `(… → いまは: …)`、行が無ければ `(… → いまは無い)`:

    y hook (hook を入れるか決める)
    answer base = b (中身は Markdown、項目の区切りと付随情報は道具が持つ)
    thought 7 on hook (hook を入れるか決める): post-tool だけ入れたい
    thought 8: 経過は要らないかも
    hide: 板はセッションごと
    unhide: 板はセッションごと
    retract thought 9: 経過は要らないかも

`hide` は、人がその行をもう見なくてよいと判断した印。対応は要らない。報告を書き直すついでにその行を落としてよい (`-h` と skill にも書く)。

### hook

    pitboard hook prompt-submit   ユーザーがプロンプトを送ったとき (UserPromptSubmit)
    pitboard hook post-tool       ツール実行のあと (PostToolUse。AI の作業中に届ける)
    pitboard hook stop            AI が止まろうとしたとき (Stop)

- stdin に hook の JSON が来る。`session_id` と `cwd` を使う。`-s` `$PITBOARD_SESSION` と作業ディレクトリは見ない。stdin は 1 MiB までしか読まず、超えたら何もせず終了コード 0
- 板は `cwd` から親へさかのぼって探す (コマンドと同じ。AI が `cd` しても届く)。`session_id` は先頭一致ではなく完全一致
- やることは `changes` と同じ: まだ届けていない人の操作を出し、届けた位置を覚える
- **板が無いセッションでは何も出さず、何も作らず、終了コード 0** (`cwd` から上に `.pitboard/<session_id>/` が無い、stdin が JSON でない、`session_id` が無いか使えない文字、のどれでも)。hook は全セッションで走るので、使っていないセッションに一切影響しない
- 板があっても、読めない・書けないときは何も出さず終了コード 0 (毎回エラーを出すとセッションが使いづらくなる)。events.jsonl がまだ無ければ作らない
- 届けるものが無いときも何も出さず終了コード 0
- 文面は `pitboard (the person acted on the board):` の 1 行、`changes` の行、最後に `Settle each thought with "pitboard -s <session_id> settle N TEXT" once you know where it goes.`
  - `prompt-submit`: stdout にそのまま
  - `post-tool`: `{"hookSpecificOutput":{"hookEventName":"PostToolUse","additionalContext":"..."}}`
  - `stop`: `{"decision":"block","reason":"..."}` (止まらずに読ませる)。`stop_hook_active` が true のときは block しない。届けずに残す (同じ停止で 2 回止めない)。届けるものが `hide` / `unhide` だけのときも block しない (届けずに残し、次の機会に一緒に届ける)

### 組み込み skill

skill は薄くする (道具を更新しても skill が古くならないように)。repo の `skills/pitboard/SKILL.md` が skill そのもので、`pitboard --skill` はこれを埋め込んで (`//go:embed`) 出す。
中身は frontmatter (`name: pitboard`、英語の description) と、「`pitboard -h` を読んでから使う。書いてあるのは、いま入っている版の使い方」という数行だけ。
入れ方は `gh skill install qawatake/pitboard pitboard`、または `pitboard --skill > ~/.claude/skills/pitboard/SKILL.md`。

使い方は全部 `pitboard -h` に置く (1 つのコマンドで全文。分けない): 何のための道具か、始め方 (セッション id の取り方、`path`、viewer を横に開いてもらう)、報告の書き方、作法、`changes` の読み方、思いつきは必ず `settle` する、hook の設定例、送る (`s` で打ち込まれる文と、そのときにすること)。

`-h` に入れる作法 (AI 向け):
- 報告は読むものではなく拾い読みするもの。1 項目 1 行、補足は字下げした中身に
- 反応や思いつきを紐づけてほしい行には必ず `^id` を付ける
- id は別の行に使い回さない。物が変わったら新しい id を付ける
- 書き換えたら `pitboard check` を通す
- 人は板の上でまとめて答えてから送る。`pitboard:` で始まる行がチャットに来たら `pitboard changes` を読む (自分から頻繁に呼ぶ必要はない。送られたものしか出ない)。
  思いつきは急いで全部さばかなくてよいが、受け取ったものには `settle` で行き先を必ず書く (todo にした / 答えた / 控えた / 見送った)
- 問いと答え: 聞かれたこと (チャットでも思いつきでも) には、チャットで答えるだけでなく報告にも書く。「答え」のような節に 1 件 1 `Item` (題が問い、中身が答え)。
  人は読んだら `x` で隠す。`hide:` が届いたら、次に書き直すときにその `Item` を落とす。問いだった思いつきは「答えた (報告の「答え」に書いた)」で `settle` する
- チャットにしか無い決定・答え・頼みごとを残さない。報告を読めば状況が分かるようにする

## 作り

- Go、標準ライブラリだけ。`pitboard/go.mod` (module `pitboard`)。`sketch/` と親ディレクトリのファイルは変更しない (コピーして使う)
- 0.5 秒ごとに report.md と events.jsonl の変化を見て描き直す
- 人が指していない行に反応が付くことが絶対に起きないこと (id で追う。カーソルの行が画面の外にあるとき、「ページが変わりました」を出している間、人が一度も動かしていないカーソルでは、反応を受け付けない)
- SIGTERM / SIGINT / SIGHUP で止められたときも、端末を元に戻してから終わる (raw mode、代替画面、カーソル、ブラケットペースト)。終了コードは 128 + シグナル番号
- 外のエディタ (`ctrl+e`) を開いている間は SIGINT を無視する (エディタの中の ctrl+c で、エディタを閉じたあとに viewer が終わらない)。エディタから戻ったら元に戻す
- テスト: 報告の解析、events の追記と `changes` / `settle`、`check`、hook、行を隠す、思いつきの欄の単体テスト
- git は触らない。inbox への登録は不要
