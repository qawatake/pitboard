# FEAT20 の結果

vet / test / build は通る。git には触っていない。pty (スクラッチパッドの空のディレクトリ、幅 60) で 1 度見た: 今日の `22:11`、別の日の `11/20 09:05`、長い題の折り返し、コメントを置いたあとの `未送信  22:11`。

## 直した項目

- `Notice` に属性 `at` (`YYYY-MM-DD HH:MM`、ローカル時刻)。書式が違えば `check` のエラー (`at "…": write the local time as YYYY-MM-DD HH:MM (date '+%Y-%m-%d %H:%M')`)。`Notice` 以外に付ければ、ほかの知らない属性と同じエラー (`internal/report/parse.go`、`Node.At`)
- 題の行の右端に薄く出す。今日なら `21:46`、違う日なら `11/23 21:46`。右端の語と同じ扱いなので題はその幅を空けて折り返し、人の入力の状態はその左に並ぶ (`internal/viewer/rows.go` の `right`・`atWord`)
- `at` は隠す鍵 (`HideKey`)・反応の鍵 (`Sig`)・既読の鍵 (`viewKey`) に入れていない。`at` だけ変わっても隠したお知らせは出ない
- `-h`: 部品の表 (`Notice` の行)、例 (`at="2026-11-23 21:46"`)、作法 (必ず付ける、`date '+%Y-%m-%d %H:%M'` で取る、知らせ直すときは時刻も新しくする、`at` だけの変化では隠したものはまた出ない)
- 仕様書: SPEC-format.md の部品の表・例・描き方、SPEC.md のお知らせの節
- テスト: `TestNoticeParse` に書式の誤りと読めた時刻、`TestNoticeAt` (今日 / 別の日 / 折り返し / コメントの状態の並び / 時刻だけ変えても隠れたまま)

## 推測で決めた点

- 「今日」はいまの端末のローカル日付で判定。年が違っても `月/日 時:分` (年は出さない)。月と日は 0 を詰めない (`1/5 09:05`。時と分は 2 桁)
- 時刻が未来でも、そのまま出す (誤りにはしない)
- 秒付きや `T` 区切り (`2026-11-23T21:46`) はエラー。`at` の無い `Notice` はエラーにしない (依頼のとおり任意。`check` で警告も出さない)
- 隠した `Notice` を `H` で出しているときも時刻を出す
