# pitboard: 送るキーの整理、改行は shift+enter、開いた題と中身の差、思いつきの修正

仕様: `docs/spec/SPEC.md`。FEAT8 が終わってから取りかかること。終わったら仕様書・`-h`・`?` の一覧も合わせる。

## 1. 送るキーの整理

- 案内の行 (いちばん下) に `s 送る` を出す。未送信があるときだけ出し、`m 書く` の手前に置く。幅が狭いときも `s 送る` `m 書く` `? キー` は最後まで残す
- **エディタの `ctrl+s` (書いて送る) をやめる**。エディタの中では何もしないキーにする。送るのは、書き終えてから `s`
- 思いつきの欄の見出しの `s で送る` は消す (案内に出るので)

## 2. 改行は shift+enter (Claude Code に合わせる)

- エディタの改行は `shift+enter`。案内には `shift+enter 改行` と出す。`ctrl+j` と `alt+enter` は今までどおり効くが、案内には出さない
- 多くの端末は、何もしないと `shift+enter` と `enter` を同じバイトで送る。区別できるようにする:
  - viewer の起動時に、キーの曖昧さをなくす拡張を有効にし、終了時 (シグナルで終わるとき・外のエディタを起動する前も) に必ず戻す。
    候補は kitty keyboard protocol の `CSI > 1 u` (戻すのは `CSI < u`) と、xterm の modifyOtherKeys (`CSI > 4 ; 1 m` / `CSI > 4 ; 0 m`)。
    Ghostty・kitty・WezTerm・iTerm2・tmux の中で、どれが効いてどれが副作用を起こすかを調べて決める (調べた結果を報告に書く)
  - 有効にすると、ほかのキー (esc、ctrl+文字、alt+文字、矢印、tab、backspace) の届き方が変わることがある。**いま使っているキーが全部、有効にする前と同じに扱えること**を単体テストで守る (`CSI 27 u`、`CSI 106 ; 5 u` のような形も読めるように)
  - 拡張に対応していない端末では、今までどおり `ctrl+j` で改行できる。そのときは案内を `ctrl+j 改行` にする (拡張が効いたかどうかは、問い合わせ `CSI ? u` の返事で判断する。返事が無ければ非対応として扱う)

## 3. 開いた項目の題と中身の見分け

ユーザーの指摘: 中身をふつうの色にしたら、今度は題と中身の差がなくなって読みづらい。

- **開いている項目の題を太字にする** (閉じているときは今までどおり)。`Ask` と `Fold` の題も同じ
- 中身はふつうの色・ふつうの太さ。字下げは題より 4 桁 (いまより深ければそのまま)
- 中身の最後のあとに 1 行空ける (次の項目の題とくっつかないように)。閉じている項目の間は空けない

## 4. 思いつきを直す

ユーザーの要望: 書き途中のまま出してしまった思いつきを直したい。

- 思いつきの欄と `tab` の一覧で、行の上の `e`: その思いつきの文を入れた状態でエディタが開く。`enter` で直した文に置き換わる。`esc` でやめる (元のまま)
- 記録は追記だけ: `{"n":N,"t":"...","op":"edit","thought":9,"text":"直した文"}`。画面に出る文は、いちばん新しい `edit` のもの
- AI への届き方:
  - まだ届いていなかった (未送信、または送ったが未読) 思いつきを直したら、AI には直した文だけが `thought 9: …` として届く (直したこと自体は届けない)
  - すでに届いた思いつきを直したら、`edit thought 9: <直した文>` と届ける (未送信の数にも数える。送るまで届かない)。行き先 (`settle`) が付いていたら、状態は「受け取った」に戻す (AI が直した文を見て行き先を書き直す)
- 直した文が空なら、何もしない (取り消すのは `x`)
- 案内: 欄・一覧の行の上では `enter 開く  e 直す  x 取り消す`
- `e` は viewer のキーなので、`Option` の `key` に使えないキーに足す。**既存の報告で `key="e"` が使われているので注意**:
  `Option` のキーは `Ask` が開いているときにカーソルがその `Ask` の上にある場合だけ効く。`e` (直す) は思いつきの欄・一覧の行でだけ効く。
  場面が重ならないので、`e` は `Option` の `key` に使ってよいままにする (使えないキーの一覧には足さない)
- `-h` の `changes` の説明に `edit thought N` を足す
- 単体テスト: 届く前 / 届いたあとの修正と `changes`、行き先が付いたあとの修正、空の文
