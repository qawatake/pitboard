# pitboard: 端末に依存しない「送る」 (`pitboard wait`)

仕様: `docs/spec/SPEC.md`。FEAT6 が終わってから取りかかること。終わったら仕様書・`-h`・README・skill も合わせる。

## なぜ

いまの「送る」は、AI のいる端末へ文を打ち込む (herdr、または `PITBOARD_SEND`)。端末の道具に依存していて、herdr が無いと設定が要る。
端末に依存しない方法: **AI のほうが待つ**。Claude Code などのエージェントは、バックグラウンドで動かしたコマンドが終わると起こされる。
AI が止まる前に「人が送るまで終わらないコマンド」をバックグラウンドで動かしておけば、人が `s` を押した瞬間にそのコマンドが終わり、AI が起きる。

## 作るもの

    pitboard -s SESSION wait [--timeout DURATION]

- まだ届けていない `send` があれば、すぐに `changes` と同じ出力をして終わる (届けた位置も進める)
- 無ければ、`send` が追記されるまで待つ (0.3 秒ごとに events.jsonl の大きさと更新時刻を見る。変わったときだけ読む)。追記されたら、`changes` と同じ出力をして終了コード 0
- `--timeout` (既定は無し = 待ち続ける。例 `30m`) を過ぎたら、何も出さず終了コード 0
- SIGINT / SIGTERM で静かに終わる (何も出さない、終了コード 0)
- 待っている間は、`.pitboard/<session>/waiting` に自分の pid を書く。終わるときに消す。古い pid (プロセスがもういない) は無いものとして扱う
- 同じセッションで 2 つめの `wait` が起動したら、古いほうに任せて、新しいほうは「already waiting (pid N)」と出して終了コード 0 で終わる

## viewer 側

- `s` / `ctrl+s` の送り方の順を変える: `send` を追記したあと、
  1. **待っている `wait` がいれば、何もしない** (それが起こす)。知らせは「送りました」
  2. いなければ、今までどおり `PITBOARD_SEND` → herdr
  3. どれも無ければ、「送る印は付けました。AI が待っていないので、チャットで一言伝えてください」
- 待っている `wait` がいるかどうかを、いちばん上の行の右端に薄く出す: いるとき `AI 待機中`。いないときは何も出さない
  (人は、`s` を押せば届く状態かどうかを、押す前に知れる)

## `-h` と skill

- 作法に足す: 「自分の番を終える前に、`pitboard -s SESSION wait` をバックグラウンドで動かしておく (Claude Code なら Bash の run_in_background)。
  人が板から送ると、このコマンドが送られたものを出して終わり、あなたは起こされる。起きたら対応し、また止まる前に `wait` を動かす」
- hook・herdr・`PITBOARD_SEND` は「`wait` を使えない場合の別の手段」として残す。順番は wait → hook → 端末への打ち込み

## テスト

- 単体テスト: すでに `send` があるとき即座に出る / 待っていて `send` が来たら出る / timeout / 2 つめの `wait` / 古い pid
- pty 越し: viewer で `s` を押すと、別のシェルで待たせた `wait` が終わって内容を出すこと。`AI 待機中` の表示が出て、終わると消えること
