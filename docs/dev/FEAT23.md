# FEAT23: 返事の行に、人の質問を引用として出す (`re`)

仕様は `docs/spec/SPEC.md` と `pitboard -h`。この依頼だけで完結する。

## なぜ

ユーザーの言葉: 「こういう私がおこなった質問には > とかをつけるなどして、あなたが私のコメントを引用していることが分かるようにしてもよさそうですね」

いまは、AI が人のコメントへの返事を書くとき、`Item` の題に質問を言い直して書き、中身に答えを書く。題が「人の言葉」なのか「AI の言葉」なのかが見分けられない。言い直しで意味がずれることもある。

## 何を

- `Item` に属性 `re="N"` (N はコメントの番号。`changes` が `thought N` と出す番号) を足す。値は数字だけ。数字でなければ `check` のエラー
- 描き方: その `Item` の題の行の**上**に、そのコメントの文を引用として出す。行頭に薄い `>`、文も薄く。字下げは題の 1 文字目に揃える。長ければ折り返し、3 行を超えたら 3 行目を `…` で終える。画像の印 (`[Image #1]`) はそのまま文として出す
- 引用の行はカーソルの止まる行ではない (その `Item` の一部)。カーソルの `>` (左端の列) とは列が違うので、見分けがつくこと。引用の `>` は題の列に置く
- その番号のコメントが無い (取り消された、番号違い) ときは、引用を出さない。落ちない
- 題は AI が書く。`re` があるときの題は「答えの結論を 1 文で」と `-h` の作法に書く (質問は道具が引用で見せるので、言い直さない)。中身に詳しい答え
- `-h` の「勧める構成」の 3 (あなたへ) の、返事の書き方を合わせる: `<Item id="a-…" re="N" look="y">結論を 1 文で` + 中身
- `re` の違いは、隠す鍵・緑の印の判定に入れる (別の質問への返事は別の行)
- コメントの側 (欄・一覧・行の下に開かれたコメント) は変えない

- 仕様書に反映。git は触らない
