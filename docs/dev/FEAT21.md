# FEAT21: 節へ飛ぶ (`g`)、画面より高い中身を読めるようにする、勧める構成を直す

仕様は `docs/spec/SPEC.md` と `pitboard -h`。この依頼だけで完結する。

## 1. `g` で節へ飛ぶ

ユーザーの言葉: 「gを押すとgotoモードになり、するとpitboardの各セクションにアルファベットの番号が付き、それを押すとそこにカーソルが移動する機能とか良くない？？」

- `g` で「飛ぶ」状態に入る。画面に見えているかどうかによらず、報告の上から順に、飛び先に `a` `b` `c` … を振る。飛び先: 固定の `Notice` (それぞれ)、`Section` (それぞれ)、最上位の `Fold` (それぞれ。`Section` の中の `Fold` は入れない)
- 見せ方: いま画面にある飛び先には、見出しの行頭 (カーソルの列) に黄で字を出す。加えて、いちばん下の案内の行を、飛び先の一覧に置き換える (`a あなたへ  b 進行中  d 決まったこと  esc やめる`。入りきらなければ折り返す、それでも入らなければ題を縮める)。画面の外の飛び先もこれで分かる
- 字を押すと: その節の最初の止まる行にカーソルを移し、節の見出しが画面のいちばん上 (固定の `Notice` の下) に来るようにスクロールする。`Fold` なら `Fold` の行へ (開かない)。`Notice` ならその `Notice` へ。止まる行の無い節は、見出しが見える所までスクロールするだけ
- 飛んだあとは、viewer が動かしたカーソルなので、今までの守り (0.4 秒は反応を受け付けない) が効く
- `esc`、`g`、振られていない字: 何もせず抜ける
- 字は `a`〜`z`。26 を超える分には振らない
- `g` は viewer のキーになるので、`Option` に使えないキーに足す (`ViewerKeys`)
- 案内の行に `g 飛ぶ` を足す (狭いとき落とす順は `space` の次)。`?` の一覧にも
- コメントの欄・一覧・エディタ・`?` の中では効かない

## 2. 画面より高い中身を、`j` / `k` で読めるようにする

ユーザーの言葉: 「折りたたみ内部に長文があるときにそのなかもカーソルで移動したくなるような気もする」

いまは、開いた中身 (や開いた `Fold` の中の文) が画面より高いと、`j` は次の止まる行へ飛んでしまい、途中が読めない。スクロールだけのキーも無い。

- 中身の行は、これまでどおりカーソルの止まる行にはしない (止まる行は、反応できる物だけ)
- `j`: 次の止まる行が画面の外にあり、いまの行との間に、まだ画面に出ていない行があるとき、カーソルは動かさず、画面を進める (半画面ずつ。最後は、次の止まる行が画面に入る所まで)。間の行が全部見えたら、次の `j` で次の止まる行へ移る
- `k` も逆向きに同じ
- カーソルの行が画面の外に出てもよい (その間、カーソルの `>` は見えない。右上か下の行に、薄く `↑ カーソルは上` のように出す)。この状態で反応のキー (`y` `n` 選択肢 `x` `r` `c`) を押したら、まずカーソルの行が見える所へ戻し、反応は受け付けない (見ていない行に反応が付かない守り)
- `space` や `g` で飛んだら、ふつうの位置に戻る
- 報告の終わりを過ぎてスクロールする今の動き (`pv.top++`) とつながること

## 3. 勧める構成を直す (`-h` の "A layout to start from")

ユーザーの判断: 「あなたへ」と「答え」は 1 つの節にまとめる。「場所」「済んだこと」は既定から外す。

- 上から: (1) 題と、いまの様子 1〜2 文 (2) お知らせ (あるときだけ) (3) 「あなたへ」: 人が答える・動くもの (`Ask`、`ask="y"`、`wait="you"`) を上、人の質問への返事 (`look="y"`。題が質問、中身が答え) を下 (4) 「進行中」: いま動いているものと次 (5) 「決まったこと」(`Fold`): 理由つきで 1 行ずつ
- 作法: 済んだ行は「進行中」から消す (履歴は git にある。溜めない)。リンクは、それが要る行の中身に書くか、その行のすぐ下に `Link` で置く (リンクだけを集めた節は作らない)。問いに答えが来たら、その問いを消し、決まった内容を「決まったこと」に 1 行で残す
- 仕様書・README・skill に同じ構成の記述があれば合わせる

## 4. 折りたたみの中身を、はっきり字下げする

ユーザーの言葉 (画面の写真つき): 「見本の下にあるのにインデントが効いておらず構造が読みづらい気がする。特に、書き出すCSVの行」

いまは、開いた `Fold` の中の行 (`Item` `Ask` `Link`、文、箇条) が、`Fold` の題とほぼ同じ位置 (1 桁ずれるだけ) に出る。どこまでが折りたたみの中かが分からない。

- 開いた `Fold` の中の物は、どれも `Fold` の題の 1 文字目からさらに 2 桁、字下げする。中の行の記号 (`?` `▸` `→` `·` `✓`) が、`Fold` の題の 1 文字目より 2 桁右に来る。中の文 (段落・小見出し・箇条) は、中の `Item` の題と同じ列に揃える
- `Fold` の中の `Fold` は、さらに同じだけ下げる
- カーソルの `>` と ● (黄・緑) の列は左端に固定のまま
- `Item` を開いた中身の字下げ (題の 1 文字目に揃える) は今までどおり。`Fold` の中の `Item` でも、その `Item` の題に揃える
- 折り返しの幅は字下げの分だけ狭くなる。幅 40 でも崩れないこと
