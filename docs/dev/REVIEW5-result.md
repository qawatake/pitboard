# REVIEW5 の結果

重い問題は見つからなかった。送る文に人の書いた内容は混ざらず、herdr 経由はシェルを通らない。IME のカーソル、問いの開閉、案内、hook は仕様どおり。
問題は 3 件で、どれも軽い: (A) 送っている最中 (最大 5 秒) に押したキーが後から効いて、結果の表示を消してしまう。(B) 送れなかったときなどの長い文で、下の行が 2〜4 行に広がる。(C) 幅が狭いとき、エディタの案内から `esc やめる` が消える。
herdr 経由で実際に送る動きは、pty では確かめていない (代役の `herdr` を PATH に置く実行が権限確認で拒まれた)。コードと単体テストで確かめた。

確かめた環境: `go vet` / `go test` / `go build` は通った。viewer はスクラッチパッドの空のディレクトリで、pty 越しに動かした (自作の小さな端末エミュレータで画面をテキストにした)。幅は 90 / 50 / 40 / 33 / 24。送り先は `PITBOARD_SEND` の代役にし、`HERDR_ENV` は 0 にした。

## 問題 (重い順)

### A. 送っている最中に押したキーが、終わったあとに効く。結果の表示も消える (軽)

送る処理は viewer を止めて行う (最大 5 秒)。その間は画面が変わらず、「送っています」のような表示も出ない。止まっている間に押したキーは溜まっていて、送り終わってから順に効く。そのため「送れませんでした: … 打ち切りました」が出た直後に、次のキーで消えてしまう。

再現:
1. `PITBOARD_SEND='sleep 10'` で viewer を開き、未送信を 1 件以上にしておく
2. `s` を押し、0.2 秒以内に `j` を押す
3. 6 秒待つ → カーソルが 1 行下に動いていて、下の行は案内に戻っている。「打ち切りました」は一度も読めない (`j` を押さなければ出る)

溜まっていた `y` などは、人が見ていた画面に対して押したものなので、違う行に反応が付くことはない。
ただし、何も表示されないまま 5 秒待たされる、失敗しても気づけない、の 2 点は使いにくい。

### B. 長い文で下の行が複数行に広がる (軽)

`say` は文を折り返して出す (この作りは前からある)。今回足した文は長いので、ふつうの幅でも折り返しが起きる。
そのぶん、思いつきの欄の件数が減る。仕様は「いちばん下の案内は常に 1 行」としている。

再現:
- 幅 50、`HERDR_ENV=0`、`PITBOARD_SEND` なしで `s` → 「送り先がありません (herdr の中で / 開くか、PITBOARD_SEND を設定)」の 2 行になる
- 幅 50、`PITBOARD_SEND` を「長い文を stderr に出して `exit 2`」にして `s` → 「送れませんでした: …」が 4 行になり、思いつきの欄は 1 件しか出なくなる。stderr の先頭行は長さが切られていない
- 幅 40 で `x` → 「隠しました。H で隠した / 行を表示」の 2 行 (これは前から)

### C. 幅が狭いと、エディタの案内から `esc やめる` が消える (軽)

エディタの案内は、高さに余裕があれば折り返して 2 行になる (幅 50 で `… ctrl+j 改行` / `ctrl+e エディタ  esc やめる`)。
高さが足りないと 1 行に切られ、`ctrl+s 書いて送る  ct…` で終わる。このとき、やめ方 (`esc`) が見えなくなる。

再現: 幅 40、高さ 12 で `m` を押し、`ctrl+j` で 10 行ほど書く → 案内の行が `enter 書く  ctrl+s 書いて送る  ct…`。

### 気づいたこと (問題ではない)

- `-h` に、`Ask` が閉じた状態で始まり、閉じている間は問いの 1 行しか見えないことが書かれていない。AI が問いの行だけで意味が通るように書くには、知っておいたほうがよい
- `-h` の `changes` の例に、改行を含む思いつきの出力 (2 行目以降は字下げされる) が無い
- `PITBOARD_SEND` の例が `-h` に無い。`$PITBOARD_MESSAGE` を引用符で囲まずに使うと、語に分かれてしまう。例を 1 つ載せるとよい

## 問題なかったこと

- vet / test / build
- `s`: 送るものが無いとき「送るものはありません」(代役は呼ばれない)
- `s`: 送れたとき「AI に送りました」。代役には `PITBOARD_SESSION` と `PITBOARD_MESSAGE` が渡り、文は仕様どおり。数も合う
- `s` を 2 回押しても未送信の数は減らない。`seen` も進まない
- `changes` のあと 0.5 秒以内に右上の `● 未送信 N` が消え、思いつきは「受け取った」になる
- `-s` に先頭一致の id を渡したとき、送る文のセッションは完全な id になる
- `ctrl+s`: 書いて送る。送れなかったときも思いつきは記録される。空のエディタで押すと閉じるだけで、未送信が 0 なら「送るものはありません」
- `tab` の一覧でも `s` が効き、右上に印が出る
- 送り先が無いとき (`HERDR_ENV` が 1 でなく、`PITBOARD_SEND` が無いか空) の文
- 失敗したとき、stderr の先頭 1 行だけが添えられる
- 5 秒で打ち切る (`sleep 10`。バックグラウンドに子が残る `(sleep 20 &); sleep 10` でも 5 秒で戻る)
- 打ち込む文に内容が混ざらない: `"; rm -rf ~; " $(touch PWNED) \`id\`` に改行を足した思いつきを `ctrl+s` で送っても、`PITBOARD_MESSAGE` は決まった文だけ。`PWNED` も作られない
- herdr 経由 (コードを読んだ): `exec.CommandContext("herdr", "agent", "prompt", pane, msg)` で、引数として渡していてシェルを通らない。文に入るのはセッション id (`[A-Za-z0-9_-]+` で確かめ済み) と数だけ。実物の `herdr agent list` の JSON (`result.agents[].agent_session.value`、`pane_id`) と、コードが読む形が一致する。照合は完全一致。単体テスト (`TestSendThroughHerdr` など) は代役で通る
- 右上の印: 題・中身の行と重なるとき、文のほうが `…` で切られる (幅 90 / 50 / 33 / 24、全角)。スクロールしても画面のいちばん上の行に出続ける。書きかけは数えない
- 問い: 閉じているときに選択肢のキーを押すと開くだけで、記録されない (`changes` は空)
- 問い: 開いているときにキーを押すと記録され、印が付く
- 問い: 答えて閉じると、右端に `b プロジェク…` (幅 90)。幅 50 でも出る
- 問い: report.md を書き換えて読み直しても、開いた状態・閉じた状態が保たれる
- 問いの案内: 閉じているとき `enter 開く  c 行に書く  x 隠す`、開いているとき `a b 答える  enter 閉じる  c 行に書く`
- IME のカーソル: 描画の 1 回の書き込みが `\x1b[行;桁H\x1b[?25h` で終わる。半角、全角、ちょうど幅いっぱい (全角 22 字 / 半角 44 字、幅 50)、入りきらない全角で折り返したとき、改行の直後、改行のあと、`c` で書くとき、高さ 12 で行が流れたとき、のどれでも位置が合う。0.5 秒ごとの描き直しでも同じ位置で終わる
- IME のカーソル: `esc` で閉じたら `\x1b[?25l`。`tab` / `?` の画面でも隠れたまま。`q` で終わるとき `\x1b[?25h\x1b[?1049l`。SIGTERM で終わるとき (エディタを開いたまま) もカーソルを見せて戻し、終了コードは 143。`ctrl+e` (代役のエディタ) から戻ったあとも隠れている
- 案内: `m 書く` と `? キー` が、問い・項目・済んだ項目・リンク・ただの行・`Fold` のどの行でも、幅 90 / 50 / 33 / 24 で出る。落ちる順は x → enter → n → y → c。`tab` の一覧でも出る
- `pitboard --skill` の出力は `skills/pitboard/SKILL.md` と同じ。`gh skill install` コマンドがあることも確かめた (入れてはいない)
- `-h` に書いてあるコマンド (`path` / `changes` / `settle` / `check` / `-s` を後ろに書く形 / 先頭一致 / 無いセッション) を打った。動きは説明どおり
- `-h` だけを読んで報告を書き始められる: 始め方、書式、部品、作法、`changes` の読み方、`settle`、hook、送る、がそろっている (足すとよい点は上の「気づいたこと」)
- 反応 (`y` が右端に出る、`changes` で届く)
- 思いつきの状態 (未読 → 受け取った)
- 行を隠す (`x`、`H` で `⌀`、`隠した行 N (表示中)`)
- hook: 板の無いセッションでは 3 つとも何も出さず、終了コード 0、ファイルも作らない。JSON でないときも同じ。`session_id` の先頭一致では届けない。`stop_hook_active` のときは block しない。`post-tool` と `stop` の出力の形
