## 1. 言葉づかい

`docs/dev/REVIEW6-result.md` の「1. 画面の言葉づかい」(1-a の問題、1-d の用語の表、1-e の注意) のとおりに、画面の語を直す。ユーザーが決めたこと:

- 「思いつき」は **コメント** と呼ぶ (画面の語だけ。記録の `op: "thought"`、コマンド `settle`、AI 向けの英語の出力 `thought N` は変えない)
- 状態の 4 語は **未送信 → 送信済 → 既読 → 対応済** (送り仮名なし。右上の `送信済 N` もこれに合わせる)
- それ以外は用語の表の提案どおり。表に「そのまま」とある語は変えない
- 1-a の a7・a8 (事実と違う文) は必ず直す。a13 (AI 向けの出力に日本語が混ざる) も直す: `→ now: …` / `→ now gone`

用語の表と食い違う語が残っていないか、最後に画面の文字列を全部拾って確かめる。

## 2. 色に意味を持たせる

ユーザーの指摘: 作業中も順番待ちも未送信も、全部同じ黄色。

| 色 | 意味 | 使う所 |
|---|---|---|
| 黄 | **人の手が要る** | 反応待ちの `●`、未送信 (右上の `● 未送信 N`、行の右端の `未送信`)、`Item` の `status` のうち `wait="you"` が付いたもの |
| 緑 | **動いている・新しい** | 新着の `●`、`state="doing"` の `Item` の `status` |
| 薄い色 | 待っているだけ・済んだ | それ以外の `status` (順番待ち、保留など)、`送信済` `既読` `対応済`、済んだ項目 |

- `Item` に属性 `wait` を足す。値は `you` だけ。「人が何かしないと進まない」印。`status` の語は AI が自由に書くので、色は語ではなく属性で決める
  (これまでの「`status` が `あなた待ち` で始まれば黄」の前方一致はやめる)
- `wait="you"` の `Item` は「反応待ち」には数えない (反応待ちは `Ask` と `ask="y"` だけ)。ただし `space` で飛ぶ先には含める (反応待ち → `wait="you"` → 新着 の順)
- `check`: `wait` の値は `you` だけ。`state="done"` に `wait` があればエラー

## 3. 行の右端に、その行への自分の入力の状態を出す

ユーザーの要望: コメントした行には、件数 (`✎2`) ではなく、**いちばん新しいコメントがいまどうなっているか**が出てほしい。`y` `n` や答えも同じ扱いにする。

- 行の右端 (AI が書いた `status` の左) に、その行への人の入力 (コメント・`y` `n`・答え) のうち**いちばん新しいもの**の状態を 1 語で出す:
  `未送信` (黄) → `送信済` → `既読` → (コメントだけ) `対応中` / `保留` / `対応済` (どれも薄く)
- `y` `n`・答えは、これまでどおり押したキーも出す: `y 未送信` → `y 送信済` → `y 既読`。AI が行を書き換えたら消える (今までどおり)
- `✎N` は出さない。コメントが 2 件以上あるときだけ、状態の左に薄く件数を出す (`2 既読`)
- コメントの状態を AI が細かく言えるようにする。`settle` に状態を足す:
  `pitboard -s S settle N [--doing | --hold | --done] TEXT` (省いたら `--done`)。
  画面では `対応中` / `保留` / `対応済`。`--doing` `--hold` のあとで、もう一度 `settle` して `--done` にできる (いちばん新しいものが有効)
  - 複数まとめる形 (FEAT10) では、番号の前に状態を書ける: `settle --doing 50 "…" --done 51 "…"`
- コメントの欄と一覧の状態の語も同じ 6 語にする

## 4. `-h` の作法に足す

- コメントを受け取ったら、すぐ終わらないものは `settle N --doing` か `--hold` で状態を知らせ、終わったら `--done` で結果を書く
- 「答え」の節の項目は、人が読んだ (`hide`) ものだけでなく、**人が返事をして解決したと AI が判断したもの**も、AI が報告から落としてよい
- 人の手が要る項目には `wait="you"` を付ける (`status` の語だけでは色が付かない)
- `pitboard wait` は、作業を始める前に動かしておいてよい (作業の途中で人が送ると、その時点で届く)。届いたら、また動かす
