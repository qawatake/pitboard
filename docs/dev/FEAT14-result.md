# FEAT14 結果

## 直した項目

- 1. viewer の「板」を全部置き換えた: `.pitboard/` が無いとき「このディレクトリと親に pitboard の置き場 (.pitboard/) がありません。…」、セッションが無いとき「pitboard にはまだ報告がありません。…」、`-s` のセッションが無いとき「セッション <id> の報告はまだありません」、`?` の一覧と外のエディタの説明の行「pitboard に置く」
- 1. `README.md` `docs/spec/SPEC.md` `docs/spec/SPEC-format.md` の「板」を置き換え (文脈で pitboard / 置き場 / viewer / セッション / 報告に書き分け)。例の文 (「板はセッションごと」) も「報告はセッションごと」などに
- 1. `TestNoOldWords` に「板」を足し、報告の無い 3 つの画面と `msg*` の定数も見るようにした
- 2. `changes` `settle` (失敗時も) `wait` (届いた・タイムアウト) と hook (出力があるとき) の最後に `report.md has N problem(s). Run: pitboard -s <短い id> check`。`wait` は始めに標準エラーにも 1 度。報告が無い・読めない (ディレクトリ、解析の失敗、panic) ときは何も足さない (`lint.go`)
- 2. `-h` の作法に「report.md を書き換えたら check。ほかのコマンドも誤りがあれば知らせる」を追記
- 3. `-h` の作法に「pitboard から届いたものへの返事は報告に、チャットは 1〜2 行」「チャットで直接聞かれたらチャットで答える (残すべきなら報告にも)」「人の判断・確認が要ることは報告の上のほうに ask / wait="you"、チャットだけにしない」を追加。既存の「問いにはチャットでも答える」の文はこれと矛盾するので「ボードで聞かれたら報告で答える」に直した
- 単体テスト `feat14_test.go` (changes / settle / wait 3 通り / hook / 無い・読めない報告)。SPEC.md に反映
- 実行で確認 (スクラッチパッドの空ディレクトリ): viewer の 3 つの空画面に新しい文が出て「板」が無い、`changes` `settle` (exit 1 のまま) `wait --timeout` (stdout と stderr) に知らせが出る、直すと出ない

## 推測で決めた点

- hook は、届けるものがある (もともと出力がある) ときだけ末尾に足す。届けるものが無いときに知らせだけを出すことはしない (post-tool で毎回出る、stop を止める、などで振る舞いが大きく変わるため)
- `wait` が SIGINT/SIGTERM で終わるとき、`already waiting` で終わるときは足さない
- `settle` が失敗しても (標準出力に) 足す。終了コードは変えていない
- 解析そのものが失敗した報告 (`parseReport` が err) は「読めない」とみなして何も足さない
- `skills/pitboard/SKILL.md` の description にある `"板"` は、ユーザーがそう呼んだときに skill を起動する語なので残した (画面の文字列ではない)
- 「板はまだありません」(セッションが無い) は、人から見ると「まだ報告が無い」なので「pitboard にはまだ報告がありません」と書き直した

## 未確認の点

- hook に知らせが足されるのは単体テストでのみ確認 (実行では、届けるものが無い場合に何も出ないことだけ確認)
- 新しい作法の文で AI の振る舞いが実際に変わるかは未確認
