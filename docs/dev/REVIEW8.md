## 見ること

a. **古い語**: 「板」(pitboard と呼ぶと決まった)、「思いつき」(コメント)、「行き先」「受け取った」「済」「未読」(状態は 未送信 → 送信済 → 既読 → 対応中 / 保留 → 対応済)、「新着」(緑の ● は「未読」ではなく AI が付ける `look="y"` の印になった。いまの呼び名が文書ごとに揃っているか)。どの文書の何行目かを全部挙げる
b. **実装と違う記述**: キーの一覧、キーの意味 (`space` `r` `u` `A` `x` `e` `s` `H` など)、属性の表 (`ask` `wait` `look`)、`Option` に使えないキーの一覧、コマンドと引数 (`settle` の複数の形、`wait`)、送る順 (wait → PITBOARD_SEND → herdr)、緑の ● が消える条件 (`r` と反応だけ)。コードが正
c. **文書どうしの食い違い**: 同じことを 2 か所で違うふうに言っている所
d. **重複**: 同じ説明が 3 か所以上にあり、直すたびに揃える手間がかかっている所。どれを正にして、ほかをどう短くするかの提案
e. **抜け**: 実装にあるのに、どの文書にも (`-h` にも) 無いもの。逆に、消えた機能の説明が残っている所
f. **読み手に合っているか**: README は人 (初めて見る人) 向け、`-h` は AI 向け、SPEC は作る人向け。読み手の違う内容が混ざっている所
g. 気づいた別件: `u` が viewer のキーなのに `Option key="u"` が `check` を通る (実装者の報告)。ほかにも同じ種類の漏れが無いか、viewer のキーの一覧と `check` の一覧を突き合わせる
