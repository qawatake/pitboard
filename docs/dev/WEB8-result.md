# WEB8 の結果

`scripts/check.sh` 通過 (vet・test・ギャラリー 205 枚・生きたページとの比較 28 件)。git には触っていない。実際の再起動は playwright-cli で確かめた (作業用の状態ディレクトリ、`--port 0` で得たポートに固定)。ブックマークの URL (`?t=` なし) は cookie だけで開けた。`--stop` してから起動し直すと、同じ URL が出て、タブは約 1 秒で帯が消え、開いていた欄と書きかけ「下書きです」が残った。`--rotate` のあとは帯が出たままになった
- 鍵: 状態ディレクトリの `token` (0600、`WritePrivate`、256 ビット)。一度作ったら使い続け、`--stop` やアイドルでの停止では消さない。リンク・他人のもの・0600 より緩い・形が違うものは使わずに作り直す。`serve --rotate` は鍵を作り直し、サーバーが動いていれば同じポートで起動し直す (動いていなければ鍵を変えたと言うだけ)
- cookie: Max-Age 30 日、HttpOnly、SameSite=Strict。ページ (`/` と `/s/<id>/`) とその SSE を cookie で開くたびに延びる
- タブが戻ったとき: オフライン中の再試行を 3 秒から 2 秒にした。`/api/page` が返ってきたら、閉じている SSE を待たずにつなぎ直す。ポートが変わったことはページには分からないので、帯の文は今のまま
- 開くかどうか: サーバーの起動から 3 秒 (`web.OpenWait`) の間に、そのボードの SSE がつながるか (鍵付きの `/api/watching`) を見て、つながればブラウザを開かない。`--open` なら必ず開き、`--no-open` なら開かない (2 つ同時はエラー)。URL は今までどおりいつも `?t=` 付きで出す (`?t=` はサーバーが 303 で外す)
- 安全面で変わること: 鍵がディスクに長く残る (本人だけが読める 0600、0700 のディレクトリ)。cookie がブラウザのプロファイルに 30 日残る。127.0.0.1 だけで待ち受け、Host・Origin・CSP の検査は変えていないので、届くのは同じマシンの本人だけ。漏れたと思ったら `--rotate` で無効にできる
- テスト: token のパーミッションと不正なファイル、再起動で古い cookie が通ること、rotate で古い cookie が 403 になること、cookie の Max-Age と延長、`/api/watching`、開く・開かないの判断。更新した文書: `-h`・`pitboard -h`・README・SPEC
