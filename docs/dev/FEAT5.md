# pitboard: 「まとめて送る」を本物にする、送り先の探し方と文言、開いた中身の色、IME が入ったままのキー

仕様: `docs/spec/SPEC.md`、`docs/spec/SPEC-format.md`。終わったら仕様書・`-h`・`?` の一覧・skill も合わせる。
FEAT4 が終わってから取りかかること。

## 1. 人が「送る」まで、AI には届かない

ユーザーの考え: 板の上でいろいろ返答して (y / n、答え、思いつき、隠す)、**最後にまとめて送る**。書くたびに届くのではない。
いまは `changes` を呼べば、書きかけの途中のものまで全部届いてしまう。送った時点を記録して、そこまでしか届けないようにする。

- `s` (と `ctrl+s`) は、まず events.jsonl に `{"n":N,"t":"...","op":"send"}` を追記し、それから AI を起こす (今の送る処理)
- `changes` と hook が届けるのは、**いちばん新しい `send` より前の操作だけ**。それより後の操作は、次の `send` まで届けない
- 起こす処理 (herdr / `PITBOARD_SEND`) が失敗しても、`send` の記録は残す (次に AI が `changes` を呼べば届く)。
  そのときの知らせは「送る印は付けました。AI を起こせなかったので、チャットで一言伝えてください」+ 理由 (下の 2)
- 送るものが無い (`send` より後に操作が無い) ときは、`send` を追記しない
- 状態の語を分ける:
  - **未送信**: `send` より後の操作。右上の `● 未送信 N` はこれを数える (`s` を押すと 0 になる)
  - **未読**: 送ったが、AI がまだ `changes` を呼んでいない。右上に `送信済み N` と薄く出す (AI が読むと消える)
  - 思いつきの状態は 4 つになる: `未送信` (黄) → `未読` (薄く) → `受け取った` (薄く) → `済` (薄く)
- 取り消し (FEAT4 の 2) との関係: 未送信の思いつきを取り消したら、送っても届かない。送ったあと (未読でも) に取り消したら `retract` が次の `send` で届く
- 打ち込む文の N は、その `send` で送る件数
- `-h` と skill の「人の操作の受け取り方」を書き直す: 人は板の上でまとめて答えてから送る。`pitboard:` で始まる行がチャットに来たら `changes` を呼ぶ。
  自分から頻繁に `changes` を呼ぶ必要はない (呼んでも、送られたものしか出ない)
- 単体テスト: `send` の前後で `changes` が出すもの、2 回の `send`、失敗しても印が残ること、数え方

## 2. 送り先の探し方と、見つからないときの文言

起きたこと: viewer を herdr の外 (同じウィンドウの別の Ghostty の分割) で動かしていて、`s` が「送り先がありません」で終わった。
AI のほうは herdr の中にいて、`herdr agent list` にはセッション id が出ていた。案内に `s で送る` と出ているのに送れず、どうすればよいかも書かれていなかった。

- herdr を使うかどうかを `HERDR_ENV` で決めない。**`herdr` が PATH にあれば、`herdr agent list` を実行して、このセッション id の agent を探す** (viewer が herdr の外にいても)
- 見つからないときの知らせは、理由と直し方を書く。1 行に入らなければ 2 行使ってよい (FEAT3 の「1 行に収める」の例外):
  - `herdr` が無く `PITBOARD_SEND` も無い: 「AI を起こす方法がありません。PITBOARD_SEND を設定してください (pitboard -h の "Send")」
  - `herdr` はあるが、このセッションの agent がいない: 「herdr にこのセッション (38d12f95) の AI がいません。AI を herdr の中で動かすか、PITBOARD_SEND を設定してください」
  - 実行に失敗: 「送れませんでした: <理由>」
- 思いつきの欄の見出しの `s で送る` は、未送信があるときだけ出す (今までどおり)

## 3. 開いた中身の文字が暗くて読みづらい

項目を開いたときの中身 (字下げされた文) を、薄い色ではなくふつうの色にする。薄くするのは、済んだ項目・隠した行・時刻・パスなどの補助情報だけ。
`note` (状態の理由) と、行の下の思いつきは、ふつうの色にして、頭の語 (「理由:」「行き先:」など) だけを薄くする。

## 4. IME が入ったままでも動かせるようにする

日本語入力のままだと、`j` `k` などの文字キーは変換待ちになって届かない (端末のプログラムから IME を切り替えることはできない)。
IME を通らないキーで、基本の操作ができるようにする。

- 報告・欄・一覧の移動に、`↑` `↓` と `ctrl+p` `ctrl+n` を足す (`k` `j` と同じ)。`pgup` `pgdn` は半画面
- 全角の英数・記号 (U+FF01〜FF5E) と全角空白は、エディタの外では半角に直してからキーとして扱う (`ｊ` → `j`、`ｙ` → `y`)。エディタの中ではそのまま文字
- 案内と `?` の一覧に `↑↓` を書く (`j k` と並べて)
- 「人が動かした」とみなすキーに `↑` `↓` `ctrl+p` `ctrl+n` も入れる
