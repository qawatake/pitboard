# FEAT9 の結果

vet / test / build は通った。1・3・4 は pty 越しに確かめた (スクラッチパッド、幅 80): 書いたあと案内に `s 送る`、欄の見出しから `s で送る` が消えた、`tab` の一覧で `e` → 文が入ったエディタ → `enter` で置き換わる、開いた `Item` の中身が 2 桁深くなる。2 は届くバイト列を単体テストで確かめた。実物の `herdr agent prompt` / `herdr pane send-*` は実行していない。

## 項目ごと

1. 送るキー: 案内に未送信があるときだけ `s 送る` (`m 書く` の手前、最後まで残す)。エディタの `ctrl+s` は何もしない。欄の見出しの `s で送る` を消した
2. 改行は shift+enter: 起動時 (と外のエディタから戻ったとき) に `CSI > 1 u` と `CSI > 4 ; 1 m` を有効にして `CSI ? u` で問い合わせ、終わるとき (外のエディタの前も) に `CSI < u` `CSI > 4 ; 0 m` で戻す。返事が来たら案内は `shift+enter 改行`、来なければ `ctrl+j 改行`。`CSI … u` と `CSI 27 ; m ; c ~` の形を、いま使っているキーと同じに読む (単体テストで全キーを 3 つの形で確かめた)
3. 開いた `Item` `Ask` `Fold` の題を太字に。`Item` の中身は題の文より 2 桁深く、中身のあと 1 行空ける (開いた `Ask` も選択肢のあと)
4. 思いつきを直す: 欄と一覧で `e`。`edit` を追記し、届く前なら直した文が `thought N` として、届いたあとなら `edit thought N: …` として次の送信で届く。行き先は外れる。空・同じ文は何もしない。`-h` の `changes` の説明に足した

## 調べた結果 (2 の拡張)

この環境では Ghostty・kitty・WezTerm・iTerm2・tmux を動かせないので、各端末の文書と実装について知っていることからの判断で、実機では確かめていない。

- kitty / Ghostty / foot: kitty keyboard protocol に対応し、`CSI ? u` に答える。disambiguate (フラグ 1) では esc が `CSI 27 u`、ctrl+文字が `CSI 106;5u`、alt+文字が `CSI 98;3u`、shift+enter が `CSI 13;2u` になる。enter・tab・backspace・矢印は今までどおり
- WezTerm: kitty の方式は設定 `enable_kitty_keyboard = true` のときだけ。既定では答えないので `ctrl+j 改行` のまま (shift+enter は既定でも `CSI 13;2u` を送る設定がある)
- iTerm2: 3.5 以降は kitty の方式に対応 (答える)。それより前は答えない
- tmux: kitty の方式は外の端末へ渡さず、答えもしない。`extended-keys on` (3.2 以降) なら modifyOtherKeys の要求を受けて shift+enter を `CSI 27;2;13~` (または `CSI 13;2u`) で渡す。問い合わせには答えないので案内は `ctrl+j 改行` だが、shift+enter でも改行できる
- xterm: modifyOtherKeys 1 で shift+enter が `CSI 27;2;13~`。ctrl+文字・alt+文字はレベル 1 では変わらない
- 副作用: 拡張を戻さずに終わると、シェルで ctrl+文字が `CSI …u` になる。q・シグナル・外のエディタの前で必ず戻すようにした (term.close)。対応していない端末は知らない列を無視する

## 推測で決めた点

- 2 つの方式を両方有効にした (kitty の方式に対応する端末ではそちらが優先され、tmux / xterm では modifyOtherKeys が効く)。案内の切り替えは指示どおり `CSI ? u` の返事だけで決める
- 端末の返事 (`CSI ? flags u`) はキーとして扱わない (知らせも消さない)
- 拡張の形で届いた、使っていない ctrl / alt の組み合わせ・テンキーなどは捨てる。alt+enter と ctrl+enter も改行として読む。ctrl+backspace は 1 語消す
- 貼り付けの中に拡張の形のキーが来ても、キーとして扱わない
- 中身の字下げ「題より 4 桁」は、題の印から 4 桁 (題の文から 2 桁) と読んだ。中身の箇条も思いつきの行も同じだけ深くなる
- 開いた `Fold` のあとは空けない (中身が項目なので)。開いた `Ask` は選択肢のあとに空ける
- 届いたあとに直した思いつきの状態は、直した記録の状態 (未送信 → 未読 → 受け取った) とし、行き先は外す。思いつき自体の番号は変えない
- 直した記録は、届いていない思いつきに対しては AI に届けない (届く `thought` の文が直したものになる)。取り消した思いつきの直しも届けない
- エディタの題は「思いつき N を直す」。`?` の一覧で `ctrl+s` の行を消し、`shift+enter` の行に置き換えた
- `s` の `?` の一覧の説明を、`wait` があるときの動きに合わせて書き直した
