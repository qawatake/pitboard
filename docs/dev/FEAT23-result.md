# FEAT23 の結果

vet / test / build は通る。git には触っていない。pty (スクラッチパッドの空のディレクトリ、幅 80 と 40、高さ 20) で、短い引用・3 行で `…` になる長い引用・画像の印・`j` で引用の行を飛ばして題に止まることを見た。

## 項目ごと

- `Item` の属性 `re="N"`: `Node.Re`。値は数字だけ (`^[0-9]{1,9}$`)、それ以外 (空を含む) は `check` のエラー。`Item` 以外では「属性が無い」エラー (`internal/report/parse.go`、`TestReAttribute`)
- 描き方: 題の行の上に、そのコメントの文を引用で出す。題の 1 文字目の列に薄い `> `、文も薄く。改行は空白にまとめ、折り返し、3 行を超えたら 3 行目を `…` で終える。`[Image #1]` は文のまま (`quote`、`internal/viewer/rows.go`、`TestQuoteAThought`)
- カーソル: 引用の行は止まる行ではない (行に鍵を付けない)。カーソルの `>` は左端の列のまま。カーソルの行を画面に入れるとき、上の引用の行も入れる (`row.lead`、`draw`)
- コメントが無い (取り消し・番号違い) ときは何も出さない
- 隠す鍵・緑の印: `HideKey` に `|re=N` を足した (`re` の無い行の鍵は変えていないので、今までに隠した行はそのまま)。未読の鍵 (`viewKey`) は `HideKey` から作るので一緒に変わる
- `-h`: `Item` の属性に `re` を足し、勧める構成の 3 を `<Item id="a-..." re="N" look="y">答えの結論を 1 文で` + 中身に、質問と答えの作法を「`re` と `look` を付け、質問は道具が引用で見せるので言い直さず、題は結論を 1 文で」に直した。例の報告の返事の行も `re` の形に
- 仕様書: SPEC-format.md (属性・描き方・`check`)、SPEC.md (勧める構成・隠す鍵) に反映
- コメントの側 (欄・一覧・行の下のコメント) は変えていない

## 推測で決めた点

- `re` は反応の鍵 (`Sig`) には入れなかった (依頼は隠す鍵と緑の印だけ)。`re` だけ書き換えても、付いていた `y` / `n` は消えない
- 引用の文の改行は空白にまとめた (3 行の枠を改行で使い切らないように)
- 引用の幅は右端の語を除かない、題の列から右端までの幅。引用の 2 行目以降にも `> ` を付けた
- 隠した行を `H` で出しているときも引用は出す (全体が薄い)
- コメントの番号が取り消されたあと `unretract` されれば、また出る
