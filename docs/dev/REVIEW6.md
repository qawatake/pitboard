## 1. 画面の言葉づかい

ユーザーの指摘: 状態の「受け取った」などが野暮ったい。言葉づかい全体を見直したい。

viewer が画面に出す日本語をすべて拾う (`view.go` ほか。案内の行、状態の語、知らせ、`?` の一覧、空のときの文、エラーの文)。それぞれについて見る:

- 初めて見た人が、説明なしで意味を取れるか
- 同じ物を別の語で呼んでいないか、別の物を同じ語で呼んでいないか (例: 「書く」「送る」「未送信」「未読」「受け取った」「済」「隠す」「片付ける」「取り消す」「思いつき」)
- 短く、端末の 1 行に収まるか。体言止めか動詞かが揃っているか
- 道具の内側の言葉 (AI 側の都合) になっていないか。使う人の言葉か
- 「AI」「あなた」の呼び方が揃っているか

出すもの: **用語の表** (いまの語 → 提案 → 理由。変えなくてよい語は「そのまま」と書く)。
思いつきの 4 つの状態 (未送信 → 未読 → 受け取った → 済) は、とくに丁寧に: 人から見て何が起きているかが分かる 4 語の組を、2 案出して、勧めるほうを言う。
「思いつき」という呼び名そのものも検討する (人が板に書く短い文。問い・頼みごと・感想・メモが混ざる)。

## 2. repo の構造

ユーザーの考え: `cmd/pitboard/main.go` にして、ほかは `internal/` に入れたい。公開するもの (他人が import できるもの) を少なくしたい。

いまは全部が repo 直下の `package main`。次を調べて、勧める構造を 1 つ出す:

- `cmd/pitboard` + `internal/...` にするときの分け方 (パッケージの境界をどこに引くか。例: 報告の解析 / 記録 / 画面 / 端末 / 送る / hook)。
  分けすぎない案を出すこと。1 人で保守する小さな道具なので、パッケージは理由のある境界だけにする
- `go install` のパスがどう変わるか
- `skills/pitboard/SKILL.md` の埋め込み (`go:embed` は親ディレクトリを参照できない) をどうするか
- テストの置き場所、`docs/dev/` (依頼と結果のファイル) を repo に残すか
- ファイル名と中身が合っているか (`page.go` `report.go` `view.go` `text.go` `store.go` など)。大きすぎるファイル、`featN_test.go` `fixN_test.go` のような経緯の名前のテストをどう直すか

出すもの: 勧めるディレクトリの絵、移す手順 (機械的にできる順)、やらないほうがよいこと。
