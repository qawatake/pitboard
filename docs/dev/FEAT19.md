# FEAT19: お知らせの開閉の印を左に、書く欄の余白、折りたたみにコメント、題の行の `>` を調べる

仕様は `docs/spec/SPEC.md` と `pitboard -h`。この依頼だけで完結する。

## 1. `Notice` の開閉の印を行頭に

ユーザーの言葉: 「お知らせ機能ですが、これも折りたたみのアイコンは左にあるほうが統一感があるような気がします」

- 中身 (かコメント) があって開ける `Notice`: 行頭の `!` の代わりに `▸` / `▾` (黄)。題の後ろの印はやめる
- 開けない `Notice`: 行頭は `!` (黄) のまま
- `Item` と同じ列に揃える

## 2. 書く欄の上下の余白

ユーザーの言葉: 「コメントの線の上部と下部のパディングはもうちょっと欲しい気がする。(下部の場合は、enterとかescとかのショートカットの下のパディングといったほうが適切か)」

- 上の線の上に空行を 1 行、案内の行 (`enter 置く …`) の下に空行を 1 行
- 固定の `Notice` の中に出すときも同じ。画面の高さが足りないときは、余白から先に削る (入力の行と案内を優先)

## 3. `Fold` にコメントできるようにする

ユーザーの言葉: 「あれ折りたたみとかにコメントできないんだね」

- `Fold` の行で `c` → その折りたたみへのコメント (エディタは `Fold` の行のすぐ下。開いていれば、開いた中身の下ではなく題のすぐ下)
- 記録の宛先: `id` があればそれ。無ければ、隠すときと同じ鍵の考え方で題から作る (`changes` には `thought N on fold "題": …` のように、AI がどの折りたたみか分かる形で出す)
- 行の右端の入力の状態、開いたときに下に出るコメント、欄・一覧、`e`、`x`、`u`、緑の印が消える扱いは、`Item` へのコメントと同じ
- `y` / `n` は今までどおり `Fold` には付けない
- 案内の行に、`Fold` の上でも `c 行に書く` を出す
- `-h` の「人が反応できるもの」を合わせる

## 4. 題の行に `>` が出る (調べる)

ユーザーの報告: 画面の冒頭がこう見えた。

    > AI セッションの横に置く
    pitboard を作る

題 (`Title`) はカーソルが止まる行ではないはずなのに、`>` が付いている。題の 2 行目の字下げも揃っていない。

- 再現を探す。見当: 固定の `Notice` があったあとそれを `x` で隠した直後、または `Notice` が 1/3 を超えて固定を外れたとき、カーソルの位置が題の行を指している。ほかに、報告が書き換わって `Notice` が消えたとき
- 原因を直し、テストを足す。再現できなければ、試した手順を結果に書く
- 題が折り返すとき、2 行目は 1 行目の文字の位置に揃える

- 仕様書に反映
- git は触らない
