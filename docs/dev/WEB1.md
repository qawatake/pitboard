# WEB1: ブラウザで操作できるモード — まず、画面に依らない層を切り出す

ユーザーの言葉: 「サーバーを起動すればブラウザで操作できるモードも作れますかね」「ブラウザで操作するモードも作ろうか」

これは 2 段階の 1 段目。**この依頼では、ブラウザの画面は作らない。** 端末の画面 (`internal/viewer`) の中にある「何を見せるか」「人の操作で何が起きるか」を、画面の種類に依らない層として切り出す。2 段目 (WEB2) で、その層の上にブラウザの画面を載せる。

## なぜ先に切り出すか

端末とブラウザで、同じ報告・同じ記録を、同じ言葉・同じ決まりで見せたい。いまは、行に付く印 (黄・緑)、右端の状態の語、どの行が開けるか・反応できるか、隠した行、未送信の数、`u` の取り消し、送る、などの決まりが `internal/viewer` の描画やキー処理と混ざっている。このままブラウザ側を書くと、同じ決まりを 2 度書くことになり、必ずずれる。

## 何を

1. 新しいパッケージ (名前は `internal/page` を勧めるが、ぶつかるなら任せる) を作る。端末にも HTTP にも依らない
   - **見せる物の組み立て**: 報告の木 (`report`) と記録の状態 (`board`) から、「画面に並ぶ物」の木を作る。1 つの物が持つもの: 種類 (お知らせ・節・項目・問い・リンク・折りたたみ・文・コード)、宛先 (反応とコメントの鍵)、題と中身 (インラインの整形は、太字・コード・リンクの区間として持つ。エスケープ列は持たない)、開けるか、人ができる操作 (y/n・選択肢・コメント・隠す・読んだ)、印 (反応待ち・未読・あなた待ち)、進み具合と右端の語 (語と、色の意味 = 待ち / 動いている / 静か)、人の入力の状態、付いているコメント、引用 (`re`)、時刻 (`at`)、隠されているか
   - **全体の情報**: 反応待ちの数、未読の数、未送信の数、AI が待っているか、報告の誤り、飛び先 (`g`) の一覧、コメントの一覧 (欄・一覧用)
   - **操作**: 反応する、答える、コメントを置く・直す・取り消す、隠す・戻す、読んだ、全部読んだ、取り消す (`u`)、送る (起こす処理を含む。結果の文も返す)。どれも「宛先 + 操作」を受けて記録に書き、人に見せる知らせの文を返す。画面の語 (`未送信` `送りました` など) はこの層が持つ
   - **守り**: 「報告が書き換わった行には、見直すまで反応を付けない」のように、どの画面でも要る守りは、この層で表せる形にする (例: 操作に「人が見ていた内容の鍵」を添えさせ、いまの内容と違えば断る)。カーソルの置かれ方や 0.4 秒のように端末の画面に固有の守りは `viewer` に残す
2. `internal/viewer` を、その層を使う形に直す。**端末の画面の挙動は変えない** (既存のテストがそのまま通ること。テストを直す必要が出たら、その理由を結果に書く)
3. 開閉の状態、カーソル、スクロール、エディタ、キーの割り当て、描画、色の実際の値は `viewer` に残す (ブラウザは別の持ち方をする)

## 進め方

- 小さな段階で。段階ごとに vet / test / build が通ること
- 切り出す境界に迷ったら、「ブラウザの画面を書く人が、`viewer` を読まずに同じ画面を作れるか」で決める
- 途中で仕様の食い違いやバグを見つけても直さない。結果に書く

## 終わったら

- vet / test / build。作った実行ファイルで、pty 越しに 1 度、開く・`c`・`y`・`x`・`u`・`s`・`g` が今までどおり動くこと。スクラッチパッドの空のディレクトリで。どの repo の `.pitboard/` も触らない。実物の `herdr agent prompt` / `herdr pane send-*` は実行しない
- git は触らない
- `docs/dev/WEB1-result.md` に書く: 新しい層の公開する型と関数の一覧 (1 つ 1 行)、`viewer` に残したものとその理由、推測で決めた点、WEB2 (ブラウザの画面) を書くときに足りなそうなもの。画面への返事は「書きました」の 1 行だけ
