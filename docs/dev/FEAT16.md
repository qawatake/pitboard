# FEAT16: 題を折り返す (状態を切らない)、お知らせの部品 `Notice`、新しい版の知らせをやめる

仕様は `docs/spec/SPEC.md` と `pitboard -h`。この依頼だけで完結する。

## 1. 題は切らずに折り返す。右端の状態は決して切れない

ユーザーの言葉: 「題の長さというよりも構造の問題ではないのか。状態とかが見切れてしまうのは。どんなに長くても状態が見きれないようにするか折り返せるようにするべきなのでは」

いまは `Item` `Ask` `Link` `Fold` と箇条の行の題が 1 行に収まらないと `…` で切れる。右端の語 (`status`、入力の状態) も、狭いと切れたり題を押しのけたりする。

- 題は切らない。入りきらなければ折り返す。2 行目以降は、題の 1 文字目の位置に揃える (記号の下には書かない)
- 右端の語は 1 行目の右端に、常に全部出す。題は、右端の語の幅 + 2 桁を除いた幅で折り返す (2 行目以降も同じ幅で折り返し、右端の列を空けておく。右の語が縦に 1 本の列として読めるように)
- 右端の語が長すぎる場合 (幅の半分を超える) だけ、右端の語を次の行に右寄せで出す
- カーソルの `>` と ● は 1 行目だけ
- 「題が切れているから enter で開ける」という扱いは要らなくなる。開けるのは中身 (か `note`) がある行だけ。`Ask` も同じ
- 済んだ行 (薄い) も同じように折り返す
- コメントの欄・一覧の行も同じ考えで: 文は折り返し、状態は切らない (欄は高さに限りがあるので、1 件が 3 行を超えたら 3 行目を `…` で終える。全文は一覧か `e` で読める)
- スクロールとカーソル移動は「行 (部品)」単位のまま。折り返した行の途中で画面が切れるときは、その部品が全部入るようにスクロールする (部品が画面より高いときは頭を出す)
- 幅 20〜200、全角・半角の混ざった題、右の語あり・なしで、どの行も幅を超えず、右の語が欠けないことをテストする

## 2. お知らせの部品 `Notice`

ユーザーの言葉: (新しい版の知らせについて)「これって開発中だけに必要な機能だからなくてもいい気がしたなぁ。それよりは、第一に確認してほしいお知らせ的な機能として汎用化してもいい気がする」

AI が「まずこれを見て」と伝える手段。報告のどこをスクロールしていても見える。

- 書式: `<Notice id="restart">pitboard を開き直してください。新しい版を入れました</Notice>`。中身は文 (1 段落。インラインの Markdown 可)。`id` 必須。最上位にだけ置ける (`Section` `Fold` の中はエラー)。3 つまで (4 つ目からエラー)
- 描き方: 画面のいちばん上 (題の行より上) に固定して出す。スクロールしても動かない。黄。折り返す (1 つにつき 3 行まで、超えたら `…`)。報告の誤りの行があれば、その下
- 人の操作: 画面を開いたとき、最初のカーソルは `Notice` があればそこに置く (ただし、置かれただけのカーソルでは反応を受け付けない今の守りはそのまま)。`k` でいちばん上の行からさらに上へ行くと `Notice` に入れる。`Notice` の上で `x` → 隠す (ほかの行の「隠す」と同じ記録・同じ `changes`・同じ `u`。AI が文を書き換えたらまた現れる)。`c` でコメント、`y` / `n` も付けられる (ほかの行と同じ)
- `space` の飛び先と右上の数には数えない (常に見えているので)
- `-h`: 部品の表、例、作法に 1 つ (「人がまず知るべきことだけに使う: 道具や環境の都合で人に何かしてもらう必要があるとき、作業が止まっているとき。ふつうの問いや答えには使わない。用が済んだら AI が消す」)
- SPEC-format.md・SPEC.md に反映

## 3. 「新しい版があります」の知らせをやめる

FEAT13 で入れた、実行ファイルの変化を見張って出す行 (`exe.go` とその呼び出し、テスト、仕様書の記述) を消す。開き直しが要るときは、AI が `Notice` で伝える。
