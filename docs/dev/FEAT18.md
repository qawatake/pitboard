# FEAT18: 行頭の `○` と `~` をやめ、進み具合は右端の語で示す

仕様は `docs/spec/SPEC.md` と `pitboard -h`。この依頼だけで完結する。

## なぜ

ユーザーの言葉: 「~ってどんな意味なんだっけ？右のテキストのほうが意味がわかりやすい気がして。これって本当に必要なのかな。◯みたいなやつもよく分からない」

`Item` の行頭の記号 (`○` まだ、`~` 作業中、`✓` 済み) は、説明なしでは意味が取れない。右端の語 (`status`) と同じことを 2 か所で言ってもいる。行頭は「その行で何ができるか」だけにして、進み具合は言葉で右端に出す。

## 何を

- `Item` の行頭:
  - 中身 (か `note`) があって開ける行: `▸` / `▾` (今までどおり)
  - 開けない行: `·` (薄く)。`○` と `~` はやめる
  - `state="done"`: `✓` で薄く (今までどおり。開けるときも `✓` のまま)
- 右端の語:
  - `state="doing"` で `status` が無いとき: 道具が `作業中` と出す (緑)。`status` があればそれを緑で出す (今までどおり)
  - `state="todo"` (既定) と `done`: `status` があれば出す、無ければ何も出さない (今までどおり)
  - 人の入力の状態 (`y 送信済` など) があるときの並べ方は今までどおり
- `Ask` の `?`、`Link` の `→`、`Fold` の `▸` / `▾` は変えない
- `-h`: 記号の説明と例を合わせる。作法の「`state="doing"` の行に『作業中』と書かない」は、「`state="doing"` なら道具が『作業中』と出すので、`status` は別のことを言うときだけ書く」に直す
- `?` の一覧や仕様書に記号の凡例があれば合わせる
