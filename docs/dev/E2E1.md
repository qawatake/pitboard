# E2E1: black-box regression suite for the spec

You work ALONE in the git worktree `~/dev/github.com/qawatake/pitboard/.worktrees/e2e` (branch `e2e-tests`). Another agent is changing the main checkout at the same time: never read or write outside your worktree, except reading this file.

User's words: 「これまでのspecのe2e的なものを用意したいかもデグレがないように。これはただテストを書くだけなのでもう一人それ専用の開発エージェントをworktreeで走らせてPRでも作らせたら良さそう」

## Goal

A test suite that pins the SPEC's observable behaviour through the real binary, so later changes cannot silently break it. Black box: build `./cmd/pitboard` once (TestMain), then drive it only through its CLI and through a pty for the viewer. No imports of `internal/...` from the suite.

## Source of truth

`docs/spec/SPEC.md`, `docs/spec/SPEC-format.md`, `pitboard -h`. Each test names the spec statement it pins (section heading or a short quote in a comment). If spec and behaviour disagree, do NOT change non-test code: record it in the result file and `t.Skip` with the reason.

## Shape

- Directory `e2e/` (package `e2e_test`), run by plain `go test ./...`. Must stay fast (< 60 s total) and deterministic: no sleeps-as-sync (poll with deadlines), no dependence on wall-clock day, isolated temp dirs via `t.TempDir()`, `HOME`/`PATH`/`PITBOARD_SEND` controlled so nothing touches the real machine: no herdr (`PATH` without it), no clipboard (`osascript` absent from `PATH`), no real `.pitboard/` anywhere.
- stdlib only; no new module dependencies. Pty: open one with stdlib/syscall for darwin and linux (build-tagged files), or skip viewer tests with a clear message on other OSes.
- A small terminal-screen model for assertions (cursor moves, erase line/screen, SGR colors enough to assert yellow/green/dim, wide characters = 2 columns). Helper API along the lines of: `v := startViewer(t, w, h)`, `v.Keys("j", "c")`, `v.Type("…")`, `v.WaitFor("text")`, `v.Line(n)`, `v.ColorAt(row, col)`, `v.Screen()`; on failure print the screen.
- Table-driven where it reads better. One file per area.

## Coverage (areas; aim for the statements that matter to a user, not line coverage)

1. CLI: `path`, `check` (every documented error class, line numbers, exit codes), `changes` (formats, dedup of repeated reactions, `open:` line, report-problem line), `settle` (states, multi form, errors), `open`, `wait` (delivers on send, timeout, second waiter, stale waiting file), session prefix rules, board discovery from subdirectories, `--skill`, `-h` mentions every command.
2. Report rendering: every part (Title, Notice incl. pinning/`at`/open, Section, Item states and right-end words, Ask/Option, Link path/url, Fold incl. nesting indent, Code, text: paragraphs, nested/numbered lists, small headings), wrapping (titles never cut, right-end words never cut), widths 40/80/120, CJK.
3. Reactions: `y`/`n`, option keys, `c`/`m` comments (editor placement, newline keys, paste), `e`, `x` hide/retract, `H`, `r`, `A`, `u` for each action before and after send, `s` (to a waiter; to `PITBOARD_SEND`; nothing available), guards (changed row, placed cursor), comment states 未送信→送信済→既読→対応中/保留→対応済 as seen on screen.
4. Navigation: `j`/`k` incl. reading tall contents, `space`, `g` (+letters, many targets), `tab` list, `?`.
5. Marks and counts: yellow/green rules, `look`, `ask`, `wait="you"`, top-right counts, AI 待機中.
6. Live reload: report rewritten while open (marks return, cursor notice), broken report (no crash, problem line), empty/missing report/session texts.
7. Robustness: tiny sizes (20x5), resize, huge report, corrupt `events.jsonl` line.

## Process

- Commit in small logical commits on `e2e-tests` (English messages). Do not touch non-test files except: `README.md` (one line on how to run), and `.github/workflows/test.yml` only if one already exists.
- When the suite passes locally 3 times in a row (`go test ./... -count=3`), push the branch and open a PR to `main` with `gh pr create` (English title/body: what is covered, what is skipped and why, how flaky-proofing is done). Do not merge.
- If `main` moved, rebase before the PR; tests that fail only because behaviour changed on `main` after your branch point: fix the test to the new spec if the spec changed, otherwise report.
- Report: `docs/dev/E2E1-result.md` IN THE MAIN CHECKOUT PATH `~/dev/github.com/qawatake/pitboard/docs/dev/E2E1-result.md` (this one file is the exception to "never write outside"): PR URL, counts per area, spec/behaviour mismatches found, skipped items. ≤40 lines. Reply on screen: one line.
