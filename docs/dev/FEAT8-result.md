# FEAT8 の結果

vet / test / build は通った。指示書の例 (と番号・小見出し・改行の指定) を pty 越しに幅 80 と 44 で見て、折り返しが文の位置 (番号つきは番号の後ろ) に揃うことを確かめた。実物の `herdr agent prompt` / `herdr pane send-*` は実行していない。

## 項目ごと

1. 文の書き方: 入れ子の箇条 (2 桁で 1 段、3 段まで、印 `·` `-` `·`)、番号つき、続きの行、`**語**:`、小見出し (`**…**` だけの行)、行末の空白 2 つ / `\` での改行、段落の間の空行を読み・描くようにした (部品は増やしていない)
2. 止まる行: 節の直下の 1 段目の `- ` だけ。入れ子・番号つき・`Item` の中身の箇条は読むだけ。入れ子のある箇条は入れ子ごと隠し、鍵は入れ子の文も含む (入れ子の無い箇条の鍵は今までと同じ)
3. `check`: 字下げが 2 の倍数でない箇条と 4 段以上の入れ子をエラーに (行番号つき)
4. `-h` に文の書き方の表と作法 (3 行を超える中身は構造で見せる) を、SPEC-format.md に「文の書き方」の節と `check` の項目を足した

## 推測で決めた点

- 番号つきの行は、節の直下でも止まらない (今まで段落だったので、隠せないまま)
- `**語**:` で始まる行は、段落の途中でも新しい段落を始める (ユーザーの困りごとが、見出し語が前の文に埋もれることだったので)。`：` (全角) も同じ
- 「段落の間は 1 行空ける」は、書いた空行を 1 行として残す形にした (空行の無い段落と箇条はつなげて出す)。`Section` / `Fold` の直下の段落は今までどおり前後を空ける
- 続きの行は「その箇条の印より深く字下げした、`- ` でも番号でもない行」。印と同じ深さの文は箇条を終えて段落になる。空行も箇条を終える
- 段を飛ばした字下げは 1 段深いだけとして扱い、エラーにしない
- 番号の印は薄くせず、ふつうの色。番号が印の欄 (2 桁) より広いときは、文と折り返し・入れ子をその分右へずらす
- 番号つきの下の入れ子も 2 桁で 1 段 (`1. ` の文の位置 3 桁に合わせた字下げはエラー)
- 行末の `\` は出さない。改行の指定は段落と箇条の続きの行に効く
- `wrap` は文の中の改行で行を切るようにした (これまで改行は文に入らなかった)
