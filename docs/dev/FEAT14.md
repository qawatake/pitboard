# FEAT14: 「板」をやめて pitboard と呼ぶ、報告の誤りを AI に必ず知らせる、返事は pitboard に書く作法

仕様は `docs/spec/SPEC.md` と `pitboard -h`。この依頼だけで完結する。

## 1. 「板」と呼ぶのをやめる

ユーザーの言葉: 「板と呼ぶのをやめよう。pitboardだろ？」

- viewer が画面に出す日本語の「板」を、すべて `pitboard` に置き換える (例: 「板が見つかりません」→「pitboard が見つかりません」)。置き換えて不自然になる文は、文ごと書き直す。全部拾うこと (案内、知らせ、空のときの文、エラー、`?` の一覧)
- 日本語の文書 (`README.md`、`docs/spec/*.md`、`skills/pitboard/SKILL.md` の日本語部分) も同じ。英語の `-h` の "the board" は、物を指す普通名詞としてそのままでよい
- `TestNoOldWords` に「板」を足す (画面の文字列に残らないこと)
- `docs/dev/` の過去の依頼書と結果は直さない

## 2. 報告に誤りがあるとき、AI が実行するどのコマンドでも知らせる

ユーザーの言葉: 「lint的なものをかけたほうがいいんじゃないか？あなたの方でも。報告に書き方の誤りがあります、とエラーが出ているので」

いまは AI が `check` を自分で呼ばないと誤りに気づけない。呼び忘れると、人の画面にだけエラーが出る。

- `changes` `settle` `wait` (届いて終わるとき、タイムアウトで終わるとき) と hook の出力の最後に、報告に誤りがあれば足す:
  `report.md has N problem(s). Run: pitboard -s <短い id> check`
  誤りが無ければ何も足さない。終了コードは変えない
- `wait` は、始めるときにも 1 度見て、誤りがあれば同じ行を標準エラーに出してから待つ (待つのはやめない)
- 報告が無い・読めないときは何も足さない (落ちない)
- `-h` の作法に足す: 「report.md を書き換えたら `check` を通す。ほかのコマンドも誤りがあれば知らせる」

## 3. `-h` の作法に足す: 返事は pitboard に書く

ユーザーの言葉: 「pitboardが充実してきたのでclaude codeで直接会話しなくて良くなってきたね。claude codeもセッション上で返答しなくてよくなったかも」

`-h` の作法 (AI 向け、英語) に次の意味の文を足す。文面は任せる:

- pitboard から届いた入力への返事は、報告に書く (問いへの答え、何をどう変えたか、次に何が起きるか)。チャットには 1〜2 行の短い知らせだけにし、同じ内容を繰り返さない
- 人がチャットに直接書いてきたときは、チャットで答える (その答えが残すべきものなら報告にも書く)
- 人の判断や確認が要ることは、必ず報告の上のほうに `ask` か `wait="you"` で置く。チャットだけに書かない
