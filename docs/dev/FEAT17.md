# FEAT17: コメントを書く欄を、画面のいちばん下ではなく、書いている行のすぐ下に出す

仕様は `docs/spec/SPEC.md` と `pitboard -h`。この依頼だけで完結する。

## なぜ

ユーザーの言葉 (画面の写真つき): 「コメント欄が画面下部すぎる。もうちょっと上に配置したいかも」

いまは `c` / `m` / `e` で開くエディタ (「〜にコメント」の見出し、入力の行、案内の行) が画面の最下部に出る。目が画面の下の端まで動き、端末の下に重なる物 (通知など) にも隠れる。コメントの対象の行とも離れている。

## 何を

- `c` (行にコメント): エディタを、その行 (開いていれば中身の下) の**すぐ下**に、報告の行の間へ差し込んで出す。見出し「〜にコメント」は、対象がすぐ上に見えているので出さない (対象の行が画面に入りきらないほど高いときだけ出す)。字下げは対象の行の題に揃える
- `m` (宛先なし): カーソルの行のすぐ下に出す。その行へのコメントではないことが分かるよう、見出しを `宛先なしのコメント` と出す
- `e` (コメントを直す): コメントの欄・一覧の中で、そのコメントの位置に出す (その場で直す)。報告の行の下に開かれたコメントを直すときも、その位置
- エディタと案内の行 (`enter 置く  esc やめる  …`) はひとかたまりで出す。エディタの上下に 1 行ずつ空ける。知らせ (FIX7 の 2) もこのかたまりの中
- 位置: エディタのかたまりが、画面の高さの上から 2/3 より下に来るときは、報告をスクロールして 2/3 より上に収める (対象の行は見えたまま)。入力が増えて行数が伸びても、下へはみ出さない
- 画面のいちばん下の行は、書いている間は空ける (案内はエディタのかたまりに移るので)。下のコメントの欄は、書いている間は出さなくてよい
- エディタを閉じたら、スクロール位置とカーソルは開く前に戻す
- 端末のカーソル (IME の位置) は、今までどおり入力位置に置く
- 書いている間に報告が書き換わったときの扱い (「この行は書き換わりました」) は今までどおり

## 終わったら

- vet / test / build。pty 越しに確かめる (幅 80、高さ 24 と 50): 画面の上・中・下の行で `c`、`m`、長い入力 (5 行)、`e`、対象が画面より高い行。スクラッチパッドの空のディレクトリで。どの repo の `.pitboard/` も触らない。実物の `herdr agent prompt` / `herdr pane send-*` は実行しない
- 仕様書に反映
- git は触らない
