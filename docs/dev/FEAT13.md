# FEAT13: 実行ファイルが新しくなったら、viewer が自分で知らせる

仕様は `docs/spec/SPEC.md` と `pitboard -h`。この依頼だけで完結する (前の依頼の記憶は要らない)。

## なぜ

viewer は横のペインで開いたままになる。実行ファイルを新しくしても、動いている viewer は古いままで、人はそれに気づけない。
ユーザーの言葉: 「コマンドが新しくなって再起動が必要なときはちゃんと教えてほしい」。AI が言い忘れても気づけるようにする。

## 何を

- viewer は起動時に、自分の実行ファイル (`os.Executable()`。シンボリックリンクは解決する) の更新時刻と大きさを覚える
- 報告の再読み込みと同じ周期で、そのパスを見直す。更新時刻か大きさが変わっていたら (消えて置き直された場合も含む)、画面のいちばん上に 1 行出し続ける:
  `新しい版があります。q で終えて、開き直してください。`
  色は黄。報告のエラーの行より上。ほかの知らせ (下の行) とは別で、消えない
- ファイルが一時的に無い (置き換えの途中) だけでは出さない。次に見えたときに比べる
- 見直しに失敗しても落ちない、何も出さない
- 自動で再起動はしない (書きかけのコメントを失わせないため)
- `?` の一覧や案内の行は変えない

## 終わったら

- vet / test / build。単体テストは「覚えた値と違えば知らせが出る」「一時的に無いだけでは出ない」
- pty 越しに確かめる: スクラッチパッドに実行ファイルをコピーして起動し、`rm` してから別の版を `cp` して、行が出ること。動かすのはスクラッチパッドの空のディレクトリで。どの repo の `.pitboard/` も触らない
- `docs/spec/SPEC.md` に 1〜2 行で反映
- git は触らない
- `docs/dev/FEAT13-result.md` に書く: 直した項目ごとに 1 行、推測で決めた点、未確認の点。画面への返事は「書きました」の 1 行だけ
