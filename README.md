# pitboard

AI のセッションの横のペインに置く報告の画面。チャットは流れるので、流れては困るもの (いまの状況、あなたが決めること、見てほしいもの) を AI がここに書く。

名前の見立て: レース中のドライバーには話しかけられないので、周回ごとにボードの前を通るときに読ませる。

- 報告は AI だけが書く。あなたは pitboard の上で反応する: `y` / `n`、問いへの答え、行についてのコメント (`c`)、宛先なしのコメント (`m`)、行を隠す (`x`)、直前の操作を取り消す (`u`)。コメントには画像も貼れる (`ctrl+v`、画像ファイルのパスの貼り付け)
- 反応は書いただけでは AI に届かない。まとめて `s` で送る。AI が待っていれば (右上に `AI 待機中`) すぐ届く
- 緑の `●` は AI が読んでほしい行。読んだら `r` で消す
- コメントには状態が付く (未送信 → 送信済 → 既読 → 対応中 / 保留 / 対応済)。書いたら忘れてよい
- ほかのキーは viewer で `?`

依存は Go の標準ライブラリだけ。

仕様の回帰テスト (ビルドした pitboard を CLI と pty で動かす) は `go test ./e2e` (`go test ./...` にも入る)。

## 入れる

```sh
go install github.com/qawatake/pitboard/cmd/pitboard@latest
```

AI に使わせるには skill を入れる。skill は「`pitboard -h` を読む」と要点を数行だけ書いた薄いもので、AI は入っている版の `-h` から使い方を読む。

```sh
gh skill install qawatake/pitboard pitboard
# または
pitboard --skill > ~/.claude/skills/pitboard/SKILL.md
```

## 開く

AI に「pitboard に報告して」と頼むと、AI が報告を書き始め、開き方を伝えてくる。AI を動かしているディレクトリで、横のペインに開いたままにする。

```sh
pitboard            # いちばん最近更新されたセッション
pitboard -s ID      # セッションを選ぶ (id は先頭数文字でよい)
```

ブラウザで見たいときは `pitboard -s ID serve`。裏でサーバーを動かし (そのセッションのものが動いていればそれを使い)、URL を 1 行出してブラウザで開き、すぐ戻る (`--no-open` で開かずに URL だけ)。ページを 30 分開いていなければサーバーは自分で止まる。すぐ止めるのは `pitboard -s ID serve --stop`、動いているものの一覧は `pitboard serve --status`、端末に付けたまま動かすのは `--foreground` (ctrl+c で止まる)。端末の画面と同じ部品・同じ言葉・同じ決まりで、端末とブラウザを同時に開いてもよい (片方でしたことはもう片方にすぐ出る)。キーは端末と同じで、マウスでも操作できる。127.0.0.1 だけで待ち受け、URL の鍵は起動のたびに変わる。ポートは既定で 7482 (電話のキーで「PITB」)、ふさがっていれば 7491 までの次の空き (セッションごとにサーバーがあるので)、それも無ければ空いているもの。`--port N` はその番号だけ。

## 届かないとき

`s` で送っても AI が待っていないと、そのままでは届かない (画面にそう出る。チャットで一言伝えれば読む)。

- **止まっている AI を起こす**: `PITBOARD_SEND` を設定すると、AI の端末に 1 行打ち込んで起こす (tmux の例は `pitboard -h` の "Send")。herdr の中で AI を動かしていれば設定は要らない
- **作業中の AI に届ける**: Claude Code の hook に入れると、AI がツールを使うたびに届く (`s` で起こしはしない)。設定例は `pitboard -h` の "Hooks"
